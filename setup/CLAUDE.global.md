# 개발 워크플로우

- 코딩 작업은 wf-design 스킬(요구사항 정의 + SW 설계) → 사용자 승인 → wf-implement 스킬(계획 + 구현 + 검증 + 통합) 순서를 따른다.
- 두 워크플로우의 문서를 만들거나 갱신할 때 wf-doc 스킬의 공통 포맷을 함께 적용한다.
- 동작·공개 인터페이스·데이터 모델·보안에 영향이 없는 국소적이고 되돌리기 쉬운 작은 작업은 wf-design을 생략할 수 있다(경량 경로). 판단이 애매하면 정식 경로를 따른다.
- 코드 작성은 wf-implement의 최소 구현 원칙(ponytail full 모드, §2.4)을 따른다. 설치된 ponytail 스킬과 내용이 다르면 wf-implement의 규정을 우선한다.
- 테스트는 wf-implement의 TDD 규정(실패하는 테스트 먼저, §3.3)을 따른다. 버그 수정은 경량 경로에서도 재현 테스트를 먼저 작성한다.
