# 저장소 품질 게이트

이 파일은 **저장소 전역 게이트**의 정본이다. [Stop 훅](../setup/hooks/wf-stop-gate.ps1)이 에이전트가 응답을 마칠 때마다 아래 펜스의 게이트와 열린 작업 기록의 [회귀 의무 목록](../skills/wf-doc/references/templates.md#작업-기록-work-log) `유지` 행을 합쳐 실행하고, 하나라도 실패하면 종료를 차단한다. 정의 위치와 실행 정책의 근거는 [ADR-005](./work/20260920-enforced-gates/ADR-005-게이트-정의-위치와-실행-정책.md)다.

## 불변 설정 원칙

**게이트를 통과시키기 위해 게이트를 고치지 않는다.** 다음은 [wf-implement §2.3](../skills/wf-implement/SKILL.md#23-자율-진행과-승인)의 명시 승인 대상이며, 에이전트가 자율로 수행할 수 없다.

- 훅 등록(`~/.claude/settings.json`의 `Stop`·`SessionStart`·`PostToolUse` 항목)의 제거·비활성화
- 훅 스크립트(`setup/hooks/wf-*.ps1`)의 게이트 실행·판정·차단 경로 변경
- 이 파일의 `gates` 펜스에서 게이트 줄을 삭제하거나 약화
- 회귀 의무 목록 행의 삭제, 또는 `유지`에서 `폐기`·`보류`로의 하향

게이트가 막았을 때 할 일은 원인 코드를 고치는 것이다. 통과시키려 게이트·테스트를 완화·비활성화·삭제하는 변경은 [§3.4의 "인수 조건을 완화하지 않는다"](../skills/wf-implement/SKILL.md#34-검증) 위반으로 취급한다. `CLAUDE_WF_GATE_DISABLE=1`은 게이트 자체를 고칠 때 쓰는 임시 탈출구이며, 실패를 우회하려는 사용은 같은 위반이다.

## 게이트

```gates
secrets = gitleaks detect --no-git --source . --no-banner --redact --exit-code 2 --config .gitleaks.toml
```

형식은 `이름 = 명령`이고 첫 `=`에서만 나눈다(Windows 경로와 `=`를 포함한 플래그가 살아남도록). `#`로 시작하는 줄은 주석이며, 펜스 밖의 어떤 줄도 게이트가 아니다.

## 실행 규칙

- **실패**는 명령이 끝까지 실행되고 종료 코드가 0이 아닌 경우뿐이다. 이때만 차단한다.
- **인프라 사건**은 통과시키고 센다 — 명령이 해석되지 않는 경우(도구 미설치), 타임아웃(게이트당 기본 300초, `CLAUDE_WF_GATE_TIMEOUT_SEC`), 훅 자체의 예외. 도구를 아직 깔지 않은 환경이 매 턴 차단당하면 게이트가 먼저 버려지기 때문이다. 누적 횟수는 상태 파일(`%TEMP%\claude-wf\<세션>-gate.json`)의 `infraCount`에 남고 [§3.5 자체 리뷰](../skills/wf-implement/SKILL.md#35-자체-리뷰)에서 확인한다.
- **인용**: 마지막으로 전 게이트가 통과한 시점의 트리 키(HEAD + 워킹트리 상태·diff의 해시)와 현재 트리 키가 같으면 실행하지 않는다. 인프라 사건이 하나라도 있었던 실행은 통과로 기록하지 않는다 — 돌지 못한 게이트를 "통과"로 굳히면 그 검사는 영구히 생략된다.
- 같은 명령이 전역 펜스와 의무 목록 양쪽에서 와도 한 번만 실행한다.

## 게이트 추가

게이트에 넣을 수 있는 명령은 **결정적**이어야 한다 — 같은 트리에서 같은 결과를 내고, ML 판정을 포함하지 않으며, 네트워크나 시각에 의존하지 않는다. 작업별 회귀 테스트는 이 파일이 아니라 작업 기록의 의무 목록에 넣는다([진입 조건](../skills/wf-implement/references/verification-depth.md#3-회귀-의무-목록의-진입-조건과-상태): 같은 SHA에서 2회 통과). 이 파일은 작업과 무관하게 저장소 전체에 항상 적용되는 검사만 담는다.
