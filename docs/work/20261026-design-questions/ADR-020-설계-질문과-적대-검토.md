## 배경

wf-design은 질문 여부를 §2 원칙 한 문장으로만 정하고, §4.5 검토는 작성자 자신이 한다. 질문 표의 열과 답의 위치는 작업마다 다르다(req-design 11건에 열 구성 5종, 답 위치 3곳). 모델은 지시 없이는 거의 묻지 않고(Ambig-SWE 2502.13069 `[노트]`), 같은 맥락의 자기 검토는 독립 신호가 아니며, 근거를 강제하지 않은 적대 검토는 동조 날조로 단일 검토자보다 나빠진다(2608.18167 `[재확인 10-26]`: F1 0.533 근거 강제 검토자+비평자 > 0.495 단일 > 0.457 근거 없는 적대).

## 영향을 받는 요구사항과 제약

- 새 개념(식별자 계열·문서 유형)은 대안이 없을 때만(05 §0). 식별자 문법은 wf-doc 소유.
- 하네스 중립 — 본문은 의무만(05 §0, ADR-014 결정 5와 같은 층 구분).
- wf-design 본문 순증 0, wf-implement 여유 0.
- 적대 검토 비용 약 4.5배 토큰(2608.18167).

## 고려한 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 질문 `Q-NN` + 6열 표. 검토는 근거 강제·`제안` 강등·할당량 금지·최대 2라운드, 실행 주체는 본문 의무 + references 하네스별(Claude Code 서브에이전트 기본, 불가 시 별도 세션) | 새 계열 없음, 하네스 중립, 근거로 날조를 걸러냄 | 검토 비용, 검토자 독립성은 프롬프트 규율에 의존 |
| B | 9월 편집안 — `consultation` 문서 유형과 전역 `CRP` 계열 + 등록부 | 자문 요청을 작업 밖에서 조망 | 새 유형·전역 번호. 다인 토론 Q-01(작업-스코프 ID)·S35와 충돌해 다시 바꿔야 함 |
| C | 적대 검토에 지적 하한("최소 N개", BMAD `bmad-review` 방식) | 검토가 빈손으로 끝나지 않음 | 할당량이 날조를 유도 — 근거 없는 적대 검토의 F1 하락과 같은 방향 |
| D | 적대 검토 없이 §4.5 자체 검토 강화만 | 비용 없음 | 같은 맥락의 검토는 독립 신호가 아님 |
| E | 실행 주체를 별도 세션으로 고정 | 맥락 분리가 확실 | 사용자 조작 증가 → 승인 피로(S26), 서브에이전트가 있는 하네스에서 과잉 |

## 결정

A를 채택한다.

1. **질문 식별자와 형식.** 질문·자문 요청은 기존 항목 ID `Q-NN`(문서 안 유일)을 쓴다. 요구사항·설계의 질문 표는 6열 `ID`·`질문`·`선택지`·`권장안`·`근거`·`답`으로 고정하고, 권장안은 미응답 시 기본 가정이며, 사용자 답은 `답` 칸 한 곳에만 적는다(인용과 일자, 또는 `대기`·`미응답 — 기본 가정 적용`·`해소 — 근거`). 구현 중 질문은 작업 기록 인계 `차단 요인`의 Q 행으로 올린다.
2. **적대 검토 규칙.** 정식 경로와 DCR 변경(명확화 제외)은 승인 요청 전 동결된 문서를 검토받는다. 지적은 근거 인용 필수, 없으면 `제안`으로 강등해 승인 요청에는 수만 싣는다. 범위는 정확성·명시 요구사항·계약 위반. 지적 수 하한·목표는 두지 않고 0건도 유효하다. 작성자는 `수용`·`반박(근거)`·`우려 유지`로 답하고, 2라운드에서 검토자가 `해소`·`남음`을 판정한다(최대 2라운드). `남음`은 승인 요청에 심각도 순으로 싣되 승인 요청을 막지 않는다. 실행할 수 없으면 `미수행 — 이유`로 공개한다. 지적 번호는 표 안 순번이며 추적 식별자가 아니다.
3. **실행 주체.** 스킬 본문은 "작성 맥락을 공유하지 않는 검토자"만 적는다. references에 하네스별 방법 — Claude Code는 새 맥락 서브에이전트(문서 경로·검토 규칙만 전달, 작성 대화 전달 금지, 읽기 전용), 서브에이전트가 없는 하네스는 사용자가 연 별도 세션. 문서는 작성자만 고친다.

## 이유

- `Q-`는 이미 모든 req-design에 있고 wf-doc 공통 항목 ID라, 열 고정만으로 답의 위치를 하나로 만든다. 새 전역 계열은 나중에 작업-스코프 ID로 다시 바꿀 비용을 만든다.
- 근거 강제는 적대 검토가 이득이 되는 조건 그 자체다(2608.18167). 할당량은 그 반대 방향이다.
- 2라운드 상한은 AI-DLC architecture-reviewer의 최대 2회 `[노트]`와 같고, 비용 상한 역할을 한다.
- 실행 주체를 층으로 나누면 하네스가 바뀌어도 본문을 고치지 않는다(ADR-014 결정 5와 같은 이유).

## 결과와 감수할 단점

- 정식 경로 작업마다 검토 비용이 든다(약 4.5배 토큰 추정).
- 검토자 독립성은 프롬프트 규율로만 보장한다 — 작성자가 대화 요약을 넘기면 깨진다.
- 질문 표·검토 표는 기계 검사하지 않는다(정착 후 판단). 완료 작업의 옛 형식 표는 그대로 남는다.
- 자문 요청을 작업 밖에서 한곳에 조망하는 등록부가 없다 — 열린 작업의 `차단 요인`으로만 보인다.

## 후속 작업

- 다음 정식 경로 작업 1~2건에서 질문 수, 지적 수·수용률·근거 없는 지적 비율, 토큰 비용 기록 → 린트 도입·라운드 상한 재검토.
- 효과(승인 후 DCR·수정 요청·결함 감소)는 코드 저장소 실측(사이클 C).
