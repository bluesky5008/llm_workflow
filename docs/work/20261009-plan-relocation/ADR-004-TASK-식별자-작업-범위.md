# ADR-004: TASK 식별자의 작업 범위 발행

> 문서 유형: `adr`
> 작업 ID: `20261009-plan-relocation`
> 상태: `approved`
> 기준선: `v1` ([REQ-DESIGN-plan-relocation](./req-design.md) 기준선에 포함, 승인일 2026-10-09)
> 작성일: 2026-10-09

> 관련 문서: [REQ-DESIGN-plan-relocation: 요구사항·설계](./req-design.md), [WORK-20261009-plan-relocation: 작업 기록](./work-log.md), [wf-doc 추적 식별자](../../../skills/wf-doc/SKILL.md#추적-식별자)

## 요약

- 결정: TASK 식별자(`TASK-NN`)는 저장소 전역 일련번호가 아니라 **작업(`docs/work/<작업-ID>/`) 범위**에서 `TASK-01`부터 발행한다. 다른 작업의 TASK는 작업 경로를 포함한 링크로 가리킨다. 과거 전역 번호(TASK-01~29)는 기록으로 유지하고 재번호하지 않는다.
- 핵심 이유: 구현 계획이 작업 폴더의 `plan.md`로 내려가면(FR-04) 전역 번호의 유일성 근거인 "한 파일 안의 일련번호"가 사라진다. 작업 범위 번호는 링크의 경로가 유일성을 보장하고, 마지막 번호를 찾기 위해 완료 작업을 뒤질 필요가 없다.
- 주요 단점: `TASK-01`만으로는 어느 작업인지 알 수 없다. 작업 밖에서 언급할 때는 반드시 경로 포함 링크나 작업 ID를 함께 적어야 한다.

## 배경

현행 [wf-doc 추적 식별자](../../../skills/wf-doc/SKILL.md#추적-식별자)는 `TASK-01`을 항목 ID로 정의하고, plan 문서 ID를 `PLAN-<프로젝트-슬러그>`(저장소 현행 문서)로 둔다. 실제 운용에서 `docs/plan.md` 하나에 7개 사이클의 TASK가 전역 일련번호(01~29)로 누적됐다. 새 사이클은 마지막 번호를 확인한 뒤 이어서 발행했고, 완료 사이클은 축약 목록으로 남겨 번호의 연속성을 유지했다.

[REQ-DESIGN-plan-relocation](./req-design.md) FR-04가 구현 계획을 `docs/work/<작업-ID>/plan.md`로 내린다. 그러면 TASK 번호의 발행 단위를 다시 정해야 한다.

## 영향을 받는 요구사항과 제약

- [FR-04·FR-05](./req-design.md#기능-요구사항) — 작업별 계획 파일과 TASK 번호 범위
- [FR-09](./req-design.md#기능-요구사항) — 이 작업의 계획이 `TASK-01`부터 시작(자기 적용)
- [NFR-02](./req-design.md#비기능-요구사항) — 완료 문서의 과거 번호를 바꾸지 않는다
- wf-doc §2.6의 "문서 안에서 식별자는 유일해야 하며 의미가 바뀌어도 재사용하지 않는다" — 유일성의 단위가 문서(plan.md)이므로 작업 범위 번호와 충돌하지 않는다

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| A. 전역 일련번호 유지(현행, 다음은 TASK-30) | 번호만으로 작업을 유일하게 식별, 과거와 연속 | 마지막 번호를 알려면 완료 작업 폴더를 뒤지거나 별도 카운터가 필요. 다인 사용에서 충돌. plan.md가 분산되면 "전역"의 근거 문서가 없다 | 없음 |
| B. 작업 범위 번호(`TASK-01`부터) (채택) | 작업 폴더만 보면 발행 가능. 링크 경로가 유일성 보장. `WORK-<작업-ID>`·`PLAN-<작업-ID>`와 같은 범위 규칙 | 번호만으로는 작업 식별 불가 → 경로 포함 링크 의무 | wf-doc §2.6 한 문장 추가, 추적표 예시 경로 수정 |
| C. 복합 식별자(`TASK-<작업-ID>-NN`) | 번호만으로 전역 유일 | 길어서 표·트리 가독성 저하. wf-doc 항목 ID 문법(`접두사-NN`) 변경이 필요해 영향 범위가 커진다 | 식별자 문법·템플릿·렌더링 규칙 전반 |

## 결정

대안 B를 채택한다. `TASK-NN`은 작업 범위 항목 ID다. 각 작업의 `plan.md`는 `TASK-01`부터 발행한다. 같은 작업 안에서는 `TASK-NN`만으로 가리키고, 다른 작업의 TASK는 `[TASK-NN](../<작업-ID>/plan.md#작업-목록)` 형태의 경로 포함 링크로 가리킨다. `VER-NN`도 같은 규칙을 따른다(검증 항목은 원래 작업 기록 안에서 발행되므로 실질 변경 없음).

과거 `docs/plan.md`의 TASK-01~29는 완료 작업 기록(work-log)에 그대로 남는다. 재번호하지 않는다.

## 이유

식별자의 유일성 단위는 그 식별자가 발행되는 문서와 같아야 한다. 계획 문서가 작업 폴더로 내려가면 발행 단위도 작업이 되는 것이 자연스럽고, 이는 이미 `WORK-<작업-ID>`·`VERIFY-<작업-ID>`가 따르는 규칙이다. 전역 번호는 단일 `docs/plan.md`가 있을 때만 비용 없이 유지됐다.

## 결과와 감수할 단점

- 작업 밖(README, 조사 기록, 다른 작업의 문서)에서 TASK를 언급할 때 작업 ID 없이 `TASK-03`이라 쓰면 모호하다 → wf-doc §2.6에 경로 포함 링크 규칙을 명시(DES-06).
- 과거 문서의 `TASK-25` 같은 전역 번호와 새 작업의 `TASK-01`이 공존한다 → 전자는 완료 기록, 후자는 진행 중 작업으로 폴더가 다르므로 충돌하지 않는다.
