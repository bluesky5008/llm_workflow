## 문제와 목적

wf-implement §7의 축약 규칙은 "상세 이력의 정본은 작업 기록이므로 삭제가 아니라 이관"이라고 규정하지만, 계획 트리 표현에는 이관 경로가 없다. 새 사이클의 계획 수립이 plan.md의 mermaid를 새 사이클 것으로 교체하고 ASCII 상세를 롤업 한 줄로 접으면, 이전 사이클의 상세 트리는 git 이력에만 남는다.

실측(2026-08-14 세션): `20260814-wf-tree-triggers` 사이클의 상세 트리(mermaid 포함)는 커밋 `13e4a72`의 plan.md에만 존재하며, [해당 work-log](../20260814-wf-tree-triggers/work-log.md)에는 트리가 없다. 사용자 요청(2026-08-14): 완료된 작업을 work-log로 이동시킬 때 mermaid 트리도 함께 백업한다.

## 설계

| ID | 항목 | 내용 |
|---|---|---|
| DES-01 | 규칙 배치 | wf-implement §7 축약 문단에 스냅숏 이관 전제(FR-01·02), §5 완료 조건에 확인 항목 추가. wf-tree §5 단일 소스 원칙에 스냅숏 예외·표시 규칙(FR-03). wf-doc work-log 템플릿 노트에 배치 규칙(FR-04). 각 스킬의 소유권 경계(축약 시점=wf-implement, 트리 표현=wf-tree, 문서 배치=wf-doc) 유지 |
| DES-02 | 스냅숏 형식 | work-log의 `## 계획 트리` 절, `## 수행 기록` 바로 앞 배치(계획 조망 후 시간순 기록 — plan의 "작업 목록 바로 앞"과 동일 원리). 절 첫 줄에 `<!-- snapshot: YYYY-MM-DD 완료 시점 -->` 표시, 내용은 해당 사이클 서브트리의 ASCII 트리와 mermaid 블록 |
| DES-03 | 시점 결정 | 주 경로 = 완료 보고와 같은 변경(FR-01): 파괴 가능 시점(다음 계획 수립) 전에 백업이 항상 존재하고, 완료 전 work-log를 마무리하는 같은 세션에서 수행. 보정 경로 = 축약 시 부재 발견(FR-02): 규칙 신설 전 완료된 사이클 대비. 대안 "축약 시점 단일 규칙"은 완료된 work-log를 나중 세션이 수정하게 되고 백업→교체 순서 실수 위험이 있어 기각. ADR 분리 불요 — 되돌리기 쉬운 문서 표현 결정 |
| DES-04 | 소급 범위 | 2건 — `wf-tree-triggers`는 git 이력(`13e4a72`)에서 복원, `id-item-tables`는 현재 plan.md에서 복사(이번 세션 완료로 아직 유실 전). 완료 상태 보존 원칙에 따라 스냅숏 추가는 기록 보완이며 완료 판정을 바꾸지 않는다 |
| DES-05 | 백업 대상 확정 | 백업 대상은 해당 사이클 서브트리의 ASCII 상세와 mermaid 둘 다 — 승인 관문에서 사용자 확정(Q-02). 초안의 mermaid 한정안은 기각: 매체별 가독 환경이 달라(터미널·diff=ASCII, 문서 뷰=mermaid) 완전한 시점 복원에는 두 표현이 함께 필요 |
