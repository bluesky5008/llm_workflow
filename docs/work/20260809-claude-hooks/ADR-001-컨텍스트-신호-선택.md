# ADR-001: 컨텍스트 사용량 신호 선택

> 문서 유형: `adr`
> 작업 ID: `20260809-claude-hooks`

> 기준선: `v1` (설계 기준선에 포함, 승인일 2026-08-09)

> 관련 문서: [DESIGN-llm-workflow: 설계](../../design.md), [REQ-llm-workflow: 요구사항](../../requirements.md)

## 요약

- 결정: 세션 인계 트리거의 컨텍스트 사용량 신호로 **transcript 파일 크기의 성장량(세션 시작·컴팩션 시점 기준점 보정)**을 사용한다.
- 핵심 이유: 훅이 접근 가능한 유일한 문서화된 신호이며, 기준점 보정으로 컴팩션 후 오차를 제거할 수 있다.
- 주요 단점: 토큰과의 비례가 근사적이라 발화 시점이 부정확할 수 있다(설정 가능 임계값으로 완화).

## 배경

FR-02(임계값 경고)는 "컨텍스트 사용량"을 알아야 한다. 2026-08-09 조사(Claude Code 공식 훅 문서) 결과: 훅 입력 JSON에는 토큰 사용량 필드가 없고, statusline 입력에는 `context_window.used_percentage` 등이 있으나 훅이 그 데이터에 접근하는 문서화된 경로가 없다. 모델 자신의 컨텍스트 자기 인식은 신뢰할 수 없다는 것이 이 작업 전체의 전제다.

## 영향을 받는 요구사항과 제약

- [FR-02, FR-03(a)](../../requirements.md#기능-요구사항) — 임계값 판정의 입력
- [NFR-03](../../requirements.md#비기능-요구사항) — 매 툴 사용마다 실행되므로 판정 비용이 낮아야 함
- 문서화된 능력만 사용한다는 설계 제약

## 고려한 대안

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| A. transcript 크기 성장 프록시 (채택) | 훅 입력의 문서화된 필드(`transcript_path`)만 사용, stat 1회로 저비용, 기준점 보정으로 컴팩션 오차 제거 | 토큰과 근사 비례(발화 시점 오차) | — |
| B. statusline 브리지(statusline 스크립트가 토큰 데이터를 파일로 지속, 훅이 읽음) | 정확한 토큰·퍼센트 | 비문서화 연계 패턴, 사용자의 기존 statusline 설정을 점유·병합해야 함, 이동 부품 증가 | A에서 B로 상태 파일 스키마 확장으로 전환 가능 |
| C. 모델 자기 판단(스킬에 "길어지면 인계하라" 지시) | 구현 0 | 모델은 자기 컨텍스트 사용량을 신뢰성 있게 모름 — 이 작업의 전제와 모순 | — |
| D. 마일스톤 개수 카운트(작업 기록의 TASK 완료 수) | 완전 이식 가능 | 컨텍스트 소모와 상관이 약함(탐색 많은 TASK 하나가 짧은 TASK 열 개보다 클 수 있음) | — |

## 결정

대안 A를 채택한다. 기준점은 `SessionStart`(startup/resume/clear)에서 기록하고 `SessionStart`(compact)에서 재설정한다. 임계값·재경고 간격은 환경 변수로 재정의 가능한 스크립트 상수로 둔다.

## 이유

문서화된 능력만으로 성립하는 유일한 저비용 신호다. 프록시 오차의 실제 비용은 낮다 — 발화가 일러도 지시는 "다음 계획 항목 경계에서 인계"이므로 낭비가 아니라 약간 이른 절단일 뿐이고, A층 불변식 덕에 어느 시점의 절단도 안전하다.

## 결과와 감수할 단점

- 발화 시점이 실제 컨텍스트 사용률과 ±수십 % 어긋날 수 있다. 기본값을 보수적으로 두고 실측 보정한다.
- 정확도가 실제로 문제가 되면 대안 B로 전환한다(상태 파일 스키마는 그대로 확장 가능).
