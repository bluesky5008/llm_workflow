## 문제와 목적

ID 발행 항목의 표기 형식이 유형마다 다르다 — VER는 표, TASK는 하위 절, FR·NFR·AC·DES는 불릿 목록, RISK·Q는 미규정. 불릿 목록은 항목 수가 늘면 ID·이름·내용의 경계가 흐려져 조망성이 떨어지고, 문서마다 표기가 흔들린다(`- FR-01:`, `- FR-01 (이름):` 혼재). 사용자 요청(2026-08-14): ID가 발행되는 성격의 항목은 표 형식으로 표시한다.

## 범위

### 포함

### 제외

- VER(이미 표)·TASK(필드 8개 하위 절이 적합)·ADR·DCR(문서 단위, 등록부가 이미 표)의 형식 변경

- wf-design 본문 — 어떤 항목에 ID를 발행할지의 소유권은 불변

## 기능 요구사항

| ID | 항목 | 내용 |
|---|---|---|
| FR-01 | 표 골격 | requirements 템플릿의 FR·NFR·AC 절과 design 템플릿의 DES 절은 `\| ID \| 항목 \| 내용 \|` 3열 표 골격으로 규정해야 한다 |
| FR-02 | 탈출 규칙 | 표 셀에 담기지 않는 중첩 구조(하위 목록·코드 블록·여러 문단)가 필요한 항목의 처리 규칙을 템플릿 노트로 명시해야 한다 — [FR-02 상세](#fr-02-상세) |
| FR-03 | RISK·Q 표 | 위험 절과 가정·미해결 질문 절에 ID 발행 시 사용할 표 골격을 규정해야 한다 (`\| ID \| 위험 \| 영향 \| 완화 \|`, `\| ID \| 질문 \| 해소 조건 \|`). ID를 발행하지 않는 간단한 서술은 계속 허용된다 |

#### FR-02 상세

탈출 규칙: 해당 항목은 표에 ID·항목명·판단 가능한 한 줄 요약을 유지하고, 상세를 표 바로 아래 `#### <ID> 상세` 하위 절에 둔 뒤 요약에서 앵커 링크로 연결한다. 표에서 항목을 빼는 방식(목록 회귀)은 허용하지 않는다 — 표의 전수 조망성이 깨지기 때문이다.

## 설계

| ID | 항목 | 내용 |
|---|---|---|
| DES-01 | 표 골격 명세 | 각 절의 템플릿 코드 블록 안에 헤더 행 + `FR-01`(등) 예시 행 1개를 둔다 — [DES-01 상세](#des-01-상세) |
| DES-02 | 노트 배치 | 탈출 규칙(FR-02)·적용 조건(FR-03)은 템플릿 코드 블록 뒤 기존 노트 불릿 목록에 추가한다. 표기 규칙의 정본은 템플릿이며 wf-doc SKILL.md 본문에 복제하지 않는다 |
| DES-03 | 대안 비교 | 순수 표(탈출 없음)는 중첩 구조 항목에서 가독성 붕괴로 기각, 2열 표(`ID\|내용`)는 항목명 열이 없어 조망성 이득이 작아 기각, **표+탈출 규칙 채택**. ADR 분리 불요 — 쉽게 되돌릴 수 있는 표현 형식 결정 |
| DES-04 | 실증 근거 | 중첩 구조의 실재는 저장소에서 확인됨 — [dev-briefing FR-01](../20260809-dev-briefing/req-design.md#기능-요구사항)의 (a)~(j) 열거. 순수 표 강제가 성립하지 않는 증거 |
| DES-05 | 호환성(비소급) | 기존 승인 문서는 소급 변환하지 않는다. 기존 문서의 항목 절은 다음 의미 갱신 시 또는 의미 불변 서식 정규화(wf-doc 단독 허용 경로)로 전환할 수 있다. 설치본은 정션 링크라 별도 배포 없음 |

#### DES-01 상세

requirements 템플릿(FR·NFR·AC 절 공통 형태, AC는 예시 ID만 `AC-01`):

```markdown
## 기능 요구사항

| ID | 항목 | 내용 |
|---|---|---|
| FR-01 | | |
```

design 템플릿(컴포넌트와 책임):

```markdown
## 컴포넌트와 책임

| ID | 항목 | 내용 |
|---|---|---|
| DES-01 | | |
```

위험·질문(두 템플릿 공통, ID 발행 시):

```markdown
| ID | 위험 | 영향 | 완화 |
|---|---|---|---|

| ID | 질문 | 해소 조건 |
|---|---|---|
```
