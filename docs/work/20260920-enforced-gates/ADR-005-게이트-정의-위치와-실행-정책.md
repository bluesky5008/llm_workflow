## 요약

- 결정: Stop 게이트의 원천은 **저장소 전역 `docs/quality-gates.md`의 `gates` 펜스 + 열린 작업 기록의 회귀 의무 목록 `유지` 행**이며, 별도의 작업 단위 게이트 펜스를 두지 않는다. 실행 정책은 **완료된 실행의 exit≠0만 실패, 인프라 사건은 통과(카운트), 트리 키가 마지막 통과와 같으면 인용**이다.
- 핵심 이유: 사이클 1의 의무 목록은 이미 "결정성 진입 조건을 통과한 명령의 집합"이라 게이트 후보의 정의와 일치한다. 같은 정보를 두 곳에 쓰면 드리프트가 생기고, 에이전트에게 "게이트에 넣을지"라는 두 번째 재량이 생긴다.
- 주요 단점: 의무 목록 표 파싱이 훅에 들어온다(형식 결합). 상태 어휘가 한국어라 ASCII 소스에서 문자 코드 비교가 필요하다.

## 배경

AI-DLC 2026의 `quality-gate.sh`는 저장소 전역 게이트와 작업(work item) frontmatter의 게이트를 가산 병합해 Stop 훅에서 실행하고, `stop_hook_active`로 재진입을 막으며, 실패 시 `decision: block`을 낸다. 묶음 B는 이를 이 저장소에 옮기며 작업 단위 게이트를 work-log의 ` ```gates ` 펜스에 두는 초안을 만들었다.

그 사이 사이클 1이 work-log에 `## 회귀 의무 목록`(발행 TASK·테스트·명령·보호 스코프·마지막 성공·상태)을 신설했다. 이 표는 (1) 명령이 실제 실행 형태로 고정되어 있고, (2) 같은 SHA 2회 통과라는 결정성 필터를 거쳤으며, (3) `유지/대체/폐기/보류` 상태로 게이트 적격성을 이미 표현한다. 묶음 B가 펜스에 담으려던 정보와 정확히 같다.

Stop 이벤트는 세션 종료가 아니라 **에이전트가 응답을 마칠 때마다** 발생한다. 게이트가 pytest라면 코드가 바뀌지 않은 턴에서도 매번 돈다. 이것이 실행 정책의 두 번째 축(인용)을 요구한다.

## 고려한 대안

### 원천

| 대안 | 장점 | 단점·위험 | 전환 비용 |
|---|---|---|---|
| A. 전역 파일만 | 파서 하나, 형식 결합 없음 | 작업별 회귀 테스트가 게이트에 못 들어감 — 이 사이클의 목적(의무 목록 강제) 미달 | — |
| B. 전역 파일 + work-log `gates` 펜스 (묶음 B 초안) | 파서 하나, AI-DLC와 동형 | 의무 목록과 중복 정의. 어느 행을 펜스에 옮길지 에이전트 재량 → 드리프트와 누락 | 낮음 |
| C. 전역 파일 + 의무 목록 `유지` 행 (채택) | 단일 정의. 진입 조건이 결정성 필터. 에이전트 재량 0 | 표 파서 추가(열 위치 결합), 한국어 상태 비교 | 낮음 — 파서 20줄 |
| D. 의무 목록만 | 가장 단순 | 린트·시크릿 스캔 같은 작업 무관 게이트를 둘 곳이 없음 | — |

### 실패 판정

| 대안 | 평가 |
|---|---|
| 타임아웃 = 실패 (AI-DLC) | 느린 머신에서 오차단 → 사용자가 `DISABLE`을 켜고 잊는 경로. 게이트 신뢰를 먼저 깎음 |
| 타임아웃 = 인프라 통과 + 카운트 (채택) | 오차단 없음. 무력화는 카운트로 감시. Q-04 확정(2026-09-20 승인) |
| 명령 없음(9009) = 실패 | gitleaks 미설치 환경에서 모든 Stop이 block — 도입 장벽 | 
| 명령 없음 = 인프라 통과 + 카운트 (채택) | 도구 도입은 점진적. 미설치 = 스캔 없음이 명시적으로 남음 |

### 실행 빈도

| 대안 | 평가 |
|---|---|
| 매 Stop마다 실행 | 단순하나 무변경 턴에도 비용. RISK-01 |
| 트리 키 인용 (채택) | ADR-004의 인용 원칙을 훅에 그대로 — 같은 트리에서 같은 명령의 결과는 같다. 키 = HEAD + status + diff 해시 |
| 열린 작업의 `completed` 전이 시에만 | Stop 훅이 그 시점을 알 수 없음(문서 상태 변화 감지 필요). 그물의 촘촘함이 떨어짐 |

## 결정

원천 C, 판정은 "완료된 실행의 exit≠0만 실패", 빈도는 트리 키 인용. `docs/quality-gates.md`는 저장소 전역 게이트와 불변 설정 원칙(FR-07)만 담는다. 작업 단위 게이트는 의무 목록 `유지` 행이며, 다른 어떤 문서 위치도 게이트가 아니다.

## 이유

세 축이 같은 원칙에서 나온다. **정의는 한 곳, 판정은 기계, 재실행은 트리가 바뀐 때만.** 첫째는 사이클 1이 "정본 하나" 원칙으로 세운 의무 목록을 게이트가 그대로 소비하는 것이고, 둘째는 fail-open 관례(기존 훅 3종)와 "실행하지 못한 검증은 성공 아님" 원칙의 교차점 — 실행하지 못한 게이트는 통과도 실패도 아니므로 막지 않되 기록한다 — 이며, 셋째는 ADR-004의 인용 조건을 훅 수준에서 반복한 것이다.

## 결과와 감수할 단점

- 훅이 work-log 표 형식에 결합된다. 의무 목록 열 순서가 바뀌면 파서도 바뀌어야 한다 — 형식 변경은 wf-doc 소유이므로 변경 시 훅 테스트가 잡도록 T-계열에 파서 테스트를 둔다.
- 인프라 통과는 우회 경로다. `infraCount`를 §3.5에서 읽는 규칙으로 보완하고, 반복 시 timeout 상향.
- 인용 키 계산이 큰 diff에서 비용을 가진다(수 MB diff 해시). 무시 가능한 수준이나 측정 대상.
