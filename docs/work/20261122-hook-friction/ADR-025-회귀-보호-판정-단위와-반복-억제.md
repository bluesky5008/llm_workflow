## 배경

ADR-014는 「`유지` 테스트를 고쳐 통과시키는 것」을 막으려고 대장 `테스트 파일` 패턴에 맞는 파일의 편집마다 사람 확인을 받고(`ask`), 종료 시 마지막 성공 SHA 이후 그 파일이 바뀌었으면 기록이 없을 때 차단한다. 대장의 보호 단위는 파일·폴더이고 판정은 파일 이름 단위라, 기존 테스트 파일에 테스트를 **더하기만** 해도 위반이다. TDD는 실패하는 테스트를 먼저 쓰라고 요구하므로 워크플로우 자신의 규정이 매번 확인과 차단을 만든다. 판정은 상태를 남기지 않아 같은 이유로 편집마다, Stop마다 반복된다. 규정(주의 ④·§3.3·§6)과 메시지는 「수정」의 범위와 「정당한 변경」의 기준을 주지 않아 Claude가 사용자에게 다시 묻는다. 사용자 보고(2026-11-22): 강요되는 선택의 대부분이 이 C·D 경로다.

## 영향을 받는 요구사항과 제약

- 회귀 보호의 목적(테스트를 고쳐 통과시키는 것을 막는다)은 유지한다.
- C층 NFR-01 fail-open과 그 예외(가드 fail-to-ask), 판정의 하네스 중립(B층), 대장 열·상태값·판독 규칙 무변경.
- 훅은 테스트를 실행하지 않는다(실행 비용·시간 제한).
- `deny`는 쓰지 않는다(ADR-014 결정 1 조건 미충족).

## 결정

1. **위반의 정의.** 보호 테스트 파일의 변경은 변경 전 줄이 변경 후에 같은 순서로 모두 남지 않거나(줄 단위 부분열 — 주석 처리·줄 안 수정·삭제·이름 변경 포함) 새 줄이 공유 비활성화 패턴(테스트를 끄는 **구문**)에 맞을 때만 위반이다. 그 밖의 순수 추가(새 파일 생성 포함)는 위반이 아니다. 패턴은 B층 데이터 파일 한 곳이 정본이고 C층 가드는 같은 파일로, 편집을 메모리에서 적용한 결과에 같은 판정을 한다. 파일 단위 판독 불가(이진 파일·diff 판독 실패·가드 판정 예외)는 위반 쪽으로, 판정 스크립트 자체의 오류는 기존 fail-open(게이트 통과)으로 둔다.
2. **지문과 해소.** 테스트 파일 위반마다 삭제 줄과 패턴에 맞은 줄의 내용만으로 지문을 만든다(줄 번호·다른 순수 추가와 무관). 테스트 파일 위반은 열린 작업 기록에 행 ID와 그 지문이 함께 기록되어야 해소된다 — 기록 뒤의 새 삭제는 새 지문이라 다시 위반이다. 대장 축소 위반은 기존대로 행 ID로 해소한다.
3. **반복 억제.** 가드는 사용자가 허락해 실제로 실행된 편집(PostToolUse의 경로·도구 입력이 `ask` 때와 같음)의 테스트 파일을 세션 동안 다시 묻지 않는다. 게이트는 같은 세션에서 이미 차단한 (행 ID·파일·지문) 키만 남았으면 다시 차단하지 않는다. 게이트 설정 파일과 NotebookEdit는 기억하지 않는다.
4. **사람의 판정 범위.** 보호 테스트 변경은 순수 추가(기록 불요) · 단언 보존 변경(지문과 함께 기록 후 진행, 완료 보고에서 일괄 확인) · 단언 약화(진행 중 금지, §6으로 즉시 판정) 셋으로 나눈다. 승인된 DCR이 바꾼 동작에 따른 기대값 변경은 §6 판정 (b)가 내려진 것으로 보고 `Breaking`으로 기록한다. 판단이 서지 않으면 단언 약화로 본다. 냄새 제거 목적의 `리팩터`는 ADR-024대로 독립 재정비 작업 한정이다.
5. **기록할 곳이 없을 때.** 남은 위반(순수 추가가 아닌 것)은 열린 작업 기록이 없어도 차단한다(결정 3으로 키마다 세션당 1회). 기록이 필요하면 경량 경로 작업 기록을 만들고, 기록한 작업을 닫을 때 그 행의 마지막 성공 SHA를 갱신한다.
6. ADR-014 결정 1(편집 시 `ask` + 종료 시 diff 판정)·3(가드 fail-to-ask)은 유지한다. 바뀌는 것은 「무엇이 위반인가」와 「몇 번 묻는가」다.

## 이유

- 회귀 보호가 막으려는 것은 「단언을 약화해 통과시키기」다. 줄을 지우거나 바꾸지 않고, 테스트를 끄는 표현도 없는 추가는 기존 단언을 약화할 수 없다(값 없는 `return`처럼 끄는 효과가 있는 줄은 패턴으로 잡는다).
- 같은 사람에게 같은 이유를 반복해 묻는 것은 정보를 주지 않고 승인 피로만 만든다. 기억은 `ask`를 낸 바로 그 편집이 실행되었을 때(경로·도구 입력 해시 일치)에만 생기므로 거절을 우회하지 않는다. 기억 뒤의 약화는 종료 게이트가 새 지문으로 다시 잡는다 — 해소가 지문 단위이기 때문이다.
- 사람 판정이 필요한 경우를 규정에 명시하면 Claude가 모호함 때문에 묻는 일이 사라진다. 단언 보존 변경은 완료 보고의 기존 일괄 확인으로 충분하다.

## 결과와 감수할 단점

- 패턴 밖의 무력화 삽입(조건부 skip, 환경 변수로 끄기, 값을 돌려주는 조기 `return` 등)은 순수 추가로 통과한다. 완료 보고의 diff 검토와 대장 `보호 스코프` 열의 테스트 수(「총 N」) 대조로 보완하고, 발견되면 패턴 파일에 더한다.
- 같은 내용 줄의 위치 이동은 Write 부분열 판정에서 놓칠 수 있다(단언 의미는 같다).
- 세션 상태 파일(`<sid>.guard.json`)과 PostToolUse 항목이 늘어 편집마다 PowerShell 기동이 1회 늘어난다.
- 게이트 억제로, Claude가 차단을 무시하면 그 세션에서는 같은 키로 다시 막지 않는다. 다음 세션과 `completed` 전이에서 다시 드러난다.
- 단언 보존 변경으로 분류해 지문을 기록하는 주체가 Claude라, 잘못 분류하면 게이트를 통과한다(기록 확인이지 승인이 아님). 완료 보고의 일괄 확인이 보완한다.
- 테스트 파일 위반의 해소에 지문이 필요해져, 지문 없는 기존 형식의 기록은 테스트 파일 위반을 해소하지 못한다. 이 저장소의 열린 기록은 이 작업뿐이지만 훅은 전역이라, 다른 저장소의 그런 기록은 키마다 세션당 1회 차단되고 지문을 더하면 해소된다.
