## 문제와 목적

llm_workflow의 개발 내용(문제의식, 2-워크플로우 구조, 스킬 4종, 문서 모델, 세션 핸드오프, 설치 체계, 개발 이력)이 저장소 문서에만 존재하여 동료 개발자가 전체 그림을 빠르게 파악하기 어렵다. 정보 공유용 발표 자료를 만들어 전달한다.

- **발표 대상:** 내부 동료 개발자
- **발표 목적:** 개발 내용의 정보 공유(설득·의사결정 아님)
- **산출 순서(사용자 지정):** 내용 초판을 md로 작성 → 사용자가 md로 내용을 검토 → pptx로 구현 → 사용자가 pptx로 구현 완성도를 검토

## 대상과 시나리오

- **시나리오 1 (발표):** 발표자가 pptx를 띄우고 구두 발표한다. 슬라이드는 요점 위주, 세부 설명은 발표자 노트가 보조한다.
- **시나리오 2 (사후 열람):** 발표를 듣지 않은 동료가 자료만 읽어도 전체 구조를 이해할 수 있다(노트 포함 열람 전제).
- **시나리오 3 (내용 갱신):** md 정본을 수정하고 생성 스크립트를 재실행하면 pptx가 재생성된다.

## 기능 요구사항

- FR-01 (커버리지): 발표 자료는 다음 주제 각각을 하나 이상의 슬라이드에서 다뤄야 한다 — (a) 문제의식과 2-워크플로우 전체 구조, (b) 스킬 4종(wf-design·wf-implement·wf-doc·wf-tree) 각각의 역할, (c) 소유권 경계·정본 모델, (d) 경량 경로, (e) 최소 구현 원칙(결정 사다리)과 TDD, (f) 문서 모델(저장소 관통 문서 + 작업 일지, 식별자·추적성), (g) 세션 핸드오프 3층 설계와 C층 훅(구현·검증 결과 포함), (h) 설치·어댑터와 하네스 중립 원칙, (i) 개발 이력 타임라인, (j) 현재 상태와 남은 과제.
- FR-02 (md 초판): 초판은 슬라이드 단위 구조(슬라이드 제목·본문·발표자 노트)를 갖춘 단일 md 문서여야 하며, 내용 검토의 대상이자 이후 갱신의 정본이다.
- FR-03 (pptx 생성): 스크립트는 md 정본을 파싱하여 .pptx를 생성해야 하며, 슬라이드 수·제목·본문·노트가 md와 일치해야 한다.
- FR-04 (재생성): md 수정 후 스크립트 재실행만으로 pptx가 갱신되어야 한다(수작업 후편집을 전제하지 않는다).
- FR-05 (디자인 시스템, v2): 스크립트는 모든 슬라이드에 DES-05의 디자인 시스템(5색 팔레트, 표지·본문 배치, 폰트 크기 체계)을 자동 적용해야 한다.
- FR-06 (인포그래픽, v2): 스크립트는 md의 태그 펜스(`flow`·`rows`·`ladder`)를 도형 기반 다이어그램으로, DES-06이 지정한 슬라이드 2곳을 카드형 배치로 렌더링해야 한다. 무태그 펜스는 고정폭 패널로 유지하고, 카드 매핑 실패 시 일반 불릿으로 폴백한다.

## 비기능 요구사항

- NFR-01 (정확성): 발표에 담는 사실(수치, 결정, 상태)은 저장소 문서·커밋에서 추적 가능해야 한다. 미완료 항목(실세션 관찰 VER-06·07, B층 미착수 등)을 완료로 표현하지 않는다.
- NFR-02 (한글 무손상): md와 pptx 전 과정에서 한글이 손상되지 않아야 한다(UTF-8, 한글 폰트 지정).
- NFR-03 (가독성): 본문 슬라이드는 요점 위주로 유지한다(대략 슬라이드당 불릿 6개 이내를 기준으로 하되, 세부는 발표자 노트로 이동).
- NFR-04 (디자인 가독성, v2): 텍스트와 배경의 명도 대비가 충분해야 하며, 다이어그램 안의 텍스트가 잘리거나 겹치지 않아야 한다(실열기·육안 검토로 확인).

## 인수 조건

- AC-01: md 초판에서 FR-01의 주제 (a)~(j) 각각이 어느 슬라이드에서 다뤄지는지 매핑 표로 확인할 수 있고, 누락된 주제가 없다.
- AC-02: 생성 스크립트를 실행하면 오류 없이 .pptx가 생성되고, 자동 대조(생성물 재열기)에서 슬라이드 수와 제목이 md 정본과 일치한다.
- AC-03: 생성된 pptx를 PowerPoint에서 실제로 열어 모든 슬라이드가 렌더링되고 한글이 깨지지 않음을 확인한다.
- AC-04: 사용자 검토 2회를 통과한다 — (1) md 초판의 내용 검토를 통과한 뒤에 pptx를 생성하고, (2) pptx의 구현 완성도 검토로 작업을 완료한다.
- AC-05 (v2): 재생성한 pptx에서 (1) 전 슬라이드에 디자인 시스템이 적용되고 (2) 지정 슬라이드에 도형 다이어그램이 존재함을 테스트로 확인하며 (3) AC-02·03이 계속 통과하고 (4) 사용자 완성도 검토를 재수행한다.

## 설계 목표와 제약

- **단일 소스:** 내용의 정본은 md 하나다. pptx는 md에서 기계적으로 파생되며 손으로 고치지 않는다(wf-tree의 단일 소스 원칙과 동형).
- **검토 2단 분리:** 내용 검토(md)와 구현 완성도 검토(pptx)를 분리한다 — 사용자 지정 진행 방식.
- **최소 구현:** 스크립트는 이 덱을 만드는 데 필요한 md 부분집합만 파싱한다. 범용 md→pptx 변환기를 만들지 않는다.

## 컴포넌트와 책임

- DES-01: **md 슬라이드 형식 계약** — `dev-briefing.md`는 다음 부분집합만 사용한다. 문서 첫 `# 제목`은 표지 슬라이드(이후 첫 `##` 전까지의 불릿은 부제·메타 정보), 이후 각 `## 제목`이 본문 슬라이드 1장을 연다. 슬라이드 안에서 `-` 불릿(2단 중첩까지)은 본문 텍스트, ``` 코드 블록은 렌더 단락, `> 노트:`로 시작하는 인용 블록(연속 `>` 줄 포함)은 발표자 노트가 된다. 표·이미지·기타 md 요소는 사용하지 않는다(불릿 또는 코드 블록으로 표현). (v2 개정, DCR-002) 코드 펜스는 태그로 렌더 유형을 지정할 수 있다 — `flow`·`rows`·`ladder`는 DES-06의 도형 다이어그램, 무태그는 기존과 같은 고정폭 패널. 태그는 렌더 방식만 바꾸며 내용의 의미는 바꾸지 않는다(하위 호환).
- DES-02: **슬라이드 구성(안)** — 18장. ① 표지 ② 문제의식: AI 코딩 위임의 실패 모드 ③ 해법 개요: 2-워크플로우 + 승인 관문 ④ 스킬 아키텍처: 4종과 소유권 경계·정본 모델 ⑤ wf-design: 요구사항·설계·ADR·역공학 ⑥ 승인 관문과 기준선·DCR ⑦ wf-implement: 계획→구현→검증→리뷰→통합 ⑧ 최소 구현 원칙(결정 사다리)과 TDD ⑨ wf-doc: 머리말·상태·식별자·하이퍼링크 강제 ⑩ 문서 모델: 저장소 관통 문서 + 작업 일지 ⑪ wf-tree: 계획 트리·포트폴리오 ⑫ 경량 경로 ⑬ 세션 핸드오프 문제와 3층 설계 ⑭ C층 훅 3종과 ADR-001 ⑮ C층 구현·검증 결과 ⑯ 설치와 어댑터: 하네스 중립 ⑰ 개발 이력 타임라인 ⑱ 현재 상태·남은 과제·정리. FR-01 (a)~(j)와의 매핑: (a)②③ (b)⑤⑦⑨⑪ (c)④ (d)⑫ (e)⑧ (f)⑩ (g)⑬⑭⑮ (h)⑯ (i)⑰ (j)⑱. 장수와 순서는 md 내용 검토(AC-04)에서 조정될 수 있으며, 조정은 매핑의 완전성(AC-01)을 유지해야 한다.
- DES-03: **생성 스크립트** — `make_pptx.py`는 (1) md를 DES-01 계약으로 파싱하고 (2) python-pptx로 16:9 덱을 생성하며(표지는 제목 레이아웃, 본문은 제목+본문 레이아웃, 폰트 맑은 고딕, 노트는 notes_slide에 기록) (3) 저장 직후 생성물을 다시 열어 슬라이드 수·제목을 md 파싱 결과와 대조하고 결과를 출력한다(AC-02의 자동 대조 내장). 인자 없이 실행하면 같은 폴더의 `dev-briefing.md` → `dev-briefing.pptx`를 처리한다. (v2 개정, DCR-002) 생성 시 DES-05의 디자인 시스템과 DES-06의 인포그래픽 렌더러를 적용한다.
- DES-04: **스크립트 테스트** — `tests/test_make_pptx.py`는 견본 md(표지+본문 2장, 중첩 불릿·코드 블록·노트 포함)로 파서와 생성기를 검증한다. 외부 테스트 프레임워크 없이 `python tests/test_make_pptx.py` 단독 실행으로 성공·실패를 판정한다(저장소에 기존 Python 테스트 체계 없음). (v2 확장) 태그 펜스 파싱, 다이어그램 도형 존재, 무태그·카드 매핑 폴백 케이스를 추가한다.

## 데이터와 인터페이스

- 입력: `dev-briefing.md` (UTF-8). 출력: `dev-briefing.pptx` (16:9).
- 실행 계약: `python make_pptx.py` — 성공 시 대조 결과 요약을 출력하고 exit 0, 파싱·대조 실패 시 원인을 출력하고 exit 1.
- md 계약의 상세는 DES-01이 정본이며, 스크립트 상단 주석에 요약을 둔다.

## 정상·실패·복구 흐름

- 정상: md 편집 → 스크립트 실행 → 자동 대조 통과 → pptx 갱신.
- 실패: 계약 밖 md 요소(표 등) 발견 시 해당 줄 번호와 함께 실패 종료(무시하고 누락된 덱을 만들지 않는다). python-pptx 미설치 시 설치 안내를 출력하고 실패 종료.
- 복구: md 수정 또는 의존성 설치 후 재실행. pptx는 항상 전체 재생성이므로 부분 손상 상태가 없다.
