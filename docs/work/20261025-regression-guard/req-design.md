## 현재 상태 조사 (wf-design §4.1)

### 사실

- **강제 대상 규칙(main):** wf-implement 주의 ④ "대장 `유지` 행의 테스트를 수정·제외해 통과시키지 않는다", §3.3 "진행 중에는 등록·격리 외의 전이와 기존 테스트의 수정·제외·삭제를 하지 않는다 — 정리는 재정비 관문에서만", §3.4·§2.4 "TDD 테스트는 최초 실패와 구현 후 성공을 모두 증거로 기록". 명세·테스트 충돌 시의 행동 규정은 없다.
- **테스트 대장 형식:** 열 `ID | 테스트·명령 | 보호 스코프 | 크기 | 발행 작업 | 상태 | 마지막 성공 (일시 · SHA) | 비고`. 테스트 **소스 파일**을 가리키는 열이 없다 — `테스트·명령`은 명령이라 TST-02처럼 디렉터리만 보이거나, `보호 스코프`는 보호 대상 제품 코드다. 템플릿은 마지막 성공을 `일시 · SHA`(+`+dirty`)로 정하지만 TST-01 셀은 `HEAD+미커밋(29/29, …; 직전 clean 성공 a38ed25 22/22)`로 형식을 벗어난다.
- **C층 훅(REQ·DESIGN-llm-workflow v3):** 3종 모두 `additionalContext` 주입만 하며 차단 출력이 없다. NFR-01 fail-open(오류 시 무출력 통과), NFR-03 성능, FR-05 저장소 가드(`docs/work/` 없으면 무동작), DES-05 ASCII 전용 소스(한글은 `messages/*.md`). 설치는 `Install-WfHooks`가 `wf-*.ps1` 경로 매칭으로 자기 항목을 식별·병합.
- **Claude Code 훅 사양(2026-10-25 공식 문서 확인):** PreToolUse는 `permissionDecision` `allow | deny | ask`(+ 비대화 `defer`)를 반환할 수 있다. `deny`는 `bypassPermissions` 모드에서도 유지된다. `ask`는 "평소처럼 권한 프롬프트를 보인다". 입력의 `tool_input.file_path`가 편집 대상. Stop 훅은 `{"decision":"block","reason":…}`로 종료를 막고, 입력의 `stop_hook_active`로 재진입을 알 수 있으며, 연속 8회 차단 시 Claude Code가 무시한다.
- **작업 기록 린트:** L3 필수 필드 `결정과 이유·검증·결과`, 항목당 8행·600자 상한. 열린 작업 기록만 검사하므로 완료(동결) 기록은 영향 없음. 수행 기록 항목에는 TASK가 아닌 항목(착수·조사)도 있다.
- **스킬 어절:** wf-implement 본문 2,846 / 상한 2,850(lint_skill K3) — 여유 4어절.
- **테스트 자산:** TST-01 훅 러너 29건(Windows PS 5.1), TST-02 린트 pytest 49건. 이 세션은 사용자 PC의 셸을 쓸 수 없어 PS 5.1 실행은 사용자가 수행한다(선례: 2026-10-18).
- **대상 하네스(사용자 지시, 2026-10-25 승인 관문):** Claude·Codex 외에 사내 에이전트(SEMCo-Work, [개발 브리핑](../../presentation/dev-briefing.md)의 회사 주력 예정 하네스)에서도 동작해야 한다. SEMCo-Work의 확장점(종료 직전·편집 직전 개입)은 미확인. B층 스크립트는 `skills/wf-doc/scripts/`의 표준 라이브러리 Python([ADR-006](../20261009-worklog-diet/ADR-006-작업-기록-린트-B층.md)).
- **자기 게이트 해제 경로:** 대장에서 `유지` 행을 `격리`로 바꾸거나 지우면 두 훅의 보호 대상에서 빠진다. 게이트 설정 파일(훅 등록)의 위치는 하네스마다 다르다.

### 해석

- 강제는 두 겹이 필요하다. **편집 시점**(PreToolUse)은 Edit/Write 경로만 보고 셸 편집(`sed -i`, 리다이렉션)은 못 본다. **종료 시점**(Stop)의 diff 검사가 그 구멍을 메운다. 어느 쪽도 의도적 우회를 완전히 막지는 못하므로 목표는 "조용한 변경을 기록된 변경으로 바꾸는 것" — 기록되면 완료 보고 관문에서 사람이 본다.
- 정당한 테스트 수정(테스트 자체의 오류, DCR)이 존재하므로 무조건 차단보다 사람 확인이 맞다. 다만 권한 프롬프트를 자동 승인하는 모드에서 `ask`가 어떻게 동작하는지는 문서에 명시가 없어 구현 첫 단계에서 확인해야 한다.
- 훅이 대장을 읽으려면 대장이 기계 판독 가능한 테스트 파일 경로와 정규화된 SHA를 가져야 한다 — R-01이 R-02·R-03의 전제다.
- 충돌 출구(R-04)는 의미 규칙이라 스킬에 둔다. 본문 어절 여유가 4어절뿐이므로 규칙 본체는 references, 본문은 링크만.
- 종료 시점 판정을 Claude 훅(PS1) 안에 두면 SEMCo-Work가 재사용할 수 없다. 판정은 git과 Python만 쓰는 B층 스크립트로 두고, 어댑터는 호출과 출력 변환만 맡는다. 확장점이 없는 하네스는 같은 스크립트를 완료 보고 전 또는 git pre-commit에서 실행해 쓸 수 있다. 편집 시점 가드는 매 편집 지연 때문에 어댑터가 같은 대장 규칙으로 직접 구현한다.

### 가정

- 이 저장소의 사용자는 1인이며, 훅의 확인 요청에 응답하는 사람이 승인권자다.
- 대장이 없는 저장소(`docs/test-register.md` 부재)에서는 두 새 훅이 무동작이어도 된다 — 대장 도입 전 레거시 테스트의 보호는 [레거시 편입 R-13](../../research/20261025-aidlc-trends/04_test_action_items.md#레거시-테스트-정비--기존-코드-저장소에-적용할-때-2026-10-25-추가)이 담당.
- git이 실행 환경에 있다(기존 전제).

| FR-03 | 보호 대상 편집 확인 | 에이전트가 파일 편집 도구로 보호 대상을 바꾸려 하면 실행 전에 사용자 확인을 거쳐야 한다. 보호 대상은 `유지` 행의 테스트 파일(공통)과 그 하네스 어댑터가 선언한 게이트 설정 파일(Claude: `~/.claude/settings*.json`, `<cwd>/.claude/settings*.json`)이다. 미등록 파일·새 테스트 파일·대장 자체는 확인 없이 진행한다(대장은 FR-08이 사후 검사). 이 작업은 Claude 어댑터만 구현한다 — [DCR-015](./DCR-015-C층-회귀-보호-훅-추가.md) |
| FR-04 | 종료 시 대장 변경 정합 | 하네스 중립 판정 스크립트는 `유지` 행의 테스트 파일이 그 행의 마지막 성공 SHA 이후 바뀌었는데 열린 작업 기록의 `### 테스트 대장 변경`에 그 행 ID가 없으면 위반으로 보고하고 0이 아닌 코드로 끝나야 한다. 테스트는 실행하지 않는다. Claude 어댑터는 세션이 응답을 마치려 할 때 이 스크립트를 호출해 위반이 있으면 종료를 1회 막고 기록하거나 되돌리라고 지시한다 — [DCR-015](./DCR-015-C층-회귀-보호-훅-추가.md) |
