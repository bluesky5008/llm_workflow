사용자 요청(2026-10-28): 이 저장소에서 할 일 1번 — 레거시 묶음 ①(R-13 + R-11) 규칙 설계. 04는 "편입이 정비보다 먼저"라고 정한다: 기존 코드 저장소의 테스트는 대장에 없어 가드(`wf-test-guard`·`wf-stop-gate`)의 보호를 받지 못하므로, 새 워크플로우로 코딩하는 동안 에이전트가 레거시 테스트를 자유롭게 고칠 수 있다.

## 현재 상태 조사

### 확인된 사실

- 착수 HEAD `539c80c`, 워킹트리 clean. 열린 작업 없음(보류 1건 `20260814-multiuser-workflow`).
- [verification-depth §2](../../../skills/wf-implement/references/verification-depth.md#2-상태와-전이): `유지` 진입 조건은 "같은 SHA에서 2회 통과(Green 1회 + `completed` 전이 1회)"이고 허용 시점은 TASK `completed` 전이다. 편입은 TDD Green이 없어 이 조건을 그대로 쓸 수 없다.
- 상태값은 `유지 · 대체 · 병합 · 격리 · 폐기` 5종, 괄호에 분류·대상·일시(templates 테스트 대장 노트). `격리`의 기존 사유는 결과 불일치와 실행 환경 원인뿐 — "둘 다 실패(기존 실패)"는 없다.
- 대장 판독기 둘 다 상태가 `유지`로 **시작하는지만** 본다: `regression_guard.py`(`state.startswith("유지")`), `wf-common.ps1` `Get-WfKeptTestFiles`(`StartsWith($kKeep)`). `격리(기존 실패, …)`처럼 괄호 분류를 늘리는 표기는 판독 코드 변경이 없다.
- `보호 스코프`는 자유 서술 열이며 `미확정` 같은 값의 규칙이 없다. [§1](../../../skills/wf-implement/references/verification-depth.md#1-시점별-실행-집합) "관련 행"은 보호 스코프와 변경 파일·심볼의 겹침으로 정의된다 — 스코프가 비면 관련 행 판정이 불가하다.
- 행 단위는 "실행 명령 하나로 도는 묶음(파일 또는 러너)" — 04의 "처음엔 파일·디렉터리 단위로 거칠게"와 맞는다.
- `마지막 성공` 3형식 중 `없음 — <이유>`가 있어 기존 실패 행을 표현할 수 있다.
- wf-implement 본문 2,850/2,850어절(K3 경고). §3.1에 트리거를 넣으려면 다른 문장을 references로 옮겨 상쇄해야 한다(05 Q-D9 선례: 순증 0).
- 이 저장소에 커버리지 도구 없음(`pytest_cov`·`coverage`·`testmon` 미설치, 2026-10-28). R-11은 외부 저장소 도구가 전제.
- 재사용 후보 자산: 대장 템플릿·`### 테스트 대장 변경` 표(templates), 재정비 관문 절차(§3), `격리` 즉시 전이 규칙, `regression_guard.py`·`wf-common.ps1` 판독(무변경 예상), 역공학 10단계(테스트 분석) RR 항목([reverse-engineering.md](../../../skills/wf-design/references/reverse-engineering.md)).

### 해석

- 편입은 새 상태값 없이 **진입 경로 하나(편입 전이)** 와 `격리` 사유 하나(기존 실패), 보호 스코프 값 하나(`미확정`)로 표현될 가능성이 높다 — 코드·훅 변경 0, 규칙은 `verification-depth.md` 새 절과 templates 노트.
- R-11은 통합의 재정비 관문(§3)에 "커버리지 도구가 있으면 보호 스코프를 다시 적고 손 값과 차이를 기록"하는 단계로 들어가며, 편입에서는 `미확정` 채우기의 수단이다.

### 가정

- 외부 저장소의 첫 작업이 편입이 된다(04 "적용 첫날"). 이 저장소는 대장 5행이 이미 등록되어 편입 시범 대상이 없다 — 검증은 문서 규칙(`lint_skill`)과 견본 수준.
