## 배경

현행 재정비 관문([ADR-009](../20261009-test-lifecycle/ADR-009-테스트-재정비-관문.md))은 통합·DCR 승인 시점에 이번 변경이 닿은 행만 다루고, 승인은 완료 보고 관문의 일괄 응답 하나다. 상태값 5종에는 테스트를 고쳐서 유지하는 처분이 없고 wf-implement §3.3은 진행 중 기존 테스트 수정을 금지한다. 4조건의 「유일 검증 아님」은 인수 조건 연결을 전제하는데 레거시 행에는 AC 가 없다. 마켓 측정(2026-10-29)은 라인 지배 54%·A급 18파일 105건을 냈지만 이 규칙 공백 때문에 정리할 수 없다. 판독기(`regression_guard.py`·`wf-common.ps1`)는 상태가 `유지`로 시작하는지만 보고, Stop 게이트는 열린 작업 기록의 `### 테스트 대장 변경` 절에 적힌 행 ID 를 통과시키며, PreToolUse 가드는 파일마다 `ask` 한다.

## 영향을 받는 요구사항과 제약

- FR-01~09, NFR-01(wf-implement 본문 ≤ 2,850·wf-design ≤ 2,300), NFR-02(판독·훅 무변경), NFR-03(도구 중립).
- wf-implement 본문 여유 57어절, wf-design 131어절. C층 훅 변경은 DCR. verification-depth 는 본문과 다르면 본문이 우선한다 — 승인 단위·반영 시점의 예외는 본문이 말해야 한다.
- 04 D-6: 「배치마다 1회. 승인 범위는 사람이 승인한 req-design 에서 읽고 plan.md 에서 읽지 않는다」.

## 고려한 대안

| 대안 | 내용 | 판단 |
|---|---|---|
| A | 정식 경로 작업의 한 종류(req-design 필수 절 + verification-depth §8) · `리팩터`는 새 상태값 없이 `유지` 유지 + `비고`·대장 변경 절 표기 · `고아` 일괄, 판단 분류는 배치별 행 승인 · 가드는 규칙만(Stop 게이트의 기록 단위가 배치, PreToolUse 는 파일별 `ask` 유지) | 채택 |
| B | 별도 문서 유형·워크플로우(「재정비 작업」 전용 스킬 절·템플릿) | 승인 게이트·린트·작업 기록 규칙을 다시 만들어야 하고 wf-design 본문(2,300 상한)도 늘어난다. 정식 경로가 이미 요구하는 승인·기록으로 충분 |
| C | 새 상태값 `리팩터(…)` 추가 | 판독기가 `유지` 접두만 보므로 그 행이 보호에서 빠지거나 판독 코드·훅·공유 견본·린트를 바꿔야 한다(NFR-02 위반). R-12 레코드화 때 한 번 더 바꾼다 |
| D | 가드가 승인된 req-design 의 대상 TST 범위를 읽어 배치 안 파일은 `ask` 생략(D-6 완전 구현) | C층 DES-06 변경 = DCR·훅 테스트. 가드는 편집 호출마다 `ask` 하므로 첫 배치(18파일)의 확인 횟수는 최소 18회(하한)이며 감내 가능하다고 보고, 피로가 실측된 뒤 DCR 로 미룬다 |
| E | 커버리지 유일 라인 0 을 유일성 부정의 단독 근거로 허용 | 값 변형 테스트의 단언을 라인 지배만으로 잃는다(측정 보고 §6 ③). §3 「겹침은 후보 신호」 원칙과 충돌 |

## 결정

A를 채택한다.

1. **형태.** 대장 일부·전부를 범위로 하는 독립 재정비 작업은 정식 경로 작업의 한 종류다(경량 불가). req-design 의 `### 대상 TST 범위·배치·성공 기준` 절(대상 행·배치 분할·성공 기준 5항과 목표치·증거 수단 — 요구는 wf-design §4.2, 정의는 verification-depth §8)이 배치 승인 범위의 정본이고 plan.md 는 범위를 넓히지 못한다. 행 분리로 생긴 새 행은 원 행 범위다. 제품 코드(테스트 코드·대장·문서 제외)는 착수 SHA 대비 diff 0. §2 `병합`·`폐기`의 허용 시점과 §3 의 시점에 이 작업의 배치를 더한다.
2. **배치.** 배치 = TASK. 착수 측정(clean 커밋의 배치 착수 SHA 기록·보호 스코프 확정 포함) → 후보 선별(신호) → 행별 판정(`폐기`·`병합`은 4조건, `리팩터`는 FR-04 증거 — 같은 제품 SHA 수정 전·후 통과 + kill 비감소 또는 단언 보존) → `### 테스트 대장 변경` 기록 → 배치 승인 → 승인 행만 반영·거부 행 복원 → 종료 측정(성공 기준 5항 — (1)(4) 미달은 행 복원, (2) 전량 실패는 원인 행 복원 또는 배치를 배치 착수 SHA 로 되돌림, (3) 제품 diff 는 제품 코드만 배치 착수 SHA 로 복원하고 전이 유지, (5) 목표치 미달은 사용자 판정). 흡수 행은 같은 작업에서 폐기·병합되지 않는다.
3. **`리팩터`.** 상태값이 아니다. 행은 `유지` 그대로, `비고`에 `리팩터(분류, 일시)`, 대장 변경 절에 `유지 → 유지(리팩터)`. 경계는 단언 보존(같거나 더 강한 단언이 남으면 `리팩터`, 제거·약화·기대값 변경은 §2 재생성 = `병합`, 4조건). 증거는 같은 제품 SHA 에서 수정 전·후 통과 + kill 집합 비감소 또는 단언 보존. 유일성 조건은 없다. 독립 재정비 작업 안에서만.
4. **유일성(AC 없음).** ① 뮤테이션(수동 표본 허용) ② 역공학 RR 연결 ③ 단언 대조 순. 커버리지 지배·유일 라인은 선별 신호. 못 대면 `유지`. `미확정` 스코프 행은 `고아` 외 전이 불가 — 스코프부터 채운다.
5. **승인 계층.** `고아`는 목록 일괄, 판단 분류는 배치별 행 단위. 응답 인용을 대장 변경 절·재정비 기록에 `배치 N 승인(일자, "응답 인용")`로 남기고 승인 뒤에만 대장을 바꾼다. wf-implement 본문 §3.6 이 이 예외(승인 단위·반영 시점)를 말한다.
6. **가드.** 이번은 규칙만 — Stop 게이트의 기록 단위(열린 작업 기록의 대장 변경 절)가 배치 단위 통과 역할을 하고, PreToolUse 의 파일별 `ask`는 유지한다. 대안 D는 피로 실측 뒤 DCR.

## 이유

- 판독기가 접두만 보므로 A는 코드·훅을 바꾸지 않고 규칙 문서·템플릿만으로 성립한다(NFR-02). 선례 ADR-023 과 같은 결.
- 정식 경로의 승인 게이트(기준선 승인 전 제품 코드 편집 확인)·작업 기록 린트·완료 조건이 재정비 작업에도 그대로 걸린다 — B처럼 새 체계를 만들 이유가 없다.
- 배치 승인은 04 R-16 의 「건별 확인은 고무도장」 문제를 분류로 나눠 푼다 — 기계적 근거(`고아`)만 일괄, 판단이 필요한 것은 행 단위.
- D-6 의 「배치마다 1회」는 Stop 게이트에서 이미 성립한다. PreToolUse 까지 묶는 것은 C층 변경이라 비용 대비 근거(피로 실측)가 아직 없다.

## 결과와 감수할 단점

- PreToolUse `ask` 가 편집 호출마다 뜬다(RISK-01, 파일 수는 하한). 수백 건 배치에서 피로하면 DCR.
- `미확정` 스코프 행은 스코프를 채우기 전엔 `고아` 외 전이가 불가하다(RISK-08).
- 뮤테이션 도구 없는 저장소는 수동 뮤턴트 표본·단언 대조가 증거의 전부라 삭제 가능 건수가 줄고 비용이 든다(RISK-02). 삭제보다 보존을 택한 결과다.
- Stop 게이트는 기록을 보지 승인을 보지 않는다 — 승인 전 기록으로도 통과한다(RISK-04). 대장 반영을 승인 뒤로 묶어 사후 감사 가능하게 한다.
- 편입 행이 거칠어 개별 테스트 전이마다 행 분리가 필요하다(RISK-07).

## 후속 작업

- 마켓 첫 배치(A급 18파일)에서 확인 횟수·증거 비용·행 분리 수 기록. 피로가 확인되면 대안 D를 DCR 로.
- 뮤테이션 도구 도입 재평가(04 D-3)는 별도.
