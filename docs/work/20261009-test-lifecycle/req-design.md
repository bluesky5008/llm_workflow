## 문제와 목적

사용자의 사용 경험(2026-10-09 세션, 요구 7·8 원문 — 세션 기록에서 복구):

> 7) 회귀테스트의 효율적 관리방안이 필요하다. 현재 사용중인 기능은 회귀테스트의 증가방향만 있고, 정리 및 최적화 방안이 없다. 회귀테스트 작성 및 수행이 반복되는 도중 해당 테스트의 재정비 및 전체 테스트 목록 중 불필요 항목의 삭제 기능이 필요하다.
>
> 8) 회귀테스트 포함 단위테스트의 수행 결과를 기존의 전통적 관점의 SDLC에서 기록하는 결과와 비슷한 형태로 기록하고 관리하는 기능이 필요하다. 라인 커버리지, 함수 커버리지, 분기 커버리지 등을 측정하고 결과를 시각화 할 방법이 필요하다.

같은 세션에서 승인된 사이클 편성: 사이클 3 = "8의 기록 형식 + 7". 보관 브랜치의 9월 설계(3튜플 앵커, 테스트 맵, 회귀 의무 목록)를 input으로 재검토하되 재정비 관문을 더해 다시 설계한다. 8의 도구 선정·시각화, RTS 문헌, flaky 관리 기법은 3번 단계(외부 조사)로 이관됐다. 7에 대한 추가 논의에서 사용자는 "테스트 방법론 지침 + 정리 절차 명시"를 제안했고, 외부 근거(TEBench 등)로 찬성하되 분량 상한을 두기로 했다 — [조사 정리 §0·§4.4](../../research/20261009-test-lifecycle/testing_research_digest.md).

## 현재 상태 조사 (wf-design §4.1)

### 사실

- **현행 테스트 규정**(main, 커밋 `b5a97ee`): wf-implement §2.4(사소하지 않은 로직에 가장 작은 검증 하나, 기존 체계 안에서), §3.3(Red→Green→Refactor, 버그 재현 테스트 선행, 특성화 테스트), §3.4(6단계 검증, 실패 4분류, 명령·결과 기록), §3.5(회귀·행위 검증·TDD 미적용 이유 3문항), §5("관련 자동화 테스트와 빌드가 성공했다"). wf-doc 합본 템플릿의 검증 표 열은 `검증 ID / 인수 조건 / 방법·명령 / 결과 / 증거`. 품질 기준·수명주기·회귀 목록·SHA 귀속·정량 기록(건수·시간·커버리지)은 없다 — [조사 정리 §1.1~1.2](../../research/20261009-test-lifecycle/testing_research_digest.md).
- **보관 브랜치 설계**(`archive/202609-cycles`, `docs/work/20260920-regression-tier/`, 커밋 `bc970ef`): FR-01~10·DES-01~08 — 3튜플 앵커(테스트 집합·SHA·명령, ADR-004), `test-map` 문서 유형(작업 폴더 별도 파일, 표 `변경 예정 파일 / 관련 테스트 / 실행 명령 / 근거 / 사전 실행`, 맵 누락 기록), 시점별 실행 집합 표(`references/verification-depth.md`), work-log `## 회귀 의무 목록`(상태 `유지 | 대체 | 폐기 | 보류`), 검증 표 `분류` 열, 명령 고정. 스킬 변경 4파일 148행. 후속 `20260920-enforced-gates`는 Stop 훅으로 게이트·의무 목록을 실행(ADR-005·DCR-006 — main의 ADR-005·006과 번호 중복).
- **보관 설계의 결함**: 의무 목록 상태값은 있으나 대체·폐기 전이를 일으키는 관문(시점·기준·증거)이 없다. 사용자 요구 7이 이 결함을 가리킨다 — [조사 정리 §1.3](../../research/20261009-test-lifecycle/testing_research_digest.md).
- **조사 정리의 설계 초안**(§4): 세 겹(① 작성 기준 ② 수명주기 ③ 기계적 검사). 상태 5종 `유지·대체·병합·격리·폐기`와 진입 트리거. 재정비 관문은 통합(§3.6)과 DCR 반환 시점에만, TASK마다는 등록·격리만. 폐기·병합은 4조건 전부 성립(분류 5종 명시, 증거, 유일 검증 아님, 사용자 승인). 상한: 의무 목록 전량 실행은 `completed`·통합·재개 3시점만, 커버리지·뮤테이션은 인수 조건이 아니라 추세·중복 판정 근거로만. §5에 후속 조사 과제 10건(tessl 원문, RTS 고전, 커버리지 도구, 뮤테이션 비용, 냄새 탐지 도구 등).
- **사이클 2 결과와의 접점**: 합본 work-log 템플릿은 H2 8개로 고정되고 린트 L2가 이를 검사한다. 회귀 의무 목록을 work-log의 새 H2로 두면 템플릿·린트 변경이 필요하다. `## 검증 결과`의 H3로 두거나 별도 파일(보관 설계의 `test-map.md` 방식)로 두는 선택지가 있다. 린트 L3·L5의 분량 상한도 의무 목록 표에는 적용되지 않는다(표 행은 불릿이 아님).
- **저장소 테스트 자산**: `setup/hooks/tests/run-tests.ps1`(PowerShell 자체 러너, 22케이스, pass/fail 출력), `skills/wf-doc/scripts/tests/test_lint_worklog.py`(pytest 33), `docs/presentation/tests/test_make_pptx.py`(단독 실행 가능). 세 자산의 결과는 work-log 검증 표에 건수로만 기록되고 산출물 파일(JUnit XML 등)은 없다.
- **도구 가용성**(2026-10-09): `python`은 `C:\src\git\git_client\.venv`의 3.13.1을 가리키며 pytest 9.1.1·pytest-qt 4.5.0이 있다. `coverage`·`pytest-cov`는 미설치. PowerShell 러너는 커버리지 수단이 없다(Pester 미사용).
- **선행 조사의 측정 스크립트**: `docs/research/20260919-aidlc-research/measure_regression_baseline.py`가 work-log 검증 표의 SHA·명령 기록률을 산출한다(보관 설계 NFR-05의 측정 도구).

### 해석

- 요구 7의 본체는 **수명주기의 전이 관문**이다. 보관 설계의 등록(TASK 완료 시)은 재사용할 수 있고, 빠진 것은 재정비 관문의 시점·기준·증거·승인이다. 조사 정리 §4.2~4.3 초안이 그 골격을 이미 제공한다.
- 요구 8은 두 조각이다. **기록 형식**(검증 1회마다 표준 산출물 + work-log 요약 표: 총계, 성공/실패/미수행, 커버리지 비율, 기준 SHA, 명령)은 지금 설계할 수 있고, **도구·시각화**는 언어별이라 3번 단계 조사 뒤에 정한다. 이 저장소에서 당장 측정 가능한 커버리지는 pytest 대상(린트 스크립트)뿐이며 도구 설치가 필요하다.
- 사이클 2가 만든 린트(L2 H2 고정, L3·L5 분량)는 이 사이클의 기록 형식에 **제약**이다. 의무 목록·결과 요약은 표로 두어 불릿 상한을 피하고, 절 위치는 템플릿 변경을 최소화하는 쪽(기존 H2의 H3 또는 별도 파일)이 유리하다.
- 분량 상한(NFR)은 사이클 2와 같은 방식으로 둬야 한다. 보관 설계는 스킬 148행을 더했고, 그 중 표는 references로 보내는 원칙(DES-05)이 이미 있었다.

### 가정

- 이 저장소의 사용자는 1인이며, 재정비 관문의 "사용자 승인"은 완료 보고 관문에서 일괄 응답으로 처리한다.
- 보관 브랜치의 ADR-004(3튜플 앵커)는 main에 없으므로 재사용하려면 이 사이클에서 새 번호로 다시 발행한다(main 다음 번호 ADR-007).
- 커버리지 수치는 인수 조건에 쓰지 않는다(조사 정리 §4.4의 게이밍 위험).

### 질문 (사용자 결정 후보 — 요구·설계 초안에서 Q-ID로 확정)

- 회귀 의무 목록(테스트 대장)의 위치: work-log `## 검증 결과`의 H3 / 작업 폴더 별도 파일 `test-map.md`(보관 설계) / 저장소 관통 `docs/test-register.md`.
- 보관 설계의 재사용 범위: 3튜플 앵커·분류 열·시점별 실행 집합 표를 그대로 복원할지, 관문만 더할지.
