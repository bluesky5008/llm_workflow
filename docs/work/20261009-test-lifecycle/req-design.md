## 문제와 목적

사용자의 사용 경험(2026-10-09 세션, 요구 7·8 원문 — 세션 기록에서 복구):

> 7) 회귀테스트의 효율적 관리방안이 필요하다. 현재 사용중인 기능은 회귀테스트의 증가방향만 있고, 정리 및 최적화 방안이 없다. 회귀테스트 작성 및 수행이 반복되는 도중 해당 테스트의 재정비 및 전체 테스트 목록 중 불필요 항목의 삭제 기능이 필요하다.
>
> 8) 회귀테스트 포함 단위테스트의 수행 결과를 기존의 전통적 관점의 SDLC에서 기록하는 결과와 비슷한 형태로 기록하고 관리하는 기능이 필요하다. 라인 커버리지, 함수 커버리지, 분기 커버리지 등을 측정하고 결과를 시각화 할 방법이 필요하다.

같은 세션에서 승인된 사이클 편성: 사이클 3 = "8의 기록 형식 + 7". 보관 브랜치의 9월 설계(3튜플 앵커, 테스트 맵, 회귀 의무 목록)를 input으로 재검토하되 재정비 관문을 더해 다시 설계한다. 8의 도구 선정·시각화, RTS 문헌, flaky 관리 기법은 3번 단계(외부 조사)로 이관됐다. 7에 대한 추가 논의에서 사용자는 "테스트 방법론 지침 + 정리 절차 명시"를 제안했고, 외부 근거(TEBench 등)로 찬성하되 분량 상한을 두기로 했다 — [조사 정리 §0·§4.4](../../research/20261009-test-lifecycle/testing_research_digest.md).

### 해석

- 요구 7의 본체는 **수명주기의 전이 관문**이다. 보관 설계의 등록(TASK 완료 시)은 재사용할 수 있고, 빠진 것은 재정비 관문의 시점·기준·증거·승인이다. 조사 정리 §4.2~4.3 초안이 그 골격을 이미 제공한다.
- 요구 8은 두 조각이다. **기록 형식**(검증 1회마다 표준 산출물 + work-log 요약 표: 총계, 성공/실패/미수행, 커버리지 비율, 기준 SHA, 명령)은 지금 설계할 수 있고, **도구·시각화**는 언어별이라 3번 단계 조사 뒤에 정한다. 이 저장소에서 당장 측정 가능한 커버리지는 pytest 대상(린트 스크립트)뿐이며 도구 설치가 필요하다.
- 사이클 2가 만든 린트(L2 H2 고정, L3·L5 분량)는 이 사이클의 기록 형식에 **제약**이다. 의무 목록·결과 요약은 표로 두어 불릿 상한을 피하고, 절 위치는 템플릿 변경을 최소화하는 쪽(기존 H2의 H3 또는 별도 파일)이 유리하다.
- 요구 7의 "전체 테스트 목록"은 작업 하나의 목록이 아니라 **작업을 넘어 누적되는 저장소의 목록**이다. 보관 설계는 의무 목록을 작업별 work-log에 두어 누적과 전이의 기록 위치가 없었고, 사이클 2 이후 완료 work-log는 동결 문서라 전이를 기록할 수 없다. 목록의 정본은 저장소 관통 문서여야 한다(Q-01).
- 분량 상한(NFR)은 사이클 2와 같은 방식으로 둬야 한다. 보관 설계는 스킬 148행을 더했고, 그 중 표는 references로 보내는 원칙(DES-05)이 이미 있었다.

### 가정

- 이 저장소의 사용자는 1인이며, 재정비 관문의 "사용자 승인"은 완료 보고 관문에서 일괄 응답으로 처리한다.
- 보관 브랜치의 ADR-004(3튜플 앵커)는 main에 없으므로 재사용하려면 이 사이클에서 새 번호로 다시 발행한다(main 다음 번호 ADR-007).
- 커버리지 수치는 인수 조건에 쓰지 않는다(조사 정리 §4.4의 게이밍 위험).
- 테스트 대장의 등록 진입 조건은 보관 설계 Q-02의 결정(같은 SHA 2회 통과 — Green 1회 + `completed` 전이 1회)을 재사용한다. 낮은 위험이라 질문으로 올리지 않는다.
- 실행 환경에 git이 있다(기존 전제). 커버리지·산출물 도구는 전제하지 않는다(NFR-04).

| FR-02 | 검증 결과의 정량 기록 | work-log `## 검증 결과`의 결과 요약은 총계(성공·실패·미수행 건수), 기준 SHA와 워킹트리 상태, 묶음별 실행 명령, 커버리지(도구가 내는 라인·분기·함수 비율, 없으면 `N/A — 이유`), 산출물 위치(없으면 `없음`)를 고정 필드로 기록해야 한다. 인수 조건별 결과 표에 `분류` 열을 두어 결과가 `실패`일 때 §3.4의 4분류 중 하나를, 그 외에는 `—`를 기록한다. 증거에는 SHA와 실제 실행한 명령이 있어야 하며 없으면 인용 가능한 기록이 아니다 |
| FR-03 | 산출물 형식 | 필수는 FR-02의 결과 요약 필드뿐이며 언어 무관이다. 산출물은 세 층: **권장** — 러너가 내장 지원하면 결과는 JUnit XML, 커버리지는 Cobertura XML 또는 LCOV. **허용** — 내장 지원이 없으면 러너의 네이티브 기계 판독 형식(JaCoCo XML, Go coverprofile, TRX, NUnit XML, TAP)을 그대로 두고 `산출물` 필드에 형식명을 적는다. 변환 의무는 없다. 산출물은 생성물이므로 커밋하지 않는다. 커버리지 비율은 인수 조건이나 완료 조건으로 쓰지 않고 추세 관찰과 중복(병합) 판정 근거로만 쓴다 — [Q-03](#가정과-미해결-질문) |
| FR-04 | 테스트 대장 | 저장소 관통 문서 `docs/test-register.md`(문서 유형 `test-register`)가 회귀 테스트의 정본 목록이어야 한다. 행 단위는 실행 명령 하나로 도는 테스트 묶음(파일 또는 러너)이며, 개별 테스트가 전이 대상이 되면 그 테스트만 행으로 분리한다. 행마다 ID, 테스트·명령, 보호 스코프(파일·심볼 또는 인수 조건), 크기 라벨, 발행 작업, 상태, 마지막 성공(일시·SHA), 비고를 기록한다. 폐기·병합·대체된 행은 삭제하지 않고 상태·이유·일시를 남긴다 — [ADR-008](./ADR-008-테스트-대장-저장소-관통.md), [Q-01](#가정과-미해결-질문) |
| FR-05 | 상태와 전이 | 대장 행의 상태는 `유지 · 대체 · 병합 · 격리 · 폐기` 5종이다. 진입(`유지`)은 TASK `completed` 전이에서 같은 SHA 2회 통과한 테스트의 등록. `격리`는 같은 SHA에서 결과가 불일치할 때 즉시(계속 실행하되 완료를 차단하지 않으며 수정 후속 작업을 등록). `대체`는 DCR 승인과 같은 변경에서 대체 테스트 ID와 함께. `병합`·`폐기`는 재정비 관문(FR-07)에서만. TASK 진행 중(Green·Refactor)에는 등록·격리 외의 전이와 기존 테스트의 수정·제외·삭제를 금지한다 — [ADR-009](./ADR-009-테스트-재정비-관문.md) |
| FR-06 | 시점별 실행 집합 | Green·Refactor 후·자체 리뷰 후에는 보호 스코프가 변경 파일과 겹치는 대장 행(코드가 바뀐 경우만), TASK `completed` 전이·통합·세션 재개(마지막 성공 SHA ≠ HEAD 또는 워킹트리 dirty)에는 `유지` 행 전량, 통합에는 추가로 전체 스위트 1회를 실행해야 한다. 전량 실행은 이 3시점 외에 두지 않는다 |
| FR-07 | 재정비 관문 | 통합(§3.6)과 DCR 승인 시점에 재정비 관문을 수행한다. (a) 이 작업의 변경이 닿은 보호 스코프의 테스트를 Breaking·Stale·Missing으로 분류해 처리한다(Breaking → 수정, Stale → 대체 또는 폐기 후보, Missing → 추가). (b) 폐기·병합 후보는 4조건 — 분류 5종(중복·동어반복·자명·신호 없음·고아) 중 하나로 명시, 증거(중복은 커버리지 겹침 또는 뮤테이션 동치, 동어반복은 구현을 바꿔도 통과하는 실험, 고아는 보호 스코프가 현재 트리에 없음), 어떤 인수 조건의 유일한 검증이 아님, 사용자 승인 — 이 전부 성립할 때만 전이하고 하나라도 미달이면 `유지`. "한 번도 실패한 적 없음"은 단독 사유가 아니다. (c) 제안과 결과를 work-log `### 테스트 대장 변경`에 표로 기록하고 완료 보고 관문에서 일괄 승인받은 뒤 대장을 갱신한다 — [ADR-009](./ADR-009-테스트-재정비-관문.md), [Q-04](#가정과-미해결-질문) |
| FR-08 | 테스트 작성 기준 | §2.4에 판단 규칙을 둔다: 구현 구조가 아니라 동작을 검증(협력자 전부 mock 금지), 결정성(시계·난수는 테스트가 주입), 테스트 하나에 동작 하나, 단언은 실패할 수 있어야 함(Red 실행이 증거), 크기 라벨 small·medium·large. 냄새 체크리스트(Assertion Roulette, Magic Number, Lazy, Conditional Logic, Empty, Duplicate Assert)는 references에 둔다 |
| FR-09 | 규칙 배치와 트리거 | 의미 규칙(귀속·시점·전이·관문·작성 기준)은 wf-implement 본문 해당 절에 한 문장~한 문단으로, 표(시점별 실행 집합·상태 전이·관문 조건·체크리스트)는 `references/verification-depth.md`로. 본문 §3.4에 "검증 시점·실행 집합·대장 전이는 references/verification-depth.md를 따른다"는 트리거 문장이 있고, 표를 참조하지 않은 생략은 이유를 기록해도 유효하지 않다 |
| FR-10 | 자기 적용 | `docs/test-register.md`를 신설해 현행 자산 3묶음(훅 러너 22, 린트 pytest 33, pptx 테스트)을 `유지`로 등록하고 마지막 성공 SHA를 기록한다. 이 작업의 work-log가 FR-02 형식을 쓰고, 통합에서 FR-07 관문을 1회 수행해 결과(변경 없음 포함)를 기록한다 |
