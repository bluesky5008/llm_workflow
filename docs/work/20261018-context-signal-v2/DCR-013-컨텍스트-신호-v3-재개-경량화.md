## 변경 사유와 증거

- **관찰(사용자, 2026-10-18):** `/clear` 후 재개 프롬프트로 이어가는 운용에서, 큰 구현 작업일수록 임계 훅이 실제 컨텍스트 대비 이르게 발화한다는 느낌이 잦다.
- **원인(분석):** transcript 바이트는 컨텍스트 토큰의 상수배가 아니다. `Edit`/`Write`의 `toolUseResult.originalFile`(수정 전 파일 전체), `Read` 내용의 이중 기록, 이전 턴 thinking 블록(컨텍스트에서 제거됨), 블록별 메시지 봉투가 컨텍스트에 없는 바이트를 만든다. 편집 위주 작업에서 비율이 커져 같은 1500KB가 더 낮은 사용률을 뜻한다. ADR-001 보정(11~15 bytes/token)은 설계·토론 세션 1건의 실측이었다.
- **비용(분석):** 인계는 호출당이 아니라 건당 고정비(인계 절 작성 + 새 세션 재읽기 30~40K 토큰 + 재탐색, 수 분)를 낸다. 캐시 덕에 큰 컨텍스트를 끌고 가는 호출당 비용은 작으므로, 실제 사용률이 낮을 때 울리는 인계는 품질 이득 없이 고정비만 반복한다. 따라서 **신호의 정확도**와 **인계 1건의 비용** 둘 다 줄여야 한다.
- **능력(2026-10-18 공식 훅 문서 재확인):** 훅 입력에 컨텍스트 사용량 필드는 여전히 없다(`SessionStart(resume|fork)`의 `context_tokens`만 있고 `PostToolUse`에는 없음). transcript의 assistant 줄 `message.usage`는 실제 프롬프트 크기를 담는다.
- **프로토타입 증거:** 계약 테스트 T22~T28을 먼저 작성해 Red(6건 실패)를 확인한 뒤 구현해 Green(27/29, 나머지 2건은 Linux 검증 환경의 경로 구분자 차이로 설치 테스트 T19·T21이 실패 — Windows에서는 기존과 동일 통과 예상). 꼬리 1MB 파싱 실측 4~74ms.

## 기존 기준선과 설계

- [FR-02](../../requirements.md#기능-요구사항): 컨텍스트 사용량이 설정 가능한 임계값을 넘으면 인계 지시를 주입. [AC-02](../../requirements.md#인수-조건): 임계값은 환경 변수로 변경 가능.
- [DES-02](../../design.md#컴포넌트와-책임): "transcript 크기의 성장량(현재 크기 − 기준점)이 임계값을 넘으면" 주입. 설정값 `CLAUDE_WF_THRESHOLD_KB`(1500)·`CLAUDE_WF_REWARN_KB`(300). 상태 파일 `{baselineBytes, lastWarnedBytes, updatedAt}`.
- 설계 제약 "문서화된 능력만 사용": 훅 이벤트·필드·출력 계약은 공식 문서에 있는 것만.
- 요구사항 가정: "transcript 파일 크기의 성장량은 컨텍스트 사용량의 단조 증가 프록시로 임계값 판정에 충분하다."
- 재개 절차: [wf-implement §3.1](../../../skills/wf-implement/SKILL.md#31-현재-상태-재확인)은 "계획의 진행 상태와 미완료 항목부터 확인한다"고만 하고 읽기 범위를 정하지 않는다. 실제 재개는 work-log·plan·req-design 전체를 읽는 경향이 있다.

## 제안 설계

1. **DES-02 v3 — 2단 신호.** 1차: transcript 꼬리의 마지막 메인 에이전트 assistant `usage`에서 `input + cache_creation + cache_read` 토큰을 읽어 절대값 임계(`CLAUDE_WF_THRESHOLD_TOKENS` 130000, 재경고 `CLAUDE_WF_REWARN_TOKENS` 20000)로 판정. 2차(폴백): 파싱 불가 시 기존 바이트 성장 판정. 주입 메시지 끝에 `(context_tokens=… threshold=… signal=usage|bytes)` 한 줄. 상세는 [ADR-012 결정](./ADR-012-컨텍스트-신호-usage-파싱.md#결정).
2. **세션 재개 절차 — 최소 읽기 집합.** wf-implement `references/session-resume.md` 신설: 인계 절만 → 해당 TASK의 plan 항목만 → 기준선은 항목 앵커만, 전체 읽기 금지, 재확인은 git 명령으로, 대장 유지 행은 SHA 같으면 인용. wf-doc 인계 블록에 세션 인계 `다음 행동`의 **자기완결 형식**(TASK·파일·적용 항목 ID·마지막 검증)을 추가한다.
3. **훅 메시지.** `resume.md`·`post-compact.md`가 위 재개 절차를 가리키도록 문구 갱신(새 규범을 만들지 않고 스킬 절차를 가리키는 포인터 — NFR-02 유지).

## 영향 범위

- 요구사항과 인수 조건: FR-02의 의미("컨텍스트 사용량 초과 시 주입")는 그대로이고 측정 방법만 바뀐다. AC-02 단위 명확화. FR-01·04·05, AC-01·03~06 무영향.
- 컴포넌트 책임: DES-01·03·04 무변경(기준점 기록은 폴백용으로 유지). 설치 로직·등록 계약 무변경.
- 인터페이스와 데이터: 훅 입출력 계약 무변경(주입 텍스트에 ASCII 1줄 추가). 상태 파일 필드 1개 추가 — 구 파일은 필드 부재를 `null`로 처리.
- 정상·실패·복구: 파싱 실패 → 폴백, 파일 부재 → 무주입, 예외 → exit 0. fail-open 유지.
- 성능(NFR-03): 꼬리 1MB 1회 읽기 + 정규식 — 실측 수십 ms. powershell.exe 기동 비용(기존)에 묻힌다.
- 하네스 중립(NFR-02): 훅은 여전히 스킬 절차를 가리키는 포인터만 주입한다. 스킬 변경은 이 DCR의 결정으로 수행하는 것이지 훅이 규범을 만드는 것이 아니다.
- 진행 중인 구현: 없음(C층 구현은 2026-08-09 완료). 보류할 구현이 없으므로 design-change §3.A는 "해당 없음"으로 확인.
- 스킬 린트: wf-implement 본문 2846/2850어절(95% 경고 기존과 동일), K4 링크는 ADR-012 생성으로 해소. 새 references는 §3.1·세션 인계에서 링크(K5 충족).
- 운용: 기본값 130000은 200K 창 기준. 1M 창을 주로 쓰면 `CLAUDE_WF_THRESHOLD_TOKENS`를 올린다.

- transcript 형식 변경 → 폴백으로 내려가고 `signal=bytes`가 메시지에 드러난다. 계약 테스트가 가정을 고정하지만 실제 파일로 검증하지는 않는다(픽스처는 필요한 필드만 모사).
- 마지막 usage는 직전 호출 기준이라 수천 토큰 과소 추정 → 기본값 65%에 여유 포함.
- 재개 절차는 모델이 따를 때만 효과가 있다. 가드 문구(주의 5항)와 훅 메시지로 강제하되, 인계 절 품질이 낮으면 확장 조건을 타서 비용이 다시 오른다.
- 번호: [결정 등록부](../../decisions.md) 기준 다음 번호 ADR-012·DCR-013.
