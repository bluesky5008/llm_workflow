## 요약

- 목적: 설계의 컴포넌트 관계와 기존 자산 출처를 어떤 형식으로 적고 무엇이 어떻게 검사하는지 정한다.
- 현재 결론 또는 상태: A 승인(2026-10-27) — DES 3열 표 아래 별도 5열 의존 표(`의존`·`피의존` 양방향, `소유 데이터`, `출처`), GAP은 기존 추적표, 검사는 신규 `lint_design.py`(표가 있는 문서만).
- 다음 행동: wf-implement에서 구현.

## 배경

wf-design §4.3은 컴포넌트 간 의존 관계를 산문으로만 요구하고, 설계 문서를 읽는 스크립트가 없다. 아키텍처 복원에서 관계 재구성이 가장 약하고(R2ABench 2604.06683v3 관계 F1 최고 0.1758 `[재확인 10-26]`), AI-DLC `components.md`는 유일 이름·대칭·단일 소유자·비순환을 적격성 규칙으로 둔다 `[노트]`. 기존 설계 문서 14건은 동결돼 있다(12건 3열 표, 2건 불릿). 이 저장소 C층 설계는 공용 모듈 `wf-common.ps1`을 DES로 적지 않았다(REQ-DESIGN-component-deps 조사).

## 영향을 받는 요구사항과 제약

- 3열 표 규칙(templates 노트), 동결 문서 불변.
- wf-design 본문 순증 0, wf-doc·wf-implement 본문 무변경.
- 린트는 표준 라이브러리(기존 린트 2종과 같음).

## 고려한 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 별도 5열 의존 표, `의존`·`피의존` 양방향 + 대칭 검사, GAP은 추적표, 신규 `lint_design.py` | 3열 규칙·동결 문서 유지, 역방향 영향을 작성자가 직접 따짐, 추적 정보 한 곳 | 같은 관계 두 번 기입, 추적표 표기 파서 필요 |
| B | 05 원안 — DES 표에 `depends_on`·`dependents`·`소유 데이터`·`충족 요구사항` 열 | 표 하나 | 3열 규칙 위반, 긴 `내용` 칸으로 행이 넓어짐, 추적표와 중복 |
| C | A에서 `의존`만 적고 역방향은 린트가 계산 | 기입 한 번, 비대칭 불가 | 작성자가 역방향 영향을 따질 계기가 없음(사용자가 Q-02에서 기각) |
| D | `lint_worklog.py`에 설계 검사 추가 | 파일 하나 | 대상(작업 기록)·실행 시점(TASK 완료·인계)이 다름 |

## 결정

A를 채택한다.

1. **형식.** 설계의 `컴포넌트와 책임`(합본은 `설계`) 절 DES 표 아래 `| ID | 의존 | 피의존 | 소유 데이터 | 출처 |`. `의존`은 직접 사용(호출·읽기·등록, 다른 요소의 파일·함수를 이름으로 지정)만, 외부 계약은 `데이터와 인터페이스` 절. `소유 데이터`는 형식·수명을 정하는 요소 하나. `출처`(필수)는 그 문서의 이번 설계 기준 `재사용(<위치>)`·`확장(<위치>)`·`신규 — <이유>` — 손대지 않은 기존 요소는 `재사용`. `—` 소유 데이터는 중복 검사에서 제외. 요소가 하나면 `N/A — <이유> · 출처: …`.
2. **GAP.** 같은 문서의 추적표(범위·나열·링크 표기를 펼침)로 판정한다. 의존 표에 요구사항 열을 두지 않는다.
3. **검사.** 신규 `skills/wf-doc/scripts/lint_design.py`가 `lint_worklog` 파서를 재사용해 의존 표가 있는 문서만 검사한다. 오류 D1~D9(정의·대칭·순환·소유·출처·GAP·고아), 경고 D10(추적표에 없는 DES). exit 0/1, 루트·경로 오류 2. 추적표가 없으면 D8 오류. §4.5 자체 검토에서 실행한다. 훅 연결은 하지 않는다.

## 이유

- 별도 표는 기존 형식과 동결 문서를 그대로 두고, 표의 존재가 곧 검사 대상 표지라 소급 오류가 생기지 않는다.
- 양방향 기입은 사용자 결정(Q-02)이며, 비대칭은 D4가 쌍을 지목하므로 동기화 비용을 린트가 줄인다.
- 추적표는 이미 모든 설계 문서에 있고 요구사항→설계의 정본이다.
- 대상과 실행 시점이 다른 검사는 다른 스크립트로 둔다(lint_skill 선례 — 파서만 공유).

## 결과와 감수할 단점

- 관계를 두 번 적는다. 2~3 작업 뒤 부담이 크면 C로 바꾸는 DCR을 검토한다.
- 요구사항이 다른 파일에 있는 문서(`docs/design.md`)는 "정의된 FR이 추적표에 없음"을 보지 못한다.
- 처방 효과(관계 오류 감소)는 이 저장소에서 측정할 수 없다 — 코드 저장소 후속.

## 후속 작업

- 코드 저장소 첫 정식 작업에서 의존 표 작성 비용, D 코드별 보고 수, 침식 점검 결과 기록.
- 교차 파일 GAP(요구사항 문서 링크 추적), 외부 의존 표기 — 필요 시.
