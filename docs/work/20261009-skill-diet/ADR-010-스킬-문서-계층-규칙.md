## 요약

- 결정: 스킬 문서를 **본문(SKILL.md) · references/ · scripts/** 세 층으로 나누고, 어느 층에 둘지는 판정 규칙 R1~R5로 정한다. 본문에서 references로 내린 내용에는 조건+명령형 **강제 트리거 문장**을 남긴다. 본문 어절 상한을 스킬별로 두고 `skills/wf-doc/scripts/lint_skill.py`가 커밋 전에 오류로 집행한다. 절차 세부·표기 세칙·템플릿·체크리스트는 이후 references에만 추가한다.
- 핵심 이유: 실증 근거의 결함 축은 길이(LSB)가 아니라 위임되지 않은 세부(UD)이고, 한번 들어온 냄새는 이후 개발에서 거의 제거되지 않으므로(종단 분석) 도입 시점 차단이 유일하게 검증된 개입이다. 콜드 계층은 저절로 읽히지 않으므로 트리거 문장이 없는 이관은 삭제와 같다.
- 주요 단점: 한 절차를 수행하는 데 읽어야 할 파일이 늘고, 트리거 문장 자체가 본문 어절을 쓴다. references 참조 준수율은 이 저장소에서 측정할 수 없어 코드 저장소 사이클에서 관측해야 한다.

## 배경

스킬 4종은 같은 세션에 동시에 로드된다(정식 경로 1세션에 통상 3개). 2026-10-09 기준 본문 합 10,446어절이며 wf-implement+wf-doc은 사이클 3이 둔 상한(6,348)에 닿아 있다. 9월 조사는 본문에 절차 세부·표·템플릿·체크리스트가 남아 있는 것(UD 46%)을 지목했고, Codified Context 관찰 연구는 헌법(항상 로드)과 Tier 3(필요 시 참조)의 분리를 **헌법이 참조를 명령**함으로써 유지했다(283세션 중 218세션 접근). 이 저장소에는 사이클 3이 둔 선례가 하나 있다 — `references/verification-depth.md`와 본문의 "표를 참조하지 않은 생략은 이유를 적어도 유효하지 않다".

저장소에는 B층 스크립트 선례(ADR-006, `lint_worklog.py`)가 있고 그 ADR의 후속 작업에 "스킬 본문 린트 — 같은 `scripts/` 관례 재사용"이 적혀 있다. `skills/wf-*`는 폴더별 junction으로 설치되므로 스킬 폴더 밖의 스크립트는 설치되지 않는다.

|---|---|---|---|
| A. 현상 유지 — 본문에 전부 두고 어절 상한만 사이클마다 "작업 전 값 이하"로 관리 | 읽을 파일이 하나. 사이클 3 방식 그대로 | 상한에 닿아 묶음 A·C의 문장이 들어갈 자리가 없다. UD·BG·MUS 미해소. 상쇄를 위해 매 사이클 중복 문장을 깎아야 하며 R1 문장이 깎일 위험 | 없음 |
| B. 길이 상한만 — 스킬별 어절 상한을 두고 초과분을 각 작업이 알아서 줄임 | 규칙이 단순 | 무엇을 내릴지의 기준이 없어 작업마다 다르게 판단. 트리거 없는 이관(=삭제) 방지 장치 없음. 종단 분석의 "재도입" 감시 없음 | 낮음 |

## 결정

대안 C를 채택한다.

**세 층의 정의**

| 층 | 두는 것 | 읽히는 시점 |
|---|---|---|
| 본문 `SKILL.md` | 항상 따라야 하는 판단 규칙·소유권·금지·가드, 다른 문서로 라우팅하는 조건, 전용 경고 절, 트리거 문장 | 스킬 로드 시 항상 |
| `references/*.md` | 특정 절차를 실행할 때만 필요한 세부 — 템플릿·표기 세칙·긴 체크리스트·표·예시·경계 소유권 표 | 본문의 트리거 문장이 지시할 때 |
| `scripts/*.py` | 결정 없이 기계적으로 재현 가능한 작업 — 린트·렌더·검사 | 본문이 실행을 지시할 때 |

**판정 규칙(묶음 A §3.1을 저장소 규칙으로 확정)**

| # | 질문 | 배치 |
|---|---|---|
| R1 | 항상 따라야 하는 판단 규칙·소유권·금지·가드인가? | 본문 유지 |
| R2 | 특정 절차 실행 시에만 필요한 세부(템플릿·표기 세칙·긴 체크리스트·표·예시)인가? | references + 본문에 트리거 문장 |
| R3 | 다른 문서로 라우팅하는 표·조건인가? 본문이 이미 온디맨드 참조를 지시하는가? | 본문에는 라우팅 문장만, 대상은 references |
| R4 | 결정 없이 기계적으로 재현 가능한가(렌더·링크 검증·롤업·측정)? | scripts + 본문에 실행 지시 |
| R5 | 치명적 함정·경고인가? | 본문의 `## 주의 — 자주 틀리는 것` 절 |

**이관 금지 목록(R1 확정):** 경계 적용 규칙(번호 목록), 가드 문구 전부, wf-implement §2.3 자율 진행·비가역 작업 목록, §4 경미/중대 분기, §5 완료 조건, wf-design 경량 경로 조건, wf-tree 단일 소스 원칙·필수 게이트, wf-doc §2.1 유형표·§2.4 상태값 표(공유 어휘).

**트리거 문장 의무:** 이관 1건마다 본문에 조건 + 명령 + 불이행 효과("…할 때는 X를 읽는다. 읽지 않은 …는 수행하지 않은 것으로 간주한다")를 1문장 남긴다. 선례 어법은 wf-implement §3.4.

**어절 상한과 집행:** 본문 어절(frontmatter 제외, 공백 분리) 상한은 `lint_skill.py` 상단 상수다 — 초깃값은 [REQ-DESIGN-skill-diet Q-01](./req-design.md#가정과-미해결-질문)의 승인값. 초과는 오류(exit 1), 95% 초과는 경고. 린트는 `skills/*/SKILL.md`·`references/*.md`를 바꾸는 커밋 전에 실행한다. 상한 변경은 wf-design 경량 경로로 처리한다(ADR-006과 같음).

**추가 규칙:** 이 결정 이후 절차 세부·표기 세칙·템플릿·체크리스트는 references에만 추가한다. 본문에 추가할 수 있는 것은 R1·R3·R5와 트리거 문장뿐이다. 이 규칙은 스킬 사용자가 아니라 스킬 유지자의 규칙이므로 스킬 본문이 아니라 이 ADR과 README 실행 기준에 둔다.

## 이유

- 판정 축이 UD이므로 "길이"가 아니라 "위임 가능성"으로 판정해야 한다(묶음 A §0-1). 짧은 wf-tree도 UD에 해당했고, 긴 경계 규칙 목록은 UD가 아니다.
- 콜드 계층은 명령 없이는 읽히지 않는다(묶음 A §1.3·§1.5-1). 사이클 3의 트리거 선례가 같은 저장소 안에서 동작 중이다.
- 종단 분석(142스킬·1,199커밋)은 냄새가 거의 제거되지 않음을 보였다. 유일한 개입 지점이 도입 시점 차단이므로 린트는 경고가 아니라 오류여야 한다.
- 린트 위치·언어는 ADR-006이 이미 결정했고 junction 구조가 스킬 폴더 밖을 배제한다.

## 결과와 감수할 단점

- 정식 경로 1세션에서 읽는 파일이 본문 3개 + references 2~4개로 는다. 대신 항상 로드되는 본문 합이 약 17% 준다(10,446 → ≤ 8,700).
- 트리거 문장이 지켜지는지는 이 저장소(산문 작업)에서 관측할 수 없다. 코드 저장소 사이클에서 참조 준수율(Read 호출)을 재고, 절반 미만이면 해당 references를 본문으로 되돌리고 트리거를 강화하는 쪽부터 시도한다(묶음 A §6 롤백 기준).
- 린트 상한은 이 사이클의 실측값이라 묶음 A·C가 본문에 문장을 더하면 상한 조정(경량 경로)이 뒤따른다. 상한은 "성장 감시"이지 절대값이 아니다.
- Python 부재 환경에서는 린트를 실행할 수 없다. 이때는 수동 검토로 대체하고 미실행을 기록한다(ADR-006 DES-03과 동일).
