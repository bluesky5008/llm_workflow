## 요약

- 목적: 승인 전 제품 코드 편집을 확인하는 게이트가 무엇을 근거로, 어디서, 어떤 출력으로 판정할지 정한다.

- 다음 행동: 없음 — 적용은 [WORK-20261026-approval-gate](./work-log.md).

## 배경

wf-design §8은 "승인 이외의 응답에서는 구현을 시작하지 않는다"를 규칙으로만 둔다. 프롬프트 속 규칙의 준수는 낮고(계획 준수 약 22~45%, 2609.38108 `[노트]`), 판단 여지가 있는 조건은 우회된다(2607.01456 `[노트]`). 테스트 쪽은 사이클 1(ADR-014)이 같은 문제를 편집 시 `ask` + 종료 시 판정으로 풀었다.

## 영향을 받는 요구사항과 제약

- 승인의 정본은 문서다(wf-design §8 승인 기록) — 대화나 status.md가 아니다.
- 작업 유형이 여럿이다: req-design 작업, DCR 작업(req-design 없음), 경량 경로 기록, 기록 없는 경량 작업.
- C층 NFR-01 fail-open과 그 예외(가드만 fail-to-ask), NFR-03 성능, 하네스 중립(B층 판정).
- `ask`가 사람에게 닿지 않는 모드는 아직 확인되지 않았다(`auto` 도달 관찰, `bypassPermissions` 미관찰).

## 고려한 대안

|---|---|---|---|

| B | A와 같은 판정을 PS로 재구현(`wf-common.ps1`), Python은 다른 하네스용으로 따로 | 기동 비용 없음 | 판독 2벌 — RISK-07(대장 판독 불일치)과 같은 위험을 하나 더 만듦 |

| E | A + 권한 자동 승인 모드에서 `deny` | 미도달 모드 대비 | 미도달이 확인되지 않은 모드에서 정당한 편집을 막음(ADR-014 결정 1과 충돌) |

## 결정

A를 채택한다.

1. **판정 원천.** 열린 작업 기록(닫힘 계열 5종 제외)의 머리말 `기준선:` 값. `N/A — 경량 경로`로 시작하면 경량 기계 조건(파일 수 ≤ 5, 게이트 설정·의존성 선언·`.wf-gate.json` 아님, 새 파일은 테스트)을, 아니면 값 안의 링크 문서를 모두 따라가 상태 ∈ {`approved`, `completed`}와 `## 승인 기록`의 `응답` + 따옴표 인용을 본다. 링크가 없으면 미승인이다.
2. **제품 코드.** 기본은 저장소 루트 아래 `docs/` 밖 전부. 루트의 선택 선언 `.wf-gate.json`(`product`·`exclude` glob, `exclude` 우선)이 덮어쓴다(Q-01 (B)). 선언은 하네스 중립 데이터라 B층이 읽고, `docs/` 밖에 두어 그 편집 자체가 게이트 대상이 되게 한다 — 승인 없이 예외를 늘리는 우회를 막는다.
3. **배치.** 판정은 `skills/wf-doc/scripts/approval_gate.py`(표준 라이브러리 + git, exit 0/1/2), 어댑터는 `setup/hooks/wf-approval-gate.ps1`. 어댑터는 `docs/work/` 부재·`docs/` 경로를 먼저 걸러 Python을 부르지 않는다.
4. **출력과 실패.** exit 1 → `ask`(포인터 메시지 + 판정 사유), exit 2·타임아웃·Python 부재 → `ask`(fail-to-ask), 바깥 예외 → 무출력. `deny`는 두지 않는다 — 미도달이 확인된 모드가 생기면 그 모드만 `deny`를 별도 DCR로 추가한다(대안 E의 조건부 채택).

## 이유

- `기준선` 필드는 모든 작업 기록에 이미 있고 wf-doc이 형식을 소유한다. 새 표지·새 파일 없이 작업 유형 전부를 다룬다.
- 응답 인용 요구는 에이전트가 `approved`를 직접 적는 구멍을 "조용한 자기 승인"에서 "기록된 승인"으로 바꾼다. 완료 작업의 승인 기록 두 형식이 이미 만족해 소급 수정이 없다.
- 판독 1벌이 판독 2벌보다 싸다. 기동 비용은 `docs/` 선필터와 NFR-02 측정으로 관리하고, 초과하면 B로 바꾼다.

## 결과와 감수할 단점

- 자기 승인은 완전히 막지 못한다(상태와 인용을 함께 쓰면 통과). 사후 감사로만 드러난다.
- 기록 없이 정식 경로 대상 작업을 하면 게이트가 발화하지 않는다 — 규칙(wf-design §1)에 의존.
- 열린 작업이 둘 이상이면 승인된 작업의 편집도 확인을 받을 수 있다.
- 제품 경로 편집마다 Python 기동 비용.

## 후속 작업

- `bypassPermissions`에서 `ask` 도달 관찰(사용자 수행) — 미도달이면 그 모드만 `deny` DCR.
- 경량 기계 조건 상한(5)의 코드 저장소 실측 조정.
- 셸 편집 종료 시 그물(Q-D6 (a)) — 2주 운용 후 판단.
