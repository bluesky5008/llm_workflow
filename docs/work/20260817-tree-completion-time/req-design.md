## 문제와 목적

ASCII 계획 트리는 완료 항목을 `[✓]`로 표시하지만 **언제** 완료됐는지는 트리에서 알 수 없다. 완료 날짜는 work-log 수행 기록(`### YYYY-MM-DD — TASK-NN`)과 git 이력에 흩어져 있어, 트리를 보며 진행 속도·완료 순서를 파악하려면 다른 문서를 뒤져야 한다. 사용자 요청(2026-08-17): 체크표시가 추가된 라인의 우측 끝에 완료 시점을 표시한다.

조사에서 확인한 구조적 제약: 트리는 [wf-tree 단일 소스 원칙](../../../skills/wf-tree/SKILL.md#단일-소스-원칙)에 따라 계획 문서의 항목 목록에서 매번 재생성된다. 완료 시점을 트리에만 적으면 재생성 시 유실되므로, **원천 항목 목록에 완료 필드가 먼저 존재해야 한다.** 현행 [wf-doc plan 템플릿](../../../skills/wf-doc/references/templates.md#구현-계획-plan)의 TASK 필드와 [status 템플릿](../../../skills/wf-doc/references/templates.md#포트폴리오-status)의 작업 목록 표에는 완료 시점 필드가 없다.

## 범위

### 포함

- `skills/wf-doc/references/templates.md` — plan TASK 필드와 status 작업 목록 표에 완료 시점 필드·열 추가
- `skills/wf-implement/SKILL.md` — §3.3 진행 상태 갱신 규정에 `completed` 전이 시 완료 시점 기입 추가
- `skills/wf-tree/SKILL.md` — §7 렌더링에 ASCII 완료 라인 우측 끝 표기 규칙 신설, §2·§7 예시 트리에 반영
- 이 저장소 `docs/plan.md`의 자기 적용(작업 목록 완료 필드 기입 + 트리 재생성) — 소급 범위는 [Q-01](#가정과-미해결-질문)

### 제외

- Mermaid 노드 라벨의 완료 시점 표기 — 요청이 ASCII 라인 우측 끝이며, mermaid는 `done` 색으로 완료를 이미 구분한다. 필요가 확인되면 후속 작업
- 완료된 work-log의 동결 스냅숏(`<!-- snapshot -->`) 소급 수정 — 스냅숏은 동결 기록이며 재생성·수정 대상이 아니다
- `in-progress`·`blocked` 등 완료 이외 상태의 시점 표기 — 시작·차단 시점은 work-log 수행 기록이 이미 담당

## 기능 요구사항

| ID | 항목 | 내용 |
|---|---|---|
| FR-01 | 완료 라인 표기 | ASCII 트리에서 완료로 렌더되는 라인(`[✓]` action item, 완료 작업 노드, 접힌 완료 서브트리 롤업 라인)의 우측 끝에 완료 시점을 표기해야 한다 |
| FR-02 | 데이터 원천 | 완료 시점은 트리의 원천인 항목 목록의 완료 필드에서 파생해야 한다. 트리에만 존재하는 정보를 만들지 않는다(단일 소스 원칙 유지) |
| FR-03 | 기입 시점 | 항목 상태를 `completed`로 바꾸는 같은 변경에서 완료 필드를 기입해야 한다 |
| FR-04 | 결손 허용 | 완료 필드가 없는 완료 항목(규칙 신설 전 항목)은 시점 표기만 생략하고 렌더링은 정상 진행되어야 한다 |
| FR-05 | 템플릿 반영 | wf-doc plan 템플릿의 TASK 필드와 status 템플릿의 작업 목록 표에 완료 시점 필드·열이 추가되어야 한다 |
| FR-06 | 자기 적용 | 이 저장소 `docs/plan.md`에 규칙을 적용해 완료 항목의 완료 필드를 기입하고 트리를 재생성해야 한다 — 소급 범위는 Q-01 확정에 따름 |

## 설계

| ID | 항목 | 내용 |
|---|---|---|
| DES-01 | 데이터 모델 | plan 템플릿 TASK 필드에 `- 완료: <시점>`을 `- 상태:` 바로 다음 위치에 추가 — 상태가 `completed`일 때만 두는 조건부 필드. status 작업 목록 표는 `\| 작업 ID \| 제목 \| 상태 \| 완료 \| 의존 \|`로 `완료` 열 추가(미완료 작업은 공란). 새 상태값을 발명하지 않는다 |
| DES-02 | 표기 형식 | 완료 시점은 날짜+시각 `YYYY-MM-DD HH:MM`(로컬 시각) — 승인 관문에서 확정(Q-02). 같은 날 다수 완료의 순서·속도가 구분된다. 문서 필드와 트리 표기는 같은 값을 쓴다. 날짜만 안은 기각: 세션 기반 작업 패턴에서 하루에 여러 TASK가 완료되어 날짜만으로는 정보 가치가 낮다 |
| DES-03 | 렌더링 규칙 | wf-tree §7에 신설: 완료 라인은 우측 끝에 완료 시점을 두고, 기존 우측 주석(작업 노드의 `completed (n/m)` 롤업, `depends:`)이 있으면 그 뒤에 배치한다. 좌측 내용과는 점선 리더 또는 공백으로 구분하고 같은 형제 블록에서 열을 맞춘다. 접힌 완료 서브트리·완료 작업 노드의 롤업 시점은 자식 완료 시점의 최댓값을 쓰는 표시 전용 파생값이며, 자식 중 하나라도 완료 필드가 없으면 롤업 시점 표기를 생략한다(FR-04와 동일 원리) |
| DES-04 | 규칙 배치 | 기입 규칙은 wf-implement §3.3의 진행 상태 갱신 문장에 한 문장으로 추가(전이·기입·트리 재생성이 같은 변경). 필드 표기는 wf-doc 템플릿 노트로 추가. 렌더링·롤업·결손 규칙은 wf-tree §7. 각 스킬의 소유권 경계(NFR-01)를 유지하고 경계표는 변경하지 않는다 |
| DES-05 | 소급 기입 | 소급 포함 — 승인 관문에서 확정(Q-01). `docs/plan.md`의 완료 항목(축약된 과거 사이클 포함)에 완료 시점을 기입한다. 시점은 각 사이클 종결 커밋의 커밋 시각으로 근사 복원한다. 완료 상태 보존 원칙에 따라 필드 추가는 기록 보완이며 완료 판정을 바꾸지 않는다 |

### 표기 미리보기 (DES-02·03, 날짜+시각 안 기준)

```text
[✓] [작업] 20260817-m0-skeleton — M0 뼈대 ........ completed (9/9) — 2026-08-16 18:40

[▶] [작업] 20260817-m1-battle — M1 전투 프로토타입 ... in-progress (5/11)
    ├─ [✓] TASK-10 구현: 결정론적 RNG ............................. 2026-08-17 10:12
    ├─ [✓] TASK-13 구현: 이동 범위 계산      depends: TASK-12 ..... 2026-08-17 13:05
    ├─ [ ] TASK-15 구현: 커맨드 적용         depends: TASK-13, TASK-14
    └─ [ ] TASK-20 통합: 자체 리뷰·검증·통합  depends: TASK-19
```
