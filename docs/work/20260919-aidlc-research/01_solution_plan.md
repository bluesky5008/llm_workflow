### 2.1 설계 — 3튜플 앵커와 검증 계층

**단일 원칙 (AI-02).** 모든 검증 결과는 **(테스트 집합, 커밋 SHA, 실행 명령)** 3튜플에 귀속된다.

- 3튜플이 같고 워킹트리가 clean이면 **재실행하지 않고 기록을 인용**한다. → A(중복) 해소
- 셋 중 하나라도 다르면 **별개의 검증**이며, 이전 결과와 비교해 "회귀"를 판정하되 이전 결과를 현재 결과로 쓰지 않는다. → C·D·E·F(부정합) 해소
- 이 규칙은 wf-implement §3.4에 두고, wf-doc verification 템플릿의 `증거` 열에 SHA·명령을 필수로 한다.

**검증 계층 표 (AI-05).** 시점별로 실행 집합을 고정한다. 이것이 S3 검증 깊이 표의 "회귀" 행을 세분화한 것이다.

| 시점 | 실행 집합 | 조건 | 집합 크기 |
|---|---|---|---|
| TDD Red | 새 테스트 1개 | 항상 | 1 |
| TDD Green | 새 테스트 + **테스트 맵**의 관련 테스트 | 항상 | 맵 |
| Refactor 후 | 테스트 맵의 관련 테스트 | **코드가 바뀐 경우만** (3튜플) | 맵 |
| §3.5 자체 리뷰 후 | 리뷰로 수정한 파일의 맵 테스트 | 수정이 있을 때만 | ≤맵 |
| **TASK `completed` 전이** | **회귀 의무 목록** 전량 | 항상. 결과에 SHA 기록, 이 TASK의 sentinel을 목록에 추가 | 의무 |
| §3.6 통합 | **전체 스위트 1회** + 의무 목록 | 사이클당 1회 | 전체 |
| §3.1 세션 재개 | 회귀 의무 목록 | HEAD ≠ 마지막 성공 SHA일 때만 | 의무 |
| Stop 훅 (AI-07) | `quality-gates.md` 게이트 | 미완료 작업이 있을 때 | 게이트 |

**증가율 변화.** 현행은 TASK당 ~7회 × 전체 스위트 → n개 TASK에서 O(n × 스위트). 계층화 후 TASK당 (1 + 맵 + 맵×조건 + 의무) 이고 전체 스위트는 사이클당 1회 → **O(n × 맵 + 스위트)**. 의무 목록은 TASK당 1–3개 sentinel(§2.4 "깨지면 실패하는 가장 작은 검증 하나")이라 n에 비례하되 상수가 작다.

**S2 초안 정정.** `s1-s3_papers_deep_dive.md` §1.5는 의무 목록 실행 시점을 "Green 직후·Refactor 후·completed·통합·재개" 5곳으로 잡았다. 이 중 **Green·Refactor의 의무 목록 실행을 테스트 맵 실행으로 대체**한다 — 그대로 두면 시간 증가의 새 원인이 된다. 의무 목록은 completed·통합·재개 3곳.

**부정합 대응 매핑.**

| 원인 | 대응 | AI |
|---|---|---|
| C 앵커 없음 | 검증 표 `증거`에 SHA·명령 필수, 의무 목록 행에 `마지막 성공(일시·커밋)` | AI-02, AI-04 |
| D 집합 비결정 | 테스트 맵이 집합을 고정. 맵 밖 실패는 맵 누락으로 기록 | AI-03 |
