## 문제와 목적

A층(상시 재개 가능 불변식, 표준 재개 프롬프트, 진입 규칙 — 커밋 `81f1103`)으로 세션은 언제 끊겨도 문서만으로 재개 가능해졌다. 그러나 Claude Code에서 다음 세 지점은 여전히 사람 또는 모델의 자발성에 의존한다.

1. **절단 신호:** 컨텍스트가 임계값을 넘었는지 사용자가 판단해야 한다. 모델은 자기 컨텍스트 사용량을 신뢰성 있게 알지 못한다.
2. **컴팩션 안전망:** 자동 컴팩션(손실 요약)이 작업 기록 갱신 전에 발생하면 대화에만 있던 정보가 유실될 수 있다.
3. **재개 진입:** 진입 규칙(CLAUDE.md)은 모델의 이행에 의존한다. 세션 시작 시점에 기계적으로 재개 컨텍스트를 주입하는 것이 더 강하다.

C층은 Claude Code 훅으로 이 세 지점을 기계화한다. 스킬 본문(skills/)은 하네스 중립 원칙에 따라 변경하지 않는다.

## 대상과 시나리오

- **대상:** 이 워크플로우를 설치한 사용자의 Claude Code 세션. 사용자 전역(`~/.claude`)에 설치되므로 모든 저장소에서 발화하되, 워크플로우를 사용하지 않는 저장소에서는 무동작이어야 한다.
- **시나리오 1 (재개):** 사용자가 `/clear` 후 아무 첫 메시지를 보내면, 세션 시작 시 주입된 재개 컨텍스트 덕에 모델이 미완료 작업 기록을 확인하고 재개 절차를 적용한다.
- **시나리오 2 (절단 신호):** 긴 자동 실행 중 컨텍스트 사용량이 임계값을 넘으면, 모델에게 "다음 계획 항목 경계에서 세션 인계를 수행하라"는 지시가 주입된다. 모델은 wf-implement 세션 인계 절차(인계 절 갱신 + 표준 재개 프롬프트 출력)를 수행한다.
- **시나리오 3 (컴팩션 안전망):** 자동 컴팩션이 임박하거나 발생할 때, 작업 기록이 최신인지 확인·갱신하라는 지시가 전달되어 손실 요약 이전에 불변식이 이행된다.

## 기능 요구사항

- FR-01: 세션 시작 시(시작·`/clear`·재개 포함) 현재 저장소의 `docs/work/`에 완료되지 않은 작업 기록이 있으면, 그 목록과 "재개 절차를 먼저 적용하라"는 지시를 세션 컨텍스트로 주입해야 한다.
- FR-02: 세션의 컨텍스트 사용량이 설정 가능한 임계값을 초과하면, "다음 계획 항목 경계에서 wf-implement 세션 인계를 수행하라"는 지시를 모델 컨텍스트로 주입해야 한다. 임계값 미만에서는 주입하지 않는다.
- FR-03: 자동 컴팩션에 대한 2단 안전망을 제공해야 한다. (a) 사전 — FR-02의 임계값 경고가 통상적인 컴팩션 발생점보다 먼저 발화하도록 보수적인 기본 임계값을 둔다. (b) 사후 — 컴팩션 직후 세션이 이어질 때, 작업 기록을 정본으로 삼아 진행 상태를 재확인하라는 지시를 주입한다. (조사 결과 컴팩션 직전 주입은 훅 능력상 불가능하다 — [가정과 미해결 질문](#가정과-미해결-질문) Q-02 해소 참조.)
- FR-04: 훅 설치는 `setup_claude.ps1` 재실행만으로 완료되어야 하며, 기존 `settings.json`의 다른 설정과 사용자가 추가한 훅을 보존해야 한다.
- FR-05: 워크플로우를 사용하지 않는 저장소(`docs/work/` 없음)에서는 모든 훅이 컨텍스트를 주입하지 않아야 한다(무동작).

## 비기능 요구사항

- NFR-01 (fail-open): 훅 스크립트의 오류·타임아웃이 세션 진행을 차단해서는 안 된다. 오류 시 주입 없이 통과한다.
- NFR-02 (하네스 중립 보존): skills/ 본문을 변경하지 않는다. 훅이 주입하는 지시는 스킬이 이미 규정한 절차(세션 인계, 재개 절차)를 가리키는 포인터여야 하며 새 규범을 만들지 않는다.
- NFR-03 (성능): 프롬프트/툴 사용마다 실행되는 훅은 체감 지연을 만들지 않아야 한다(단순 파일 크기 확인 수준의 작업만 수행).
- NFR-04 (인코딩): 주입 텍스트의 한글이 손상되지 않아야 한다.

## 인수 조건

- AC-01: 미완료 작업 기록이 있는 저장소에서 새 세션을 시작하면, 첫 응답에서 모델이 해당 작업 기록의 존재를 인지하고 재개 절차를 적용한다. 미완료 기록이 없으면 어떤 재개 지시도 주입되지 않는다.
- AC-02: 컨텍스트 사용량이 임계값을 초과한 세션에서는 다음 훅 발화 시점에 인계 지시가 주입되고, 임계값 미만 세션에서는 주입되지 않는다. 임계값은 환경 변수 또는 설정 파일로 변경 가능하다.
- AC-03: 훅 미설치 상태와 기설치 상태 각각에서 `setup_claude.ps1`을 실행한 뒤 `settings.json`이 유효한 JSON이고, 사전에 존재하던 무관한 키·훅이 보존된다.
- AC-04: 훅 스크립트가 인위적 오류를 내도 세션의 프롬프트 처리가 정상 진행된다.
- AC-05: `docs/work/`가 없는 저장소에서 세 훅 모두 아무 컨텍스트도 주입하지 않는다.
- AC-06: 컴팩션 직후 이어지는 세션에서, 작업 기록을 정본으로 재확인하라는 지시가 주입된다(수동 `/compact`로 재현·관찰 가능).

## 제약과 의존성

- Windows PowerShell 5.1 환경(설치 스크립트·훅 스크립트 공통). 한글 리터럴 인코딩 제약에 유의한다.
- Claude Code 훅 API(이벤트, 입력 JSON, 컨텍스트 주입 방식)는 문서화된 현행 능력을 따른다. 조사 결과는 설계 문서에 사실로 기록한다.
- 훅은 사용자 전역 설치이므로 이 저장소 외의 프로젝트에도 적용된다(FR-05가 오발화를 막는다).

## 가정과 미해결 질문

- 가정: transcript 파일 크기의 성장량(세션 시작 시점 기준점 대비)은 컨텍스트 사용량의 단조 증가 프록시로 임계값 판정에 충분하다. 오차는 보수적 기본 임계값과 설정 가능성(AC-02)으로 흡수한다. 신호 선택의 대안 비교는 [ADR-001](./work/20260809-claude-hooks/ADR-001-컨텍스트-신호-선택.md)에 기록한다.
- Q-01 (해소, 2026-08-09): 컨텍스트 사용량을 훅이 직접 알 수 있는 문서화된 신호는 없다. 훅 입력 JSON에 토큰 필드가 없고, statusline 입력에는 있으나 훅이 접근하는 문서화된 경로가 없다. → transcript 크기 프록시 채택(ADR-001).
- Q-02 (해소, 2026-08-09): PreCompact 훅은 모델 컨텍스트 주입을 지원하지 않는다(컴팩션 차단만 가능). → FR-03을 사전 임계값 + 사후 재정렬의 2단 안전망으로 확정.

## 위험

- RISK-01: Claude Code 훅 API 변경으로 훅이 무동작·오동작할 수 있다. 완화: fail-open(NFR-01) 설계로 최악의 경우에도 A층 수동 경로가 유지된다.
- RISK-02: transcript 크기와 실제 컨텍스트 토큰의 괴리로 임계값이 과소·과대 발화할 수 있다. 완화: 설정 가능한 임계값(AC-02), 보수적 기본값, 지시 문구를 "다음 경계에서"로 두어 조기 발화의 비용을 낮춘다.
- RISK-03: 전역 훅이 무관한 저장소에서 발화한다. 완화: FR-05 가드.
