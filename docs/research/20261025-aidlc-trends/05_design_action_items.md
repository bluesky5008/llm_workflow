**기본안과 다른 편성 두 가지.**

1. **S6(경량 경로 기계 조건)을 기타에서 사이클 B로 당긴다.** S28 훅은 "경량 경로 작업은 통과"해야 하는데, 경량 경로 여부를 에이전트의 판단이나 자기 표시로만 정하면 훅이 그 판단을 그대로 믿게 된다. 판단 여지가 있는 조건은 우회된다는 9월 근거(Rationalization Loophole 94%, 2607.01456 — A1 정밀 확인)가 S6의 원래 이유이므로, 통과 조건을 정하는 사이클에서 함께 정해야 기준선을 두 번 바꾸지 않는다.
2. **실행 순서를 B → A → C로 권한다(Q-D7).** 기본안의 사이클 이름(A·B·C)은 유지하되, [04 §0](./04_test_action_items.md#0-원칙)의 "규칙 → 강제" 원칙과 [대조 문서 §5](./00_trends_vs_workflow.md#5-권고-순서)(강제 장치 묶음 우선)를 따른다. B가 먼저 끝나면 (a) S28이 사이클 A 자신의 구현 단계를 지키고, (b) B에서 §1·§8 본문을 references로 옮겨 생긴 어절 여유를 A가 쓸 수 있다(§6). 기본안 순서(A 먼저)를 택해도 항목 내용은 같다.

## 0. 원칙

- **새 규칙보다 기존 규칙의 강화·강제.** 질문 장치는 §2 "결과를 크게 바꾸는 정보만 질문"과 §3.1 가정 확인을, 적대 검토는 §4.5 일관성 검토를, 승인 게이트는 §8 "승인 이외의 응답에서는 구현을 시작하지 않는다"를 강화한다. 새 개념(새 식별자 계열, 새 문서 유형)은 대안이 없을 때만 둔다.
- **본문 어절 예산.** wf-design 본문은 2,288/2,300어절(여유 12), wf-implement 2,850/2,850(여유 0), wf-doc 2,337/2,350(여유 13), wf-tree 1,193/1,200(`lint_skill.py`, 2026-10-26). 각 사이클은 **본문 순증 0**을 목표로 하고, 늘어나는 규칙은 references로 보내 본문에는 트리거·링크만 둔다(ADR-010). 사이클별 이관 계획은 §6.
- **하네스 중립.** 스킬 본문은 "작성 맥락을 공유하지 않는 검토자", "편집 시점 확인"처럼 의무만 적는다. 훅은 `setup/hooks/` 어댑터에, 판정은 하네스 중립 B층 스크립트에 둔다(ADR-014 결정 5의 3층 구조 재사용).
- **테스트 사이클 위에 쌓는다.** S28은 DCR-015의 훅 구조(PreToolUse `ask` + 조건부 `deny`, 가드만 fail-to-ask, `messages/*.md` 포인터 메시지, B층 판정 스크립트 + 어댑터 래퍼)를 그대로 재사용한다. 구현 중 자문 요청(D-03)은 사이클 1의 충돌 출구(verification-depth §6)를 일반화한다.
- **측정 위치를 적는다.** 효과 측정이 이 저장소에서 불가능한 항목은 "코드 저장소 실측 필요"로 표시한다(v2 결정 D-02 제안: 최소 1개 사이클은 코드 저장소에서).
- **근거 표시.** `[재확인 10-26]` 이번에 원문 확인, `[노트]` 2026-10-25 노트의 원문 판독(이번 미재확인), `[실무]` 실무·현장 보고(통제 실험 아님), `[2차]` 2차 출처, `[미확인]` 확인 못 함.

## 3. 첫 사이클 완료 판정 초안(인수 조건 후보)

**권장안(Q-D7 (B)) — 사이클 B를 먼저 할 때**

- 열린 정식 경로 작업의 req-design이 `approved`가 아닐 때 `skills/`·`setup/` 파일을 Edit/Write하려 하면 확인 요청이 뜨고, `docs/` 파일은 확인 없이 쓰인다.
- 열린 작업이 없거나, 열린 작업이 경량 표지와 기계 조건을 만족하면 확인 없이 쓰인다. `docs/work/`가 없는 저장소에서는 아무 동작도 하지 않는다.
- 상태가 `approved`여도 승인 기록 절에 사용자 응답 인용이 없으면 확인 요청이 뜬다(Q-D6 (b) 채택 시).
- 작업 문서를 읽지 못하면 확인 요청이 뜬다(fail-to-ask). 권한 자동 승인 모드에서의 `ask` 도달 여부가 관찰·기록된다(두 가드 모두).
- wf-design 본문의 경량 경로 절과 §8 승인 요청 문단이 references로 옮겨지고 본문 어절이 2,288 이하로 줄어든다. ADR 템플릿에 직전 ADR 참조 문장이 있다.
- TST-01·TST-02가 확장된 건수로 같은 SHA 2회 통과한다.

**기본안(A 먼저)을 택할 때**

- 정식 경로 req-design에 질문 단계 기록(질문 표 또는 "질문 없음 — 이유")이 있다.
- 적대 검토 결과 표의 지적마다 근거 인용 또는 `제안` 강등 표시가 있고, 라운드 수가 2 이하다.
- 질문 표에 `선택지`·`권장안`·`답` 열이 있다.
- wf-design 본문이 2,300어절 이하다(lint_skill K3) — 이관 없이 트리거 2문장을 넣으면 넘칠 가능성이 높다(§6).
