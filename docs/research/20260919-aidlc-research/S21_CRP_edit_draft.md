# S21 편집안 — 에이전트 발신 자문 요청 (CRP)

> 대상: `bluesky5008/llm_workflow`. SE 3.0 로드맵이 지목한 유일한 구조적 공백("모든 관문이 인간→에이전트 하향")을 메우는 편집안.
> 근거: 이번 추가 검색으로 확보한 명확화(clarification) 실증 6편. 수치는 원문 재확인.
> 작성 2026-08-27.

---

## 0. 이 편집안의 한 줄 요지

**CRP는 "에이전트가 아무 때나 질문하는 기능"이 아니다.** 타이밍 실증이 보여준 바에 따르면 목표 수준의 모호함은 실행 시작 직후에만 해소 가치가 있고(이미 wf-design §8이 그 자리를 점유), 늦게 묻는 것은 낭비다. 따라서 CRP는 **구현 중 발견되는 입력·제약 수준의 모호함**만 담당하며, 답이 기준선의 의미를 바꾸면 즉시 DCR로 전환된다. 새로 만드는 것은 질문 기능이 아니라 **Q-NN(설계 시점) / CRP(구현 시점, 기준선 불변) / DCR(기준선 변경)의 3분할 경계**다.

## 1. 근거 — 추가 검색 결과 6편

### 1.1 타이밍이 설계를 결정한다 (가장 중요)

**Ask Early, Ask Late, Ask Right** (PwC US, [arXiv 2605.07937](https://arxiv.org/html/2605.07937)) — 84 태스크 변형·5개 주입 지점(10/30/50/70/90%)·3개 벤치마크(MCP-Atlas·TheAgentCompany·SWE-Bench Pro)·4개 프론티어 모델·**6,000회 이상 실행** + 자연 질문 300세션. 재확인 완료:

| 명확화 유형 | 결과 |
|---|---|
| **목표(goal)** | Inj-10에서 pass@3 **0.78**(오라클 0.80, 무명확화 0.40) → Inj-30 0.50 → **Inj-70 0.39 = 베이스라인**. 30%까지는 잔존 가치, 70%면 완전 소멸 |
| **입력(input)** | 회복 창이 **약 50%까지** 연장("agents partially compensating through environment exploration") |
| **제약(constraint)** | 오라클 격차가 없으면 이득 미미. 실행 전 명시가 최선 |
| 낭비 계산 | 오라클 궤적에 없는 사전 행동이 Inj-10 **0.0%** → Inj-90 **21.7%** |

**그리고 결정적 발견:** 어떤 프론티어 모델도 최적 창에서 묻지 않는다 — GPT-5.2 첫 질문 평균 **43%**, Claude Sonnet 4.5 **50%**, Gemini 3 Flash **0%(전혀 안 물음)**. 결론: "agents should validate goals within the first few actions."

→ **함의:** 모델의 자연 질문 시점(50%)은 목표 명확화에 이미 늦다. 워크플로우가 이를 **구조로 강제**해야 하며, 용스님의 wf-design §8 승인 관문은 정확히 그 강제 장치다(실행 0% 지점). CRP는 그 자리를 침범하지 않고 **입력·제약 수준**을 맡아야 한다.

### 1.2 묻는 것은 효과가 있지만 과잉 질문은 손해다

**Ask or Assume?** (Edwards & Schuster, Univ. of Vienna, [arXiv 2603.26233](https://arxiv.org/html/2603.26233v1)) — Main Agent + Intent Agent 분리 스캐폴드, Claude Sonnet 4.5, SWE-bench Verified.

| 조건 | 해결률 |
|---|---|
| 완전 명세 기준선 | 70.80% |
| **다중 에이전트(Intent Agent)** | **69.40%** |
| 단일 에이전트 | 61.20% |
| 다중 에이전트가 **묻지 않기로 한** 태스크 | **76.92%** (억제 판단이 정확했다는 증거) |

**과잉 질문의 대가:** 단일 에이전트 변형은 500개 중 **369개**에서 질문했고 질문한 태스크의 해결률은 **55.81%**(다중 65.99%). 비용은 태스크당 $3.50 vs 완전명세 $1.63으로 두 배 이상.

Intent Agent의 탐지 신호(명시적 신뢰도 점수 아님): 의도에 영향을 주는 맥락 결손, 모호·가정 의존 정보, 완료를 막는 공백, **실패한 파일 조작**, **코드 변경과 테스트 결과의 불일치**.

### 1.3 에이전트는 스스로 묻지 않는다

**Ambig-SWE** (CMU, ICLR 2026, [arXiv 2502.13069](https://arxiv.org/html/2502.13069)) — SWE-bench Verified 500건을 축약해 과소명세 변형 생성, 3조건(Full/Hidden/Interaction) 비교.

- 상호작용은 비상호작용 대비 **최대 74%** 향상, Claude Sonnet 4는 완전명세 성능의 **89%** 회복.
- **대부분의 모델은 명시적 유도 없이는 비상호작용이 기본값**(Neutral/Moderate/Strong 3단계 유도 필요).
- 과소명세 **탐지 정확도**: Claude Sonnet 4 89%, Sonnet 3.5 84% — 그 외는 저조. **Qwen 3 Coder는 어떤 조건에서도 상호작용 실패(100% FNR)**.
- Claude Sonnet 4는 **50% 적은 질문으로 동등한 정보 이득**(0.171 vs 0.179) — 탐색 우선 전략.

→ **함의:** "불확실하면 물어라"는 지시로는 작동하지 않는다. **관찰 가능한 발행 조건**을 문서에 명시해야 하고, 모델 의존성이 크므로 규칙은 모델 능력에 기대지 않아야 한다.

### 1.4 멈춤 판단은 늦거나 없다

**Agentic Abstention** (Leeds·SWJTU·UW, [arXiv 2606.28733](https://arxiv.org/html/2606.28733v1)) — 13개 시스템·28,000 태스크. 대부분 모델의 **적시 기권 재현율 40% 미만**. 최고(Llama-3.3-70B) WebShop 적시 26.7%. 궤적을 재사용 가능한 정지 규칙으로 증류하는 `convolve`가 26.7%→**57.4%**로 개선(파라미터 갱신 없이).

→ **함의:** 정지·자문 판단은 모델 내재 능력이 아니라 **외부화된 규칙**으로 끌어올려야 한다. 이는 이 저장소의 스킬 방식과 정확히 같은 처방이다.

### 1.5 "확신에 찬 오답"이 진짜 실패 모드

**Knowing When to Ask for Help** (Shaikh, [arXiv 2608.24087](https://arxiv.org/abs/2608.24087)) — 자기 에스컬레이션을 최적 정지 문제로 정식화. 핵심 문장: "**high entropy is not failure and low entropy is not correctness, since a model can be confidently wrong.**" 실무 권고: 라우팅 로직 정교화보다 **판단 근거의 보정(calibration)**이 우선.

→ **함의:** CRP 발행 기준을 "에이전트의 확신 정도"에 두면 안 된다. **외부에서 관찰 가능한 사실**(기준선에 값이 없다, 두 해석이 검증 결과를 가른다, 같은 접근이 두 번 실패했다)에 두어야 한다.

### 1.6 종합 — 설계 원칙 5가지

| # | 원칙 | 근거 |
|---|---|---|
| P1 | 목표 수준 명확화는 **구현 시작 전**에 끝낸다. CRP는 목표 수준을 다루지 않는다 | 2605.07937 (Inj-70 = 베이스라인) |
| P2 | 발행 조건은 **관찰 가능한 사실**로 쓴다. "불확실하면"으로 쓰지 않는다 | 2608.24087, 2502.13069 |
| P3 | **억제 조건**을 함께 명시한다. 과잉 질문은 해결률을 떨어뜨린다 | 2603.26233 (369/500, 55.81%) |
| P4 | 각 계획 항목의 **시작 시점**에 판정을 강제한다 | 2605.07937 (모델 자연 질문 43–50%는 늦음) |
| P5 | 발행 수에 **상한**을 두고, 초과하면 기준선 결함을 의심한다 | 2603.26233 (3.06 질문/태스크), 2606.28733 |

## 2. 설계 결정 — Q-NN / CRP / DCR 3분할

기존 워크플로우에는 이미 두 개의 질문 장치가 있다. 새 장치를 넣기 전에 경계를 확정한다.

| 장치 | 발생 시점 | 다루는 것 | 기준선 영향 | 소유 |
|---|---|---|---|---|
| **`Q-NN` 미해결 질문** | wf-design 단계 | 요구·설계를 확정하려면 답이 필요한 질문 | 기준선 확정 **전**이므로 해당 없음 | wf-design (§8 승인 관문에서 함께 제시) |
| **`CRP-NNN` 자문 요청** (신설) | wf-implement 단계 | 승인된 기준선을 **실행**하는 데 필요한 정보·해석 | **바꾸지 않음** | wf-implement가 발행, 사용자가 해소 |
| **`DCR-NNN` 설계 변경** | wf-implement 단계 | 기준선의 의미·계약을 바꿔야 하는 사실 | **바꿈** | wf-design (재승인·새 기준선) |

**전환 규칙(핵심):** CRP의 답이 요구사항·인수 조건·공개 계약·데이터·보안 정책의 의미를 바꾸면, 그 CRP는 즉시 `escalated`로 닫고 [DCR 절차](../wf-design/references/design-change.md)로 전환한다. 판단이 애매하면 DCR로 취급한다.

**왜 CRP를 DCR로 합치지 않는가:** DCR은 보류·영향분석·재승인·기준선 증가를 요구하는 무거운 절차다. "로그 레벨을 어디에 맞출까", "이 환경변수 이름이 기존 관례와 다른데 어느 쪽인가" 같은 **기준선을 바꾸지 않는 실행 정보**까지 DCR로 처리하면 §4.2의 중대 변경 목록이 희석되고, 실무에서는 결국 에이전트가 임의 가정으로 진행하게 된다 — 이 저장소가 경계하는 "대화에만 존재하는 결정"이다.

**왜 Q-NN을 확장하지 않는가:** Q-NN은 요구사항·설계 문서 안의 **정적 목록**이고 승인 관문에서 일괄 해소된다. CRP는 구현 중 발생하는 **개별 사건**이며 그 시점에 해당 계획 항목만 보류시켜야 한다. 상태 전이와 해소 경로가 달라 같은 식별자로 묶으면 추적이 흐려진다.

## 3. 편집안 — 파일별 실제 문장

### 3.1 wf-implement/SKILL.md — 새 절 `3.7 자문 요청(CRP)`

> 배치: §3.6 통합 뒤, §4 변경 관리 앞. (§3.3~3.6 절차 흐름 뒤, 변경 관리 앞이 의미상 자연스럽다.)

```markdown
### 3.7 자문 요청 (CRP)

승인된 기준선을 실행하는 데 필요한 정보나 해석을 사용자에게 요청해야 할 때 자문 요청(`CRP`)을 발행한다. CRP는 기준선의 의미를 바꾸지 않는 범위의 질문이며, 기준선을 바꿔야 하는 사실을 발견했다면 CRP가 아니라 [설계 변경](#42-중대한-변경--구현-보류-후-재승인-필요)이다.

CRP 문서의 절 구조와 상태 표기는 [wf-doc 자문 요청 템플릿](../wf-doc/references/templates.md#자문-요청-consultation)을 따른다. 이 절은 발행 조건, 억제 조건, 보류 범위와 해소 판정을 소유한다.

**판정 시점.** 각 계획 항목을 시작할 때, 그 항목이 참조하는 기준선 항목을 읽고 아래 발행 조건을 먼저 판정한다. 항목을 절반 이상 진행한 뒤에 발견한 의도 수준의 모호함은 CRP로 처리하지 않고 [현재 상태 재확인](#31-현재-상태-재확인)의 누락으로 기록한 뒤 설계 변경 여부를 판단한다.

**발행 조건.** 다음 중 하나에 해당하고, 억제 조건에 걸리지 않을 때 발행한다. 조건은 모두 관찰 가능한 사실이며, 에이전트의 확신 정도를 기준으로 삼지 않는다.

- 기준선이 두 가지 이상으로 읽히고, 어느 쪽을 택하느냐에 따라 인수 조건의 판정 결과가 달라진다.
- 계획 항목을 실행하는 데 필요한 값·경로·자격·환경이 기준선에도 저장소에도 없다.
- 기준선의 문언과 저장소의 실제 관행이 충돌하고, 어느 쪽을 따를지가 공개 동작에 드러난다.
- 같은 접근으로 두 번 실패했고, 실패 원인이 기술적 문제가 아니라 의도 해석에 있다.

**억제 조건.** 다음에 해당하면 발행하지 않는다.

- 저장소를 조사하거나 실행해 확인할 수 있다. 직접 확인할 수 있는 내용은 묻기 전에 조사한다.
- 결과를 크게 바꾸지 않는 낮은 위험의 가정으로 진행할 수 있다. 이 경우 가정을 작업 기록에 명시하고 진행한다.
- 답이 기준선의 의미를 바꾼다. 이때는 설계 변경으로 처리한다.
- 같은 사안으로 이미 발행한 CRP가 미해소 상태다.

**보류 범위.** CRP를 발행하면 그 CRP가 막는 계획 항목만 보류하고, 의존 관계가 없는 다른 항목은 계속 진행한다. 보류한 항목의 상태는 `blocked`으로 두고 차단 요인에 CRP 식별자를 적는다.

**발행 상한.** 한 작업 사이클에서 미해소 CRP가 3건을 넘으면 개별 발행을 멈추고, 기준선 자체가 구현하기에 충분하지 않다고 보아 [wf-design 승인 관문](../wf-design/SKILL.md#8-사용자-승인-관문)으로 반환한다. 반환 시 미해소 CRP 목록을 근거로 인계한다.

**해소.** 사용자 응답을 CRP 문서에 기록하고 상태를 다음 중 하나로 바꾼다. 해소 결과는 대화에만 남기지 않는다.

| 응답 | 상태 | 이후 |
|---|---|---|
| 답변 | `answered` | 답변을 근거로 보류한 항목을 재개한다. 답변이 기준선의 의미를 바꾸지 않음을 확인한다 |
| 판단 위임 | `delegated` | 선택한 안과 이유를 가정으로 기록하고 재개한다. 가정은 [자체 리뷰](#35-자체-리뷰)에서 다시 확인한다 |
| 기준선 변경 필요 | `escalated` | 설계 변경으로 전환하고 CRP는 닫는다. DCR에 이 CRP를 근거로 연결한다 |
| 자체 해소 | `withdrawn` | 조사·실행으로 답을 확인했음을 근거와 함께 기록하고 재개한다 |

해소되지 않은 CRP가 남은 상태에서 작업을 완료로 보고하지 않는다. 세션을 인계할 때는 미해소 CRP를 [인계](#7-작업-기록과-저장-위치) 절에 명시한다.
```

## 6. 남은 위험과 미해결

- **모델 의존성.** Ambig-SWE에서 탐지 정확도가 모델별로 89%~0%였다. 발행 조건을 관찰 가능한 사실로 쓴 것이 이 위험의 완화책이지만, 완전한 해결은 아니다. 조건 문장이 실제로 발화를 유발하는지 초기 사이클에서 확인해야 한다.
- **사용자 응답 지연.** 논문들은 즉시 응답하는 시뮬레이션 사용자를 전제한다(2603.26233은 GPT-5.1 시뮬레이터의 "unnaturally cooperative" 한계를 스스로 지적). 1인 사용 환경에서는 응답이 늦을 수 있으므로 "잠정 진행" 절과 항목 단위 보류가 이를 흡수한다.
- **`delegated`의 남용.** 사용자가 매번 "알아서 해"로 답하면 CRP가 형식만 남는다. 자체 리뷰에서 위임 가정을 재확인하는 규정으로 일부 방어하나, 실사용에서 관찰이 필요하다.
- **미검증 전제.** 3건 상한과 20% 발행 시점은 논문 수치(3.06, 10~30% 창)에서 유추한 값이지 실증된 임계가 아니다. 초기 사이클에서 보정 대상.
