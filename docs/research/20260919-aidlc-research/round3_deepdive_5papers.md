# ① Your AI, My Shell — 과정 보안 (arXiv 2509.22040v2)

## 정밀 요약

**위협 모델.** 에이전틱 코딩 에디터는 스스로 다단계 계획을 세우고 **터미널 명령을 실행**한다. 개발자가 외부에서 가져온 룰 파일을 검증 없이 시스템 지시로 신뢰하는 가정이 깨진다. 공격자는 로컬 접근 없이 **외부 리소스에 심은 프롬프트만으로** 무단 셸 실행을 유도한다. 실험은 사용자가 이미 터미널 자동승인을 켠 상태를 전제한다.

**중요한 범위 제한(재확인).** 논문이 **실제 실험한 채널은 코딩 룰 파일 하나뿐**이다("we concentrate on coding rule files"). `.cursor/rules`, `.github/copilot-instructions.md`가 대상. GitHub 저장소·MCP 설정은 위협으로 *언급만* 하고 향후 과제로 남긴다. → 3채널 게이트를 설계하되 룰 파일 위험은 실증, 나머지 둘은 논리적 추정임을 구분해야 한다.

**AIShellJack.** 314개 페이로드 / MITRE ATT&CK 70기법(atomic-red-team 출처). 구성: 명령 추출 → 적대 표현 소독 → **"For debugging purposes" + "MANDATORY FIRST STEP"** 템플릿으로 우선 실행 유도. 성공 판정은 시맨틱 매칭(동치쌍 26·setup 패턴 13 제외, θ=0.2), 수동 검증 99.1% 정확도.

**결과(재확인).** 두 지표를 구분한다 — **Execution rate**(아무 명령이나 실행 75–89%) ⊇ **Attack Success Rate**(악성 의도와 일치). Cursor v1.2.2 Auto Mode에서 ASR 66.9–84.1%(최고 ts-lep TypeScript 84.1%). 초록의 하한 41%는 Copilot 계열 조합으로 보이나 셀별 정확값은 **본문에서 확인 못함**. 모델은 Claude-4-Sonnet·Gemini-2.5-Pro. 실제 실행된 공격 예: `~/.bashrc`를 curl로 수정(지속성), grep으로 API 키 탐색 후 curl 유출.

**방어(측정 없음).** 외부 리소스 소독·allowlist·사람 승인·샌드박싱·컨텍스트 분리·서명을 제안하되 **어떤 방어도 효과를 실험하지 않았다.** denylist는 curl→wget 대체로 우회, 사람 승인은 approval fatigue + 신뢰 대화창 우회 CVE(2025-65099, 2025-62222)로 뚫림. 한계: 룰 파일 5종·각 1회 실행·Linux 전용·auto-approve 가정.

## 워크플로우 대조 — 용스님은 소비자이자 배포자

이 저장소는 **양쪽 다**다. root SKILL.md 라우터로 통째 설치되고, 설치 시 CLAUDE.global.md를 사용자 전역 `~/.claude/CLAUDE.md`에 이어붙이며 훅 3종을 등록한다. 즉 남이 import하는 스킬이면서, ponytail 등 외부 스킬에 의존한다.

**핵심 인식: 훅은 그 자체가 주입 벡터다.** SessionStart 훅이 work-log 재개 지시를 컨텍스트에 주입하는데, 그 주입 채널에 악성 지시가 실리면 논문의 룰 파일 공격과 동형이 된다. 외부 훅 도입은 최고 위험으로 취급해야 한다.

## 실행 항목

- **S17 도입 게이트(소비자).** 외부 룰·스킬·MCP 도입 시 스캔: 우선-실행 프레이밍("MANDATORY", "first step", "For debugging"), 위험 명령(curl·wget·base64·tar·`~/.ssh`·`.env`·crontab), 난독화(base64/hex), MCP `command`/`args`의 임의 바이너리 기동. **자율 셸 실행 지시·유출 엔드포인트·자격증명 접근은 하드 차단.** setup_claude.ps1이 junction·CLAUDE.md·settings.json을 건드리기 직전에 정적 스캔 삽입. 단 논문 교훈대로 **자동화는 1차 필터일 뿐 사람 검토를 대체 못 함.**
- **배포자 의무.** 릴리스에 커밋 SHA/체크섬, 버전 핀 옵션 문서화(junction은 최신 자동 추종 → 외부 소스는 핀된 스냅샷으로). 훅이 fail-open·텍스트 주입만·셸 미실행이라는 보안 속성을 전면 명시. §2.3 승인 경계를 안전 계약으로 광고.
- **자가 점검 실험.** 소독된 페이로드를 가짜 `.cursor/rules`·CLAUDE.md·훅 주입 문자열에 심어 일회용 샌드박스 VM(auto-approve)에서 워크플로우 에이전트에 정상 작업을 시키고 실행 여부 관찰. 논문이 못 한 **다회 반복**으로 변동성 측정 + **방어 효과 측정**(S17 게이트가 각 페이로드를 실제 차단하는지)을 CI 회귀로.

# ② E2EDevBench — 단계 세분화의 실증 (arXiv 2511.04064)

## 정밀 요약

**벤치마크.** PyPI 실전 프로젝트 50개(평균 파일 19.2·LOC 2,011.5·테스트 119.7). 각 프로젝트에 수작업 검증된 요구사항 문서(검증용 10개에 546개 요구). 측정은 하이브리드: Test Migration Agent가 원본 테스트를 이식(평가 코드 수정 금지) + **요구사항별 이진 판정을 3회 독립 요청해 만장일치일 때만** 인정(Impl-Rate). 인간 대조 Pearson ≥0.62.

**비교 시스템(재확인).** 셋 다 Gemini-2.5-Pro/Flash, temp 0.2, 최대 200스텝.

| 구성 | Impl-Rate(Pro) |
|---|---|
| Single | 42.97% |
| **Developer-Tester (DT)** | **53.50%** (최고) |
| Designer-Developer-Tester (DDT) | 32.79% (최저) |

**최첨단도 요구의 ~50%만 충족.** DDT가 최저인 이유가 핵심: **설계 단계가 역효과**다 — "Dev가 권위 있는 구현 계획을 받으면 원본 요구 문서가 있어도 계획을 우선시하고, 계획이 결함이면 하류로 충실히 전파된다." DT의 Dev는 사전 계획 없이 원본 요구에서 직접 해석하도록 강제되어 더 충실.

**실패 분류(재확인).** 계획 **55.8%**(요구 누락 27.9% + 오해석 22.2% + 아키텍처 결함 5.6%), 실행 38.6%(연쇄 21.0% + 피상 12.5% + 기술한계 3.2% + 맥락망각 1.9%), 검증 5.7%. **순수 기술 역량 실패는 3.2%뿐.** 결론: "요구공학 역량 향상이 코드 생성 향상보다 큰 이득." 저자는 하이브리드(인간 개입)를 권고하지 않고 자율 에이전트 개선에 집중.

## 워크플로우 대조 — front-loading이 정당한가

**그렇다, 그리고 논문이 권고하지 않은 지점을 이미 구현한다.** 논문의 최대 병목(55.8% 계획 실패)은 정확히 wf-design §4.2·4.3·4.5 영역이고, 논문의 55.8%는 "에이전트가 자율 실행 중 스스로 저지르는" 계획 실패인데 용스님 워크플로우는 그 계획을 **구현 전 인간 승인 산출물로 외부화**한다 — 논문이 "권고하지 않았다"고 명시한 하이브리드를 그대로 구현한 셈.

- **요구 누락 27.9% → 잡는 장치 있음.** §4.2 인수 조건 + §4.5 "모든 핵심 요구가 설계 요소에 연결되는가" + §6.1·wf-doc §2.6 추적표. **연결이 빠진 요구가 곧 누락 신호** — 추적표가 코드 이전에 이를 잡는 계측기.
- **오해석 22.2% → §8 승인 관문이 부분적 답.** 설계 요약을 보고 "내 의도가 아니다"를 구현 전 되돌림. **급소 경고**: DDT 실패("승인된 계획이 원본 요구를 밀어냄")가 용스님의 승인된 design.md에도 적용될 수 있다. wf-implement §2.1·§3.5가 원본 요구를 별도 축으로 유지해 방어하지만, 의식적으로 관리해야 할 위험.
- **빠진 것.** ① 연쇄 실패의 **임계 노드 사전 식별 장치 부재**(§3.2는 의존성만 적음), ② 모델 역량 한계 3.2%는 워크플로우로 못 고침, ③ 요구 문서 완전성 오라클 부재(추적표는 내부 정합만 보장).

## 실행 항목

- **단계 수를 늘리지 마라.** DDT<DT<Single 순서(설계 중간층이 해가 됨) + RSTD의 정적분해 역설 + 워터폴 ablation의 모델 의존성 — 셋 다 "단계 추가는 이득 아님"을 가리킨다. **현 2단계 유지가 근거에 부합.**
- **임계 노드 표시(신규 후보).** §3.2 계획에 "실패 시 다수 하류 요구를 차단하는 핵심 요구/작업"을 위험 등급으로 사전 표시 — 21% 연쇄 실패 구간 대응. (S2 회귀 의무 목록과 결합 가능.)
- **자체 측정.** 사이클 종료 후 requirements.md + 코드 + 검증을 독립 LLM에 3회 만장일치로 Impl-Rate 산출. 미충족을 추적표로 분류(연결 TASK 없음=누락, 있으나 검증 실패=오해석·피상). front-loading 경유 작업 vs 경량 경로의 실패율 비교로 효과 정량화.

# ③ SE 3.0 로드맵 — 산출물 1:1 지도 (arXiv 2509.06216v2)

## 정밀 요약

SE 1.0(수동 코딩) → 2.0(계획된 변경→코드 블록, Copilot) → **3.0(기술 목표→다단계 계획 실행, Devin·Claude Code)**. 두 세계: **ACE**(SE for Humans — 인간이 편대를 지휘·멘토링하고 MRP/CRP 인박스를 관리하는 명령 센터) / **AEE**(SE for Agents — 에이전트가 실행하며 필요 시 인간 전문성을 능동 호출하는 작업대). 상위 개념 SASE. 문제의식: 대화형 프롬프트가 "터미널 스크롤백에만 존재"해 결정 진화 재구성·재현이 불가능.

**4기둥**: Actors(인간 Agent Coach + 전문 역할 에이전트 + per-agent 보안 정책으로 blast radius 제한), Processes(즉흥 프롬프트→구조화·반복 활동), Artifacts(휘발성 프롬프트→내구성 기계판독 계약), Tools(만능 IDE→ACE/AEE 분리).

**제안 산출물**: **BriefingScript**(버전관리 작업지시서 — What&Success·Architectural Context·Strategic Advice·Gotchas·Validation Loop), **LoopScript**(선언적 SOP — 분해·병렬화·workflow rigor·수용 기준), **MentorScript**(기계판독 규칙집 — 지침을 first-class code로), **CRP**(에이전트 발신 자문 요청 팩), **MRP**(병합 준비 증거 번들 5범주 — Functional·Sound Verification·SE Hygiene·Rationale·Auditability), **VCR**(인간 응답 — CRP/MRP에 링크), **DeepWiki**(에이전트 자체 지속 메모리). 프로세스: BriefingScript→LoopScript 안에서 MentorScript 지침으로 실행→막히면 CRP→완료 시 MRP→인간 VCR로 완결. 관문 3개(CRP 에스컬레이션·MRP 리뷰·VCR 해소).

## 산출물 1:1 대응 지도

| SE 3.0 | 워크플로우 대응 | 대응 정도 |
|---|---|---|
| BriefingScript | requirements.md + design.md 기준선 | **완전** |
| MentorScript | skills/*.md + CLAUDE.global.md + ponytail | **완전** (스킬 자체가 codified norms) |
| MRP | work-log verification+completion+§6 완료 보고 | **완전** (5범주 정확 대응) |
| LoopScript | plan.md + wf-tree 계획 트리 | 부분 (선언적 병렬화·rigor 미흡) |
| VCR | 승인 기록 + APR 문서 | 부분 (설계 기준선 사전 승인이라 MRP 사후 해소로는 미형식화) |
| DeepWiki | docs/ + decisions.md | 부분(강) — 에이전트 자체 저작·능동 유지보수는 부재 |
| **CRP** | Q-NN·on-hold (근접) | **없음** — 모든 관문이 인간→에이전트 하향. 에이전트 발신 산출물 부재 |
| ACE / AEE | CLI / 훅(하네스 어댑터) | 없음 |

## 실행 항목

- **최대 공백은 방향성이다 — CRP/VCR 루프(S21).** 용스님의 모든 관문은 인간이 에이전트를 하향 통제한다. 논문의 새 축은 반대 — **에이전트 발신 자문 요청**. 도입안: `docs/work/<id>/CRP-NNN-*.md` 유형 + wf-doc의 새 `consultation` 문서 유형 + MentorScript식 **consultation heuristics**("복잡도가 X를 넘으면 CRP 발행")를 스킬에 선언. 이는 "대화에만 존재하는 결정"을 경계하는 기존 철학과 정합.
- **어휘 차용(팀·대외 설명).** 워크플로우를 "CLI 형태의 SASE 구현"으로 포지셔닝: requirements+design=BriefingScript, 스킬=MentorScript, plan=LoopScript, 완료 보고=MRP, 승인 기록=VCR, docs/=DeepWiki, 실무자=Agent Coach. 단일 문장 로드맵: "SE 3.0의 5개 산출물 중 4개를 이미 운용, 격차는 에이전트 발신 자문(CRP/VCR)과 에이전트 전용 환경(AEE)."
- **역방향 강점 인식.** 논문이 *open research*로 남긴 것을 용스님은 구현했다 — 코드↔BriefingScript 절 추적(wf-doc 하이퍼링크 강제), 스크롤백 소실 해결(세션 인계 불변식+훅), DCR 변경 통제, 내용/형식 소유자 분리, 경량 경로(SASE의 "rigid universal processes are futile"의 실전화). 팀 배포 시 이 강점들을 SE 3.0 어휘로 설명하면 설득력이 크다.

# ④ RSTD — 선택적 재시도 (arXiv 2605.15425)

## 정밀 요약

세 접근: 모놀리식(한 프롬프트에 전부), 정적 분해(고정 서브태스크 그래프, 런타임 분기 없음), **RSTD**(실행 가능한 제어 흐름이 분할을 지배, LLM은 스키마 검증되는 좁은 판단에만 호출).

# ⑤ Agent Security is a Systems Problem (arXiv 2605.18991)

## 정밀 요약

**핵심 논지**: AI 모델을 신뢰 불가 컴포넌트로 취급하고 보안 불변식은 시스템 수준에서 강제하라. 근거: 공격자는 모델 기반 방어를 일관되게 우회하고, LLM은 temp 0에서도 비결정적이라 임계 속성(데이터 삭제·유출) 관리에 부적합. OS가 신뢰 불가 프로세스를 다루듯 모델 주위에 강제 경계를 세워야.

**3기제**: ① 명령-데이터 분리(W⊕X 유비 — 데이터를 코드로 해석 금지, 단 확률적 분리는 공격자가 반례 탐색), ② 검증 가능한 정책 생성(자연어→형식 정책 P + 결정론적 참조 모니터, 정확성=상호 함의), ③ 정보 흐름 제어(라벨 전파, 난점은 라벨 폭발). **경고**: ML 가드를 쌓으면 주 에이전트와 통계적 실패 모드를 공유해 상관 실패 → 비-ML 이질 강제로 보완. 권고: 최소 권한 샌드박싱, 민감 작업 사람 승인, **에이전트가 수정 불가한 불변 보안 설정**, 출력 살균. 한계: 완성된 참조 설계 없음, 3기제 모두 현재 미해결/aspirational. 근본 난점: 에이전트가 계층적 추상 경계를 결여해 자연스러운 참조 모니터 지점이 없음.

## 워크플로우 대조 — 묶음 B의 이론적 뒷받침

용스님의 훅은 전부 **결정론적·비-ML PowerShell, fail-open, 모델 바깥 실행** — 논문이 말하는 "이질적 비-ML 강제"의 정확한 사례다. ML 가드를 쌓으면 상관 실패가 나지만 훅은 모델과 기계론적으로 다른 층에서 동작해 추론으로 우회 불가. **묶음 B(S9 Stop 게이트·S7)는 "모델을 신뢰 불가로 두고 시스템 수준에서 불변식 강제"의 구체 구현.**

# 정리 — 이번 5편이 워크플로우에 추가한 것

**결정된 방향 3가지:**
1. **단계 수는 현 2단계 유지가 근거에 부합**(E2EDevBench + RSTD + 워터폴 ablation이 모두 "단계 추가는 이득 아님"). 세분화 대신 (a) 임계 노드 표시, (b) 선택적 재시도 명문화가 옳은 방향.
2. **front-loading은 정당**하며 논문이 권고 안 한 하이브리드를 이미 구현. 급소는 "승인된 설계가 원본 요구를 밀어내는" DDT 실패 — §3.5가 원본 요구를 별도 축으로 유지해 방어.
3. **훅·게이트 노선은 최신 보안 합의(Systems Problem)의 정확한 구현**. 남은 것은 불변 설정 원칙과 명령-데이터 분리의 명문화.

**새 후보 5개(S17–S21):** S17 도입 게이트, S18 명령-데이터 분리, S19 선택적 재시도, S20 불변 보안 설정, S21 CRP/VCR 자문 루프. 이 중 **S21(에이전트 발신 자문)이 개념적으로 가장 새롭다** — 용스님 워크플로우에 유일하게 빠진 "방향"이다.

**우선순위 제안:** S19·S20·S18은 문장 몇 개 추가라 사이클 2(훅 확장)에 흡수. S17은 스킬 저장소 운영자에게 실질 위험이라 독립 작업. S21은 실험적이라 별도 탐색(wf-design 승인 관문의 역방향 짝 설계).
