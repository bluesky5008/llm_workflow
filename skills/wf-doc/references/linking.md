# 문서 연결과 하이퍼링크 세부 규칙

[wf-doc 문서 연결, 추적성과 증거](../SKILL.md#26-문서-연결-추적성과-증거)의 핵심 규칙(모든 참조는 링크, `## 문서 연결` 절 필수, 역방향 링크 동시 추가, 가상 링크 금지, 루트·불변 문서 예외)을 적용할 때 따르는 세부 규칙과 표 어휘다. 어떤 관계가 존재하고 필수인지는 내용 소유자가 결정하며, 이 문서는 결정된 관계를 적는 **형태**만 정한다. 골격은 [공통 문서 연결 절](templates.md#공통-문서-연결-절)과 [추적표](templates.md#추적표)를 쓴다.

## 세부 규칙

- `관련 문서`, `문서 연결`, `추적성`, `승인 기록`, `대체 관계`, `기준선`, `검증 결과`, `인계`에서는 일반 텍스트 경로나 백틱으로 감싼 경로를 링크 대신 사용하지 않는다.
- `관련 문서` 머리말은 `## 문서 연결`에 있는 주요 링크의 요약이어야 하며 두 위치의 링크와 관계가 서로 충돌해서는 안 된다. 불안정한 줄 번호보다 문서 ID와 절 제목을 참조하고, 안정적인 Markdown 앵커가 있으면 파일 링크에 앵커를 추가한다.
- 승인된 문서에 역방향 링크만 추가하는 것은 기준선 의미를 바꾸지 않는 문서 명확화로 처리할 수 있다. 링크가 새로운 관계나 기준선 변경을 의미하면 `wf-design`의 DCR 절차를 따른다.
- 대상 문서가 외부·읽기 전용·불변 기록이라 역방향 링크를 추가할 수 없으면 현재 문서의 `## 문서 연결` `비고`에 사유와 대체 추적 위치를 기록한다. 이 경우에만 단방향 연결을 허용한다.
- 같은 파일에 여러 문서 유형을 합쳤으면 파일 경로 대신 해당 절의 Markdown 앵커로 연결한다.
- 문서를 이동하거나 이름을 바꾸면 저장소에서 해당 경로와 문서 ID를 검색하여 들어오는 링크와 나가는 링크를 모두 갱신한다.
- 연결 대상이 있는데 찾지 못한 경우에는 `N/A`로 숨기지 말고 `TBD`와 확인 책임자·조건을 기록한다.

## 문서 연결 표의 어휘

- `방향`은 현재 문서를 기준으로 `input`, `output`, `bidirectional` 중 하나를 사용한다.
- `관계`는 `baseline`, `refinement`, `decision`, `change`, `approval`, `implementation`, `verification`, `result`, `replacement`, `handoff`, `related` 중 가장 구체적인 값을 사용한다.
- `대상 문서`는 반드시 `[문서-ID: 제목](경로)` 형태의 하이퍼링크로 작성한다.
- `대상 항목`에는 관련 FR/NFR/AC/DES/TASK/VER 식별자를 기록한다. 문서 전체가 대상이면 `document`로 기록한다.
- 문서 유형별 필수 연결 대상은 [문서 유형별 필수 연결](templates.md#문서-유형별-필수-연결)을 따른다.
