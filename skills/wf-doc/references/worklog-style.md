# 작업 기록 교정 규칙

작업 기록의 산문을 [합본 템플릿](templates.md#작업-기록-work-log)의 필드로 바꾸는 변환 규칙과, 린트가 지적한 항목의 교정 방법이다. 분량 상한·린트 실행 시점·명령은 [wf-implement 작업 기록과 저장 위치](../../wf-implement/SKILL.md#7-작업-기록과-저장-위치)가 규정하고, 이 문서는 교정의 **형태**만 정한다. 원칙은 하나다: 저장소에서 재구성할 수 있는 것은 쓰지 않고, 재구성할 수 없는 것(결정·이유·검증 결과·다음 행동)만 남긴다.

## 변환표

| 서술 유형 | 바꿀 필드·형태 |
|---|---|
| 결정의 경위(검토한 대안, 고민, 바꾼 생각) | `결정과 이유`: "선택 — 이유" 한 문장. 기각한 대안은 재구성할 수 없을 때만 쉼표로 덧붙인다 |
| 사실·측정(실행 결과, 개수, 크기, 소요) | `검증` 또는 `발견 사항`: 수치, 실행 명령 1줄, VER·파일 링크. 형용사 대신 숫자 |
| 경과 서술("먼저 … 다음 … 마지막으로", 시도와 실패 과정) | 삭제한다. 결과와 결정만 남기고, 실패에서 얻은 결정은 `결정과 이유`로 옮긴다 |
| 변경 파일·diff 설명("A 파일의 B 절을 C로") | 삭제한다. git이 정본이며 미커밋 변경만 `## 인계`에 한 줄로 적는다 |
| 반복 설명(계획의 TASK 목표, 설계, 템플릿에 이미 있는 내용) | 정본으로 가는 링크 1개. 계획 목표와 같은 `수행 내용`은 필드째 삭제한다 |
| 진행 중 메모(지금 하는 일, 임시 발견) | 수행 기록 항목이 아니라 `## 인계`의 `다음 행동`에만 둔다. TASK 완료 시 항목으로 확정한다 |

## 전후 예시

전: 사이클 1 작업 기록(`docs/work/20261009-plan-relocation/work-log.md`)의 `수행 내용` 불릿 1개, 680자.

> 수행 내용: **TASK-05** `git rm docs/plan.md`(이력 보존). `docs/status.md`(`ST-llm-workflow`) 신설 — 작업 목록에 진행 중 2행(…), ASCII 트리 1회 생성(…), 승인 기록은 v1 승인 관문이 겸함. 역방향 링크: 이 작업 plan.md와 다인 토론 work-log의 문서 연결에 status 행 추가(링크만). README "실행 기준" 절 끝에 진행 중·완료 작업의 위치 안내 한 문단. 들어오는 링크 수리 53곳: 완료 작업 폴더 11개 파일의 `../../plan.md[#앵커]` → `./work-log.md[#수행-기록|#계획-트리]`, `docs/requirements.md`·`design.md` 추적표의 `./plan.md#작업-목록` → `./work/20260809-claude-hooks/work-log.md#수행-기록`(그 TASK들이 속한 사이클). 치환 전 대상 work-log에 해당 절이 있는지 단언으로 확인. **TASK-06** ADR-003 `## 대체 관계`에 관련(부분 수정) 1항, `## 변경 이력`에 1행 추가(`git diff` +2행). (…)

후: 3행. 무엇을 바꿨는지(계획 목표·git과 중복)는 버리고, 왜 그렇게 했는지와 어떻게 확인했는지만 남긴다.

> - 발견 사항: 삭제할 `docs/plan.md`로 들어오는 링크 53곳(완료 작업 폴더 11개 파일 + 추적표 2편).
> - 결정과 이유: 추적표 링크는 그 TASK가 속한 사이클의 work-log `#수행-기록`으로 — 삭제된 계획이 아니라 실제 기록을 가리키게. 치환 전 대상 절의 존재를 단언으로 확인해 일괄 치환 오류를 차단.
> - 검증: VER-07 링크 전수 검사 깨짐 0.

## 린트 코드별 교정 방법

| 코드 | 지적 | 교정 |
|---|---|---|
| L1 | 머리말 필수 필드 누락, 상태 어휘 오류 | [공통 머리말](../SKILL.md#23-공통-머리말-작성) 필드를 채우고 상태는 [상태 기록](../SKILL.md#24-상태-기록)의 어휘만 쓴다 |
| L2 | H2 목록·순서·중복이 합본 템플릿과 다름 | 템플릿 순서로 재배치한다. 현재 상태·미완료 항목·재개 지점 절은 내용을 `## 인계`로 옮기고 삭제한다. 같은 의미의 절은 하나만 남긴다 |
| L3 | 수행 기록 항목의 필수 필드 누락, 8행·600자 초과 | `결정과 이유`·`검증`·`결과`를 채운다(없으면 `없음`). 초과분은 변환표로 줄이고, 계획 목표와 같은 `수행 내용`은 삭제한다 |
| L4 | 펜스 코드블록 | 명령·경로는 인라인 코드로, 긴 출력은 핵심 수치 요약과 원본 위치 링크로 바꾼다 |
| L5 | 불릿 300자 초과 | 불릿 하나에 사실 또는 결정 하나만 둔다. 경과 서술은 삭제, 반복 설명은 링크로 바꾼다 |
| L6 | 로컬 링크 대상 없음, 앵커 불일치 | 실제 경로와 실제 제목의 슬러그로 고친다. 아직 없는 문서로의 링크는 제거한다(가상 링크 금지) |
| L7 | 인계 절 형식 오류 | 열린 상태는 7필드 + 표준 재개 프롬프트, `completed`는 4필드 축약 — [인계와 재개 지점 작성](../SKILL.md#27-인계와-재개-지점-작성) |
| L8 | `docs/status.md` 행 불일치 | 열린 작업은 행을 추가하고 완료 작업은 행을 제거한다 — [포트폴리오 행의 추가·제거](../../wf-implement/SKILL.md#7-작업-기록과-저장-위치) |
| L9 | 파일 12KB 초과(경고) | 가장 긴 항목부터 변환표를 적용한다. 검증 표의 증거는 출력 대신 링크로 둔다 |
