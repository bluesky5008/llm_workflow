# wf-doc 경계 소유권 표

[wf-doc 워크플로우 스킬과의 역할 경계](../SKILL.md#워크플로우-스킬과의-역할-경계)가 소유하는 중첩 기능별 소유권 표다. 본문의 경계 적용 규칙(항상 적용)은 SKILL.md에 있고, 이 문서는 **어느 기능을 누가 소유하는지** 판단이 필요할 때 읽는다. 경계를 바꿀 때는 이 표를 고치고 상대 스킬의 요약이 여전히 맞는지 확인한다.

## wf-design과의 경계

> **정본:** 이 표가 wf-design ↔ wf-doc 경계의 정본이다. 상대 스킬에는 [요약](../../wf-design/SKILL.md#wf-doc과의-역할-경계)만 두며, 적용 규칙은 [본문](../SKILL.md#wf-design과의-경계)에 있다.

| 중첩 영역 | wf-design 소유 | wf-doc 소유 |
|---|---|---|
| 적용과 산출물 | [워크플로우 적용 여부](../../wf-design/SKILL.md#1-적용-시점), [필요한 산출물과 저장 구조](../../wf-design/SKILL.md#6-산출물) | 선택된 산출물을 문서 유형과 템플릿에 매핑 |
| 요구사항·설계 | [요구사항, 인수 조건 및 설계의 의미와 충분성](../../wf-design/SKILL.md#42-요구사항-정의) | 요구사항·설계 문서의 절 구조, 머리말과 링크 |
| ADR | [ADR 필요성, 대안, 결정, 결과 및 승인](../../wf-design/SKILL.md#44-설계-결정-기록) | ADR Markdown 템플릿, 상태 표기, 대체 문서 링크 |
| DCR | [변경 분류, 영향 분석, 재승인과 새 기준선](../../wf-design/references/design-change.md) | DCR Markdown 템플릿, 변경 이력과 상호 링크 |
| 승인·기준선·상태 | [누가 무엇을 언제 승인하며 어떤 기준선이 유효한지](../../wf-design/SKILL.md#8-사용자-승인-관문) | 승인 결과 필드, 상태값 표기, 날짜와 변경 이력 형식 |
| 식별자 | 어떤 대상에 ID가 필요하고 언제 새 ID·기준선을 발행하는지 | 작업·문서·항목 ID와 기준선의 문자열 문법 및 표시 형식 |
| 추적성 | [어떤 요구사항·설계·ADR·DCR·승인·검증이 연결되어야 하는지](../../wf-design/SKILL.md#61-문서-관계와-추적-범위) | 결정된 관계를 표현하는 식별자, 하이퍼링크·역방향 링크와 추적표 |
| 승인 요청과 기록 | 사용자에게 승인·재승인을 요청하고 응답의 의미·효력을 결정 | 영구 승인 기록의 템플릿과 승인 대상·근거 링크 형식 |
| 인계 | [Workflow 2로 넘길 내용과 인계 가능 여부](../../wf-design/SKILL.md#7-완료-조건) | 인계 블록의 필드, 문서 링크와 재개 지점 형식 |
| 품질 판단 | 요구사항·설계의 정확성, 완전성, 실현 가능성 | 문서 구조의 일관성, 링크 유효성, 기계 판독성과 가독성 |

## wf-implement와의 경계

> **정본:** 이 표가 wf-implement ↔ wf-doc 경계의 정본이다. 상대 스킬에는 [요약](../../wf-implement/SKILL.md#wf-doc과의-역할-경계)만 두며, 적용 규칙은 [본문](../SKILL.md#wf-implement와의-경계)에 있다.

| 중첩 영역 | wf-implement 소유 | wf-doc 소유 |
|---|---|---|
| 적용과 산출물 | [계획·작업 기록·검증·완료 보고의 필요 여부, 저장 위치와 필수 내용](../../wf-implement/SKILL.md#wf-doc과의-역할-경계) | 선택된 산출물을 `plan`, `work-log`, `verification`, `completion` 유형과 템플릿에 매핑 |
| 구현 계획 | [작업 분할, 순서, 의존성, 위험, 완료 조건과 상태 전이](../../wf-implement/SKILL.md#32-계획-수립) | 계획 Markdown 구조, `TASK-NN` 표기와 문서 링크 |
| 작업 기록 | 결정과 이유, 발견, 검증 결과, 차단 요인, 갱신 시점과 재개에 필요한 사실 | 작업 로그의 필드, 시간순 표현, 증거 링크와 재개 지점 형식 |
| 검증 | [테스트·명령·환경 선택과 실행, 결과 판정과 실패 분류](../../wf-implement/SKILL.md#34-검증) | 검증표, `VER-NN` 표기, 결과와 증거 링크 형식 |
| 완료 | [완료·부분 완료·차단 판단과 통합 상태](../../wf-implement/SKILL.md#5-완료-조건) | 완료 보고서의 절 구조와 문서 상태 표기 |
| 상태 | 작업 상태 전이와 최종 구현 결과의 의미 | 문서 상태 및 작업·결과 상태값을 기록하는 위치와 표기 |
| 추적성과 인계 | 어떤 기준선·작업·검증이 연결되는지, 실제 완료·미완료·위험·재개 조건 | 식별자, 하이퍼링크·역방향 링크, 추적표와 인계 블록 형식 |
| 코드·API·운영 문서 | 구현과 일치하는 기술적 내용 | 워크플로우 기록의 공통 포맷만 소유하며 제품별 문서 템플릿을 대체하지 않음 |
| 품질 판단 | 구현 정확성, 검증 충분성, 통합과 완료 여부 | 문서 구조, 필수 필드, 식별자, 하이퍼링크와 기계 판독성 |
