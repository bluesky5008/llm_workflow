# 대화형 승인 요청 — 구성과 분량

[wf-design §8 사용자 승인 관문](../SKILL.md#8-사용자-승인-관문)이 소유하는 승인 요청의 구성이다. 승인의 효력과 응답별 상태 전이는 본문이 정하고, 이 문서는 **사용자에게 무엇을 얼마나 보여 주는지**와 승인 기록의 인용 규칙을 정한다. 결정은 [REQ-DESIGN-approval-gate](../../../docs/work/20261026-approval-gate/req-design.md) FR-07·FR-08이 정본이다.

## 1. 한 화면 요약

대화형 승인 요청은 한 화면(30줄 목표)으로 구성하고 나머지는 산출물 링크로 넘긴다.

- **사용자가 고를 결정:** 미해결 질문마다 선택지와 권장안
- **주요 위험:** 승인 후에도 남는 것
- **남은 질문:** 승인과 별도로 열려 있는 것
- **산출물 링크:** 요구사항·설계·ADR·DCR 문서

목표·범위·핵심 요구사항·설계 요약·주요 결정·가정·승인 대상 산출물은 승인 요청의 필수 내용이며, **요약 한두 줄 또는 문서 링크**로 충족한다. 문서에 있는 내용을 요청에 다시 옮겨 적지 않는다. 마지막에 이 요구사항과 설계를 구현 기준선으로 승인할지 명시적으로 묻는다.

## 2. 규모별 축소

- 경량 경로: 승인 요청이 없다([경량 경로](lightweight-path.md)).
- 요구사항·설계를 합친 작은 작업: 결정 표 중심으로 묻는다.

## 3. 형식

대화형 승인 요청은 승인 상호작용의 필수 내용이지 영구 문서의 Markdown 포맷이 아니다. 요구사항·설계 문서와 영구 승인 기록의 절 구조는 wf-doc의 [요구사항](../../wf-doc/references/templates.md#요구사항-requirements), [설계](../../wf-doc/references/templates.md#설계-design), [승인 기록](../../wf-doc/references/templates.md#승인-기록-approval) 템플릿을 따른다. 승인 요청을 파일로 보존할 때도 wf-doc의 `approval` 문서 유형을 적용한다.

## 4. 승인 기록의 응답 인용

승인을 기록할 때는 사용자 응답을 따옴표로 인용한다(예: `응답: Q-01 "(A)", "승인"`). 승인 게이트는 기준선 문서의 상태와 함께 `## 승인 기록`의 이 인용을 읽어 승인 여부를 판정한다. 승인 기록은 사용자가 승인 요청에 응답한 직후에만 쓴다 — 응답 없이 상태를 `approved`로 바꾸거나 인용을 만들지 않는다.
