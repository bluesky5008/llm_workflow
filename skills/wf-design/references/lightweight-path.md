# 경량 경로 — 판단 조건과 기계 조건

[wf-design §1 적용 제외 — 경량 경로](../SKILL.md#적용-제외--경량-경로)가 소유하는 판정의 본체다. Workflow 1의 산출물을 생략하고 Workflow 2를 축약할 수 있는지 판단하는 조건, 생략하지 않는 것, 승인 게이트와의 관계를 정한다. 결정과 대안은 [REQ-DESIGN-approval-gate](../../../docs/work/20261026-approval-gate/req-design.md) FR-04·FR-06과 [ADR-018](../../../docs/work/20261026-approval-gate/ADR-018-승인-게이트-판정.md)이 정본이다.

## 1. 판단 조건

다음을 모두 만족해야 한다.

- 제품 동작, 공개 인터페이스, 데이터 모델, 보안 정책에 영향을 주지 않는다.
- 변경이 국소적이고 쉽게 되돌릴 수 있다.
- 새로운 설계 결정이나 대안 비교가 필요 없다.

예: 오타·주석·로그 문구 수정, 원인이 명확한 단일 버그 수정, 기존 계약을 바꾸지 않는 테스트 보강, 기존 테스트의 [대장 편입](../../wf-implement/references/verification-depth.md#7-대장-편입)(테스트 무수정).

## 2. 기계 조건

판단 조건 앞에 다음을 확인한다. 하나라도 어기면 정식 경로다. 기계 조건은 **상한이지 허가가 아니다** — 통과해도 1절의 판단 조건을 그대로 적용한다.

| 조건 | 내용 |
|---|---|
| (a) 변경 규모 | 제품 코드 변경 파일(미추적 포함)이 5개 이하 |
| (b) 민감 파일 | 게이트 설정(`.claude/settings*.json` 등), 의존성 선언(`requirements*.txt`, `pyproject.toml`, `package.json`, `go.mod`, `Cargo.toml`, `*.csproj`, `pom.xml`, `build.gradle*` 등), 제품 코드 선언 `.wf-gate.json`을 바꾸지 않는다 |
| (c) 새 파일 | 새로 만드는 파일은 테스트 파일뿐이다(`test`/`tests` 디렉터리 또는 `test_*`·`*_test.*`·`*.test.*`·`*Tests.*`) |

제품 코드는 저장소 루트 아래 `docs/` 밖 전부다. 루트의 선택 선언 `.wf-gate.json`(`{"product": [glob…], "exclude": [glob…]}`, `exclude` 우선)이 이를 덮어쓴다.

## 3. 생략하지 않는 것

- 변경 범위 준수와 관련 없는 파일 보존
- 변경 위험에 맞는 검증 수행
- 결과와 남은 위험 보고

## 4. 승인 게이트와의 관계

경량 경로로 기록을 남기면 작업 기록 머리말을 `기준선: N/A — 경량 경로로 기준선 없음`([wf-doc 경량 경로 문서](../../wf-doc/SKILL.md#28-경량-경로-문서))으로 적는다. 승인 게이트(C층 훅)는 이 표지를 읽고, 표지가 있는 작업에는 2절의 기계 조건을 판정한다 — 표지만으로 통과하지 않는다. 기록을 남기지 않는 경량 작업은 열린 작업이 아니므로 게이트와 무관하다.

## 5. 정식 경로로의 전환

조건 충족 여부가 의심스러우면 정식 경로를 사용한다. 작업 도중 조건을 벗어나는 것이 확인되면 그 시점에 정식 경로로 전환한다.
