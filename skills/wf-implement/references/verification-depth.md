# 검증 시점·실행 집합·테스트 대장 전이

이 문서는 [wf-implement 검증](../SKILL.md#34-검증)이 소유하는 규칙의 표 부분이다. 3튜플 귀속·인용·실패 분류·관문의 의미는 본문 §2.4·§3.3~§3.6이 정의하고, 이 문서는 **어느 시점에 어느 집합을 실행하고 테스트 대장의 행이 어떤 조건으로 전이하는지**를 정한다. 본문과 다르면 본문을 우선하고 이 문서를 고친다. 대장의 형식은 [wf-doc 테스트 대장 템플릿](../../wf-doc/references/templates.md#테스트-대장-test-register)을 따른다.

원칙은 둘이다. 같은 테스트 묶음을 통과 후 다시 실행하는 것은 그 사이에 코드가 바뀐 경우에만 한다. 테스트를 지우는 쪽이 입증 책임을 진다.

## 1. 시점별 실행 집합

| 시점 | 실행 집합 | 조건 |
|---|---|---|
| TDD Red | 새 테스트 1개 | 항상 |
| TDD Green | 새 테스트 + 관련 행 | 항상 |
| Refactor 후 | 관련 행 | 코드가 바뀐 경우만 |
| [자체 리뷰](../SKILL.md#35-자체-리뷰) 후 | 리뷰로 수정한 파일의 관련 행 | 수정이 있을 때만 |
| TASK `completed` 전이 | 대장 `유지` 행 전량 | 항상. 이 TASK의 테스트를 등록하고 SHA를 기록 |
| [통합](../SKILL.md#36-통합) | 전체 테스트 스위트 1회 + `유지` 행 전량 + 변경 범위 뮤테이션([§5](#5-검증-결과-기록)) + 재정비 관문 | 작업당 1회. 전체 스위트를 실행하는 유일한 시점 |
| DCR 승인 | 재정비 관문(`대체` 전이) | DCR이 보호 스코프의 의미를 바꿀 때 |
| [세션 재개](../SKILL.md#31-현재-상태-재확인) | `유지` 행 전량 | 마지막 성공 SHA ≠ HEAD 또는 워킹트리에 미커밋 변경이 있을 때만. 같으면 인용 |

**관련 행**은 대장에서 `보호 스코프`가 변경 파일·심볼과 겹치는 행이다. 대장에 없는 파일은 "관련 행 없음"으로 적고, 통합의 전체 스위트가 최종 그물이 된다. 전량 실행은 `completed` 전이·통합·재개 세 시점 밖에 두지 않는다 — 대장이 커질수록 작업당 비용이 비례해 늘기 때문이다. `보호 스코프`가 `미확정`인 행은 관련 행 판정에서 빼고 전량 시점에만 돌린다. 단 통합의 변경 범위 뮤테이션에서는 거짓 survived를 막으려고 관련 행에 넣는다.

## 2. 상태와 전이

| 상태 | 의미 | 진입 조건 | 허용 시점 |
|---|---|---|---|
| `유지` | 이후 모든 작업에서 통과해야 하는 의무 | 같은 SHA에서 2회 통과(Green 1회 + `completed` 전이 1회). 둘 사이에 코드가 바뀌었으면 전이에서 2회 실행 | TASK `completed` 전이, 편입([§7](#7-대장-편입)) |
| `대체` | 기준선 변경으로 의미가 바뀐 테스트를 새 행이 이어받음 | DCR 승인. 대체 행 ID 기록 | DCR 승인 |
| `병합` | 같은 보호 스코프를 더 넓은 행이 흡수 | 관문 4조건 + 중복 증거. 흡수 행 ID 기록 | 재정비 관문, 독립 재정비 작업([§8](#8-독립-재정비-작업)) |
| `격리` | 통과를 신뢰할 수 없거나 기존 실패라 완료 판정·게이트에서 제외하되 계속 실행 | 같은 SHA에서 결과 불일치, 실행 환경 원인으로 통과를 확인할 수 없음, 또는 편입 2회 실패. 수정 후속 작업 기록 | 즉시 |
| `폐기` | 보호 스코프 소멸·동어반복·신호 없음으로 의무 소멸 | 관문 4조건 전부 + 사용자 승인 | 재정비 관문, 독립 재정비 작업([§8](#8-독립-재정비-작업)) |

`격리` 행은 통합에서 실행해 결과만 검증 결과에 적고 완료 판정에는 넣지 않는다. 진입 조건을 채우지 못한 새 테스트는 등록하지 않고 다음 `completed` 전이에서 다시 판정한다. 전이된 행은 삭제하지 않고 상태·분류·이유·일시를 남긴다. `유지` 행을 통과시키려고 테스트를 수정·제외·삭제하는 것은 [§3.4](../SKILL.md#34-검증) "인수 조건을 완화하지 않는다"의 위반이다. 의미 충돌은 [§6](#6-명세테스트-충돌)의 출구를 쓴다. 기존 행을 새로 쓴 테스트로 바꾸는 재생성은, 그 행이 실패 중이면 §6을, 통과 중이면 `병합`으로 보고 [재정비 관문](#3-재정비-관문)의 4조건을 거친다 — 진행 중에는 하지 않는다. 같은 SHA에서 결과가 엇갈리면 순서 의존(비정렬 컬렉션·공유 상태·실행 순서)을 먼저 의심하고, 진단 결과를 `격리`의 후속 작업 기록에 적는다. 회귀 사건(이전 성공 → 실패)을 `기존 실패`로 재분류하려면 마지막 성공 SHA보다 앞선 실패 증거가 있어야 한다.

**`리팩터`**는 `유지` 행의 테스트를 고쳐서 `유지`로 두는 처분이며 상태값이 아니다. 행의 `상태`는 `유지` 그대로, `비고`에 `리팩터(분류, 일시)`, 작업 기록 `### 테스트 대장 변경`에는 `유지 → 유지(리팩터)`로 적는다. 분류는 [§4](#4-테스트-작성-체크리스트)의 냄새 이름, `대역 교체`(mock→fake), `통합`(한 행 안의 케이스를 합치되 각 케이스의 단언이 보존됨 — 행 간 흡수는 `병합`) 중 하나와 사유다. 경계는 **단언 보존**이다 — 수정 전 단언마다 같거나 더 강한 단언이 수정 후에 남으면 `리팩터`(강화 허용), 단언을 없애거나 약화하거나 기대값을 바꾸면 위의 재생성이며 `병합`으로 4조건을 거친다. 증거는 같은 제품 코드 SHA에서 수정 전·후 모두 통과 + kill 집합 비감소(도구 또는 수동 뮤턴트 표본 — 수정 전 kill을 수정 후에도 전부 kill) 또는 단언 대조(수정 전 단언마다 같거나 더 강한 단언이 수정 후에 있음). 유일성 조건은 없다(행이 남는다). [독립 재정비 작업](#8-독립-재정비-작업) 안에서만 허용하며, 기능 작업 진행 중의 기존 테스트 수정 금지([§3.3](../SKILL.md#33-구현))는 그대로다. 수정 전에 실패 중인 행은 대상이 아니다([§6](#6-명세테스트-충돌)) — [주의 ④](../SKILL.md#주의--자주-틀리는-것)의 「통과시키려는 수정」과 다르다.

## 3. 재정비 관문

시점은 통합과 DCR 승인, 그리고 [독립 재정비 작업](#8-독립-재정비-작업)의 배치다. 순서:

1. 변경이 닿은 보호 스코프의 행을 **Breaking**(코드 변경 후 실패 → 수정), **Stale**(통과하지만 바뀐 동작을 더 이상 검증하지 않음 → `대체` 또는 폐기 후보), **Missing**(새 동작에 필요한데 없음 — 통합 뮤테이션의 survived 포함([§5](#5-검증-결과-기록)) → 추가)으로 분류한다. Stale은 실행 신호가 없으므로 이 문항이 유일한 트리거다.
2. (통합에서만) 커버리지 도구가 있으면 변경이 닿은 행과 `미확정` 행의 `보호 스코프`를 행별 커버리지로 다시 계산해 기존 값과의 차이를 `### 테스트 대장 변경`에 적는다. 대장 반영은 순서 4의 승인 뒤다. 도구가 없으면 생략하고 이유를 적는다.
3. 폐기·병합 후보마다 아래 4조건을 검토한다. 하나라도 미달이면 `유지`.
4. 제안을 작업 기록 `### 테스트 대장 변경`에 적고 완료 보고 관문에서 일괄 승인받은 뒤 대장과 `## 재정비 기록`을 갱신한다. 변경이 없어도 재정비 기록에 1행을 남긴다.

| 조건 | 내용 |
|---|---|
| 분류 명시 | `중복`(같은 보호 스코프를 다른 행이 덮음) · `동어반복`(구현을 바꿔도 통과) · `자명`(의미 있는 단언 없음) · `신호 없음`(보호 스코프가 바뀌어도 실패할 수 없음) · `고아`(보호 스코프의 파일·심볼이 현재 트리에 없음) 중 하나와 사유 |
| 증거 | 중복: 낼 수 있는 가장 강한 것 — ① 뮤테이션 kill 집합 보존(흡수 행이 흡수되는 행의 kill을 전부 kill, 수동 뮤턴트 가능) ② 커버리지 겹침 + 단언 대조 ③ 단언 대조. 겹침은 후보 신호이며 단독 근거가 아니다. 동어반복·자명: 구현을 바꿔도 통과하는 실험. 고아: `git ls-files`·심볼 검색 결과 |
| 유일 검증 아님 | 그 행이 어떤 인수 조건의 유일한 검증이 아니다. 유일하면 대체 행을 먼저 등록. 인수 조건이 없는 행은 순서대로 판정한다 — ① 뮤테이션: 다른 행이 죽이지 못하는 뮤턴트를 이 행이 죽이면 유일(도구가 없으면 보호 스코프에 수동 뮤턴트 1~3개) ② [역공학](../../wf-design/references/reverse-engineering.md) 10단계의 RR 항목에 연결돼 있으면 그 항목의 다른 검증 유무 ③ 단언 대조: 흡수 행이 이 행의 단언 전부를 같거나 더 강하게 가지면 유일 아님. 커버리지 지배·유일 라인 0은 후보 선별 신호이며 단독 근거가 아니다. 어느 증거도 대지 못하면 `유지`. `보호 스코프`가 `미확정`인 행은 ①·③을 쓸 수 없어 `고아` 외의 전이가 불가하다 — 스코프부터 채운다 |
| 사용자 승인 | 완료 보고 관문의 일괄 응답. 독립 재정비 작업은 [§8](#8-독립-재정비-작업)의 계층 — `고아`는 목록 일괄, 판단 분류는 배치별 행 단위 |

"한 번도 실패한 적 없음"은 단독 사유가 아니다. 그 테스트는 무가치가 아니라 하중을 받고 있을 가능성으로 취급한다.

## 4. 테스트 작성 체크리스트

[§2.4](../SKILL.md#24-최소-구현-원칙--ponytail-full-모드)의 작성 기준을 리뷰할 때 다음 냄새를 찾는다. 하나라도 있으면 고친 뒤 등록한다.

| 냄새 | 징후 |
|---|---|
| Assertion Roulette | 설명 없는 단언이 여러 개라 어느 것이 실패했는지 알 수 없음 |
| Magic Number | 의미를 알 수 없는 리터럴 기대값 |
| Lazy Test | 여러 테스트가 같은 대상을 같은 방식으로 호출 |
| Conditional Logic | 테스트 안의 if·for로 기대 결과가 갈림 |
| Empty / Trivial | 단언이 없거나(출력만 하는 Print-only 포함) non-null·true 확인뿐 |
| Duplicate Assert | 같은 조건을 반복 단언 |
| Over-mock | 대상 밖 협력자까지 대역으로 바꿔 상호작용만 단언 |
| Mirror | 기대값을 구현과 같은 식·코드로 계산 |

파서·직렬화·변환처럼 불변식(왕복·멱등·순서 무관)이 분명한 순수 로직은 예제 테스트 대신 또는 함께 속성 기반 테스트를 고려한다. 선택이며 의무가 아니다. 도구가 없으면 새 의존은 [§2.4](../SKILL.md#24-최소-구현-원칙--ponytail-full-모드) 결정 사다리로 판단하고, 생성은 고정 시드로 결정적으로 둔다.

## 5. 검증 결과 기록

작업 기록 `## 검증 결과`의 결과 요약은 여섯 필드를 고정으로 적는다. 형식은 [wf-doc 합본 템플릿](../../wf-doc/references/templates.md#작업-기록-work-log)이 정한다.

| 필드 | 내용 |
|---|---|
| 총계 | N (성공 N / 실패 N / 미수행 N) |
| 기준 | 커밋 SHA · 워킹트리 clean 또는 dirty |
| 명령 | 묶음별 실제 실행 명령, 묶음마다 1줄 |
| 커버리지 | 도구가 내는 지표만(라인·분기·함수). 없으면 `N/A — 이유` |
| 뮤테이션 | killed N / survived N / 동치 N · 도구명 또는 `수동`. 대상이 없으면 `N/A — 이유` |
| 산출물 | 형식명과 경로. 없으면 `없음` |

산출물은 세 층이다. **권장** — 러너가 내장 지원하면 결과는 JUnit XML, 커버리지는 Cobertura XML 또는 LCOV. **허용** — 내장 지원이 없으면 러너의 네이티브 기계 판독 형식(JaCoCo XML, Go coverprofile, TRX, NUnit XML, TAP)을 그대로 두고 형식명을 적는다. 변환 의무는 없다. 산출물은 생성물이므로 커밋하지 않는다.

**변경 범위 뮤테이션**은 통합에서 작업당 1회, 작업 착수 SHA 이후 바뀐 코드 파일(문서·테스트 제외)에만 한다. 뮤턴트를 하나씩 적용해 그 파일의 관련 행(없으면 전체 스위트)을 실행하고 복원한다. 도구는 저장소에 이미 있을 때만 쓰고, 없으면 기존 테스트를 읽은 상태에서 실제 결함형(경계·분기 반전·반환값) 수동 뮤턴트 1~3개를 쓴다 — 새 의존은 [§2.4](../SKILL.md#24-최소-구현-원칙--ponytail-full-모드) 결정 사다리로 판단한다. 뮤턴트는 테스트 파일을 바꾸지 않고, 적용 전 `git hash-object` 값과 복원 후 값이 같음을 확인하며, 커밋하지 않는다. 뮤턴트로 인한 실패는 kill이며 검증 표의 `실패`, 회귀 사건, [§6](#6-명세테스트-충돌) 충돌이 아니다. survived와 동치는 위치·변이·이유를 `### 테스트 대장 변경`에 Missing 후보로 적어 [재정비 관문](#3-재정비-관문)의 입력으로 쓴다. 목표 비율은 두지 않는다 — 결정은 [ADR-017](../../../docs/work/20261026-test-quality/ADR-017-변경-범위-뮤테이션.md). 검증 표의 `분류` 열은 결과가 `실패`일 때 §3.4의 네 가지 중 하나, 그 외 `—`이며 증거 열에는 SHA와 명령이 있어야 인용할 수 있는 기록이다.

설계 침식 점검([review-checklist](review-checklist.md#요구사항과-설계)) 결과는 결과 요약 필드를 늘리지 않고 자체 리뷰 기록(수행 기록)에 적는다.

## 6. 명세·테스트 충돌

`유지` 행이 실패하고, 통과시키려면 테스트 또는 인수 조건의 의미를 바꿔야 하면 구현을 멈추고, 충돌을 작업 기록 인계 절의 `차단 요인`에 기록하고, 사용자에게 다음 중 판정을 요청한다.

| 판정 | 의미 | 처리 |
|---|---|---|
| (a) 테스트 오류 | 기준선은 그대로이고 테스트가 틀렸다 | Breaking으로 `### 테스트 대장 변경`에 적고 [재정비 관문](#3-재정비-관문)에서 수정한다 |
| (b) 요구사항 변경 | 기준선의 의미가 바뀌어야 한다 | [wf-design 설계 변경](../../wf-design/references/design-change.md)으로 DCR을 올린다. 승인되면 해당 행을 `대체`로 전이한다 |

테스트를 고쳐 통과시키는 것도, 인수 조건을 다시 읽어 통과시키는 것도 이 절차 밖에서는 하지 않는다.

테스트를 쓰기 전에 인수 조건이 둘 이상으로 읽히면 이 표가 아니라 [wf-design DCR 시작 조건](../../wf-design/references/design-change.md#2-변경-시작-조건)으로 멈춘다.

## 7. 대장 편입

워크플로우 적용 전부터 있던 테스트를 삭제·수정 없이 대장에 올려 가드의 보호 아래 두는 절차다. 결정은 [ADR-023](../../../docs/work/20261028-legacy-onboarding/ADR-023-레거시-테스트-대장-편입.md).

- **대상:** 어떤 대장 행의 `테스트 파일`에도 걸리지 않는 기존 테스트. 작업 중 진입 조건 미달로 등록하지 않은 새 테스트([§2](#2-상태와-전이))는 대상이 아니다.
- **시점과 형태:** 대상이 있는 저장소는 기능 작업 전에 독립 편입 작업을 한다 — [경량 경로](../../wf-design/references/lightweight-path.md) 허용. [§3.1 재확인](../SKILL.md#31-현재-상태-재확인)에서 대상을 발견하면 편입부터 한다. 2회 실행 전에 편입 작업 기록 골격을 커밋해 워킹트리를 clean으로 둔다.
- **행 단위:** 처음엔 파일·디렉터리·러너 단위로 거칠게 둔다. `테스트 파일`은 필수다. `보호 스코프`는 커버리지 도구가 있으면 행별 커버리지로 채우고, 없으면 `미확정` 또는 근거를 적은 손 기입이다. 도구는 저장소마다 고르며(예: coverage.py·JaCoCo·Go coverprofile) 특정 도구를 요구하지 않는다.
- **판정:** 같은 SHA·clean 워킹트리에서 행마다 2회 실행한다. 테스트는 수정·삭제·skip하지 않는다.

| 2회 결과 | 상태 | 마지막 성공 | 비고 |
|---|---|---|---|
| 둘 다 통과 | `유지` | 그 SHA | — |
| 불일치 | `격리(불일치, <후속>)` | `없음 — 편입 2회 불일치` | — |
| 둘 다 실패 | `격리(기존 실패, <후속>)` | `없음 — 편입 2회 실패` | 실패 건수와 대표 메시지 |

- **부분 실패 분리:** 행의 일부 테스트만 실패·불일치하면 그 테스트만 별도 `격리` 행으로 분리하고, 나머지는 러너의 **명령줄** 제외 옵션(예: pytest `--deselect`)을 붙인 명령으로 같은 SHA에서 2회 다시 실행해 판정한다. 설정 파일은 바꾸지 않는다.
- **제외의 수명:** 제외는 편입 시점에만 허용되는 예외이며 제외 대상과 `격리` 행은 1:1이다. 제외 대상은 아직 `유지`가 아니고 `격리` 행으로 등록되므로 [주의 ④](../SKILL.md#주의--자주-틀리는-것)·[§3.3](../SKILL.md#33-구현)의 제외 금지에 해당하지 않는다. 편입 뒤에는 §2 `격리` 진입 조건(불일치·환경)을 채울 때만 제외를 더하고 그 테스트를 `격리` 행으로 분리해 1:1을 유지한다 — 실패를 피하려는 제외는 주의 ④ 위반이다. `격리` 해제는 원 행 명령에서 제외를 뺀 명령이 같은 SHA에서 2회 통과할 때다. 원 행을 그 명령과 SHA로 갱신하고, `격리` 행은 재정비 관문에서 `병합(→원 행)`으로 전이한다.
- **파이프 금지:** 대장 표의 모든 셀(명령·비고의 실패 메시지 포함)에 파이프 문자를 쓰지 않는다 — 판독기가 행을 파이프로 나눈다. 다른 문자로 바꾸거나 요약한다.
- **기록:** `## 재정비 기록`에 시점 `편입` 1행 — 행 수, `유지`·`격리` 건수, 제외 목록 수, 2회 실행 시간, `승인` 칸 `N/A — 경량 경로(편입)`.

## 8. 독립 재정비 작업

대장 일부·전부를 범위로 테스트를 정리하는 작업이다. 결정은 [ADR-024](../../../docs/work/20261029-legacy-cleanup/ADR-024-독립-재정비-작업과-리팩터-표기.md). 통합·DCR 승인에 딸린 [재정비 관문](#3-재정비-관문)이 변경이 닿은 행만 다루는 것과 달리 승인된 범위의 행을 다루고, 승인은 배치마다 행 단위로 받으며 대장 반영은 배치 승인 뒤다 — 이 예외는 [wf-implement §3.6](../SKILL.md#36-통합)이 둔다.

- **형태:** 정식 경로 작업의 한 종류다([경량 경로](../../wf-design/references/lightweight-path.md) 불가). 요구사항 문서는 `## 범위` 아래 `### 대상 TST 범위·배치·성공 기준` 절에 (i) 대상 TST 행 목록 또는 선정 규칙 — 배치 중 행 분리로 생긴 새 행은 원 행의 범위에 속한다 (ii) 배치 분할 — 배치 하나 = TASK 하나, 모듈·디렉터리 단위와 순서 (iii) 성공 기준 5항(아래 (g))과 저장소별 목표치 (iv) 증거 수단(뮤테이션·커버리지 도구 유무, 없을 때의 수동 뮤턴트·단언 대조)을 적는다. 사용자가 승인한 이 절이 배치 승인 범위의 정본이며 plan.md는 범위를 넓히지 못한다. 범위 밖 행은 DCR. 절의 요구는 [wf-design §4.2](../../wf-design/SKILL.md#42-요구사항-정의), 형식은 [wf-doc 요구사항 템플릿](../../wf-doc/references/templates.md#요구사항-requirements).
- **제품 코드 동결:** 테스트 코드·대장·문서만 바꾼다. 테스트 코드는 대장 `테스트 파일` 패턴에 걸리는 파일과 [경량 경로 기계 조건 (c)](../../wf-design/references/lightweight-path.md#2-기계-조건)의 테스트 파일 정의에 맞는 파일이다. 그 밖의 `docs/` 밖 변경은 작업 착수 SHA 대비 diff 0이어야 하며 배치마다 확인한다. 제품 코드 변경이 필요해지면 그 행을 `유지`로 두고 별도 작업으로 넘긴다. 통합의 변경 범위 뮤테이션은 `N/A — 제품 코드 변경 0`.
- **배치 절차:** 배치 TASK마다 순서대로.
  - (a) 착수 측정 — 앞 배치의 반영을 커밋해 워킹트리를 clean으로 두고 그 SHA를 **배치 착수 SHA**로 기록한다. `유지` 행 전량 통과(3튜플 인용 가능), 실행 시간, `격리` 수, 배치 행의 kill 집합(도구 있을 때) 또는 단언 목록, 대상 행의 `보호 스코프` 확정 — `미확정`이면 커버리지 재계산 또는 근거 있는 손 기입으로 채운다.
  - (b) 후보 선별 — 커버리지 지배·유일 라인·[§4 냄새](#4-테스트-작성-체크리스트)는 신호일 뿐 근거가 아니다.
  - (c) 행별 판정 — `폐기`·`병합`은 [§3](#3-재정비-관문) 4조건, `리팩터`는 [§2](#2-상태와-전이)의 조건(유일성 조건 없음). 묶음 안 개별 테스트만 대상이면 먼저 새 행으로 분리하고 원 행 ID를 새 행 비고와 대장 변경 절에 적는다 — 분리 행은 원 행 범위 안이며 DCR 대상이 아니다.
  - (d) 기록 — 제안 전부를 작업 기록 `### 테스트 대장 변경`에 행 ID와 함께 적는다. Stop 게이트는 이 절을 기록 단위로 읽는다.
  - (e) 배치 승인 — 아래 승인 계층.
  - (f) 반영 — 승인된 행만 대장에 전이·`리팩터` 비고 기입. 거부·미응답 행은 `유지`로 두고 `리팩터`는 수정을 되돌린다.
  - (g) 종료 측정 — `유지` 전량 실행·SHA 갱신(TASK `completed` 규칙), 재정비 기록 1행, 성공 기준 전후값: (1) 배치 행의 kill 집합 합 ≥ 착수 시(도구 없으면 수동 뮤턴트 표본 전부 kill 또는 단언 대조로 단언 보존) (2) `유지` 전량 통과 (3) 제품 코드 diff 0 (4) 전이·`리팩터` 행마다 분류·증거·승인 기록 (5) 실행 시간·`격리` 수 전후값. 미달이면 TASK를 `completed`로 바꾸지 않는다 — (1)(4) 미달은 그 행을 `유지`로 복원, (2) 실패 원인이 전이 행이면 그 행 복원·아니면 배치의 테스트·대장 변경 전부를 배치 착수 SHA로 되돌림(앞 배치의 승인·반영은 보존), (3) 제품 코드 변경을 배치 착수 SHA로 되돌리고 전이는 유지, (5) 목표치 미달은 승인된 전이를 유지한 채 사용자에게 목표치 변경(DCR) 또는 배치 되돌림을 묻는다.
  - (h) 흡수 행 보호 — `병합(→TST-xx)`의 흡수 행은 같은 작업의 어느 배치에서도 `폐기`·`병합` 대상이 될 수 없다.
- **승인 계층:** `고아` 행은 배치 목록으로 일괄 승인(응답 한 번). 판단 분류(`중복`·`동어반복`·`자명`·`신호 없음`·`리팩터`)는 배치별 행 단위 — 요청은 행마다 분류·증거·유일성 판정을 한 줄로 적은 표, 응답은 행 ID를 특정한다(「전부」·「X 제외 전부」도 행 전부에 대한 응답으로 기록). 응답 인용을 `### 테스트 대장 변경` `승인` 열과 재정비 기록 `승인` 칸에 `배치 N 승인(YYYY-MM-DD, "응답 인용")`로 적고 승인 뒤에만 대장을 바꾼다. 승인 범위는 요구사항 문서의 대상 TST 범위를 넘지 못한다. 게이트는 기록을 보지 승인을 보지 않으므로, 대장 반영을 승인 뒤로 묶는 것이 사후 감사의 근거다.
- **기록:** `## 재정비 기록`에 배치마다 시점 `재정비 작업` 1행 — 행 수, 분류별 건수, `리팩터` 수, 실행 시간·`격리` 수 전후값, 승인. 작업 통합의 재정비 관문은 그와 별도로 시점 `통합` 1행(변경 없음이라도).
