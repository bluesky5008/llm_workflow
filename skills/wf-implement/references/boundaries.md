# wf-implement 경계 소유권 표

[wf-implement의 wf-design과의 역할 경계](../SKILL.md#wf-design과의-역할-경계)가 소유하는 중첩 영역별 소유권 표다. 본문의 경계 적용 규칙(항상 적용)과 반환 흐름은 SKILL.md에 있고, 이 문서는 **어느 영역을 누가 소유하는지** 판단이 필요할 때 읽는다.

> **정본:** 이 표가 wf-design ↔ wf-implement 경계의 정본이다. 상대 스킬에는 [요약](../../wf-design/SKILL.md#wf-implement와의-역할-경계)만 두며, 경계를 바꿀 때는 이 표를 고치고 그 요약이 여전히 맞는지 확인한다.

| 중첩 영역 | wf-design 소유 | wf-implement 소유 |
|---|---|---|
| 문제·범위·성공 기준 | [요구사항, 인수 조건과 비기능 목표의 의미](../../wf-design/SKILL.md#42-요구사항-정의) | 승인된 항목을 작업과 검증에 빠짐없이 매핑 |
| 저장소 조사 | 설계를 결정하기 위한 현재 동작·제약·영향 조사 | [계획 직전 기준선과 저장소 상태의 변경·실행 가능성 재확인](../SKILL.md#31-현재-상태-재확인) |
| 구조와 계획 | [아키텍처, 책임, 인터페이스, 데이터와 품질 속성](../../wf-design/SKILL.md#43-sw-설계) | [작업 순서, 변경 파일, 의존성, 테스트와 롤백 계획](../SKILL.md#32-계획-수립) |
| 프로토타입과 제품 코드 | 가설·범위·폐기 여부가 명시된 설계 실현 가능성 프로토타입 | 승인된 기준선을 충족하는 제품 코드와 유지할 테스트 |
| 구현 중 결정 | 제품 동작, 공개 계약, 데이터, 보안, 주요 책임과 장기 결정 | 승인 범위 안의 되돌릴 수 있는 내부 구현 세부사항 |
| DCR·ADR | [변경 분류, 대안·영향 분석, 재승인과 새 기준선](../../wf-design/references/design-change.md) | 차이를 감지하고 영향받는 구현을 보류하며 증거·현재 코드 상태·초안을 인계 |
| 검증 | 검증할 동작, 인수 조건과 품질 목표, 검증 전략 | [구체적인 테스트 선택·실행, 결과 분류와 증거 기록](../SKILL.md#34-검증) |
| 문서 | 요구사항·설계·ADR·DCR 기준선의 의미 | 작업 기록, 코드·설정·운영 문서 갱신과 구현 결과; 기준선 의미 변경은 wf-design으로 반환 |
| 승인과 실행 권한 | 설계 기준선의 승인·재승인과 효력 | 기준선 안의 로컬 구현 자율 진행; push·병합·배포·삭제는 별도 사용자 권한 필요 |
| 완료 | 승인된 구현 기준선을 발행하고 인계 가능 여부 결정 | [구현·검증·리뷰·통합의 완료와 증거](../SKILL.md#5-완료-조건) |
