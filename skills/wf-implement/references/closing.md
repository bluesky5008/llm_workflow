# 작업 종결 절차 — 구현 커밋과 종결 커밋

[wf-implement §7 아카이빙 시점](../SKILL.md#아카이빙-시점)이 소유하는 종결의 순서다. 작업을 `completed`로 종결하는 변경을 **커밋으로 남기는 작업**에 적용한다. 결정과 대안은 [ADR-016](../../../docs/work/20261025-plan-closing/ADR-016-작업-종결-커밋-규칙.md)이 정본이다. 커밋·push 자체의 실행 권한은 [§2.3](../SKILL.md#23-자율-진행과-승인)이 정한다.

## 1. 원칙

- **마지막 커밋이 완료다.** 종결에 필요한 문서 갱신은 전부 마지막 커밋 하나에 들어가고, 그 뒤에는 이 작업의 문서를 고치지 않는다.
- **자기 참조를 피한다.** 커밋은 자기 SHA를 담을 수 없고 push 결과는 push 전에 알 수 없다. 그래서 테스트 근거는 앞선 구현 커밋의 SHA로 적고, push 결과는 문서에 적지 않는다(정본은 원격 ref).
- **종결 커밋은 문서만 바꾼다.** 그래야 구현 커밋에서 잰 3튜플([§3.4](../SKILL.md#34-검증))이 종결 상태에도 그대로 성립한다.

## 2. 순서

| 단계 | 하는 일 | 확인 |
|---|---|---|
| ① 구현 커밋 | 완료 보고 관문에서 커밋·push 범위를 승인받은 뒤, 코드·테스트·진행 중 문서를 커밋한다. 작업 기록은 아직 `in-progress` | 승인 응답이 작업 기록에 있음 |
| ② clean 재실행 | 그 SHA에서 워킹트리 clean으로 대장 `유지` 행 전량을 실행한다 | 전량 통과. 실패하면 종결하지 않고 수정 후 ①부터 |
| ③ 종결 갱신 | 한 변경에서 모두 갱신한다 — 대장 `마지막 성공`(① SHA)·`## 재정비 기록`, plan(마지막 TASK `completed`, 머리말 `상태`, `## 요약`·`## 인계`, 최종 트리), 작업 기록(`completed`, 완료 보고, 인계 축약), `docs/status.md`(행 제거·트리 재생성), 추적표 결과 | 린트 2종 0 오류 |
| ④ 문서 전용 확인 | `git diff --name-only <① SHA>`의 결과가 전부 `docs/` 아래인지 본다 | 밖의 파일이 있으면 종결 커밋을 만들지 않는다 — 그 변경을 ①로 되돌려 다시 시작 |
| ⑤ 종결 커밋 | ③의 변경만 커밋한다 | — |
| ⑥ push | 승인된 경우 ①·⑤를 한 번에 push한다 | 이후 문서 변경 없음 |

## 3. 기록 규칙

- 완료 보고 `### 통합 상태`에는 "구현 커밋 `<① SHA>`, 이 종결 커밋과 함께 push 대상(승인 YYYY-MM-DD HH:MM)"처럼 **대상과 승인**만 적는다. "push했다"는 쓰지 않는다.
- push가 실패하거나 지연돼도 문서를 고치지 않는다. git으로 재시도한다.
- push 뒤 오류를 발견하면 이 작업의 문서가 아니라 새 작업 또는 [경량 경로](../../wf-design/SKILL.md#적용-제외--경량-경로)에서 고친다.

## 4. 커밋하지 않는 경우

- 구현 커밋이 승인되지 않으면 종결하지 않는다. 작업 상태는 `awaiting-approval`, 인계의 다음 행동은 "커밋 승인 대기"로 둔다. 커밋 없이 기록을 닫으면 대장 셀이 `+dirty`로 남고 닫힌 기록은 `### 테스트 대장 변경`의 근거가 되지 못해, 이후 회귀 판정이 그 작업의 테스트 변경을 위반으로 본다.
- git을 쓰지 않는 저장소는 ③의 종결 갱신을 한 변경에 모으는 것만 적용한다.
