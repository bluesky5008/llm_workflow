# 트리 렌더링 — 표기 어휘와 뷰

[wf-tree §7 렌더링](../SKILL.md#7-렌더링)이 소유하는 ASCII 표기의 세칙이다. 생성은 `scripts/render.py`가 하며, 이 문서는 스크립트가 정하지 못하는 것 — 표기의 의미, 완료 시점의 파생 규칙, 뷰의 용도, 손 렌더 시 지켜야 할 표기 — 을 정한다. 매체 선택과 생성 시점은 본문이 소유한다.

## 표기 어휘

- `[✓]`·`[▶]`·`[ ]`가 각각 `completed`·`in-progress`·`pending`에 대응한다. `approved`는 `[✓]`로, 그 밖의 상태(`blocked`·`on-hold`·`awaiting-approval`·`rejected`)는 `[ ]`로 그리고 상태 이름을 우측 주석에 적는다. OR-분기의 기각 대안은 `(기각)` 표기로 흐리게 보존한다.
- 승인·릴리스·전환 게이트는 ★로 표시한다. 제목이 `승인:`·`릴리스:`·`전환:`으로 시작하는 항목이 게이트다.
- 가지는 `├─ `·`└─ `로, 이어지는 깊이는 `│   `·`    `(4칸)로 그린다. 루트 라인은 `[작업] <작업-ID> — <제목>`(계획) 또는 `[포트폴리오] <ST-ID> — <제목>`(포트폴리오)이다. 자식 라인은 `[표시] <제목> (<ID>)`이며 포트폴리오에서는 `[표시] <작업-ID> <제목>`이다.
- 우측 주석은 라인 끝에 두고 좌측 내용과 점선 리더(` … `)로 구분하며 같은 형제 블록에서 열을 맞춘다. 순서는 `상태 이름` → 롤업 `(완료/전체)` → `⚠ blocked N` → `depends: …` → 완료 시점. 우측 주석이 없는 라인에는 리더를 그리지 않는다.
- 롤업 `(완료/전체)`는 그 노드 아래 항목(자손)의 완료 수와 전체 수다. 루트의 롤업은 목록 항목 전체를 센다. `blocked`는 롤업 배지 `⚠ blocked N`(자손 중 `blocked` 수)으로 표시한다. 롤업은 표시 전용이며 문서의 상태 필드를 바꾸지 않는다.
- `depends:`는 항목의 `의존성` 필드에서 `TASK-NN`·`TASK-NN~MM` 토큰만 뽑아 적는다. 토큰이 없으면(`없음`, 설명문) 주석을 생략한다.
- 완료 노드는 [완료 상태 보존](../SKILL.md#6-상태와-롤업)에 따라 기준선이 바뀌어도 되돌리지 않는다.
- `implement` 노드의 `test` 자식은 첫 자식으로 배치하고 `(선행)` 라벨을 붙인다. 부모-자식은 분해 관계이므로 테스트 선행성은 구조가 아니라 배치 순서와 라벨로 표현한다([wf-implement §3.3의 TDD 사이클](../../wf-implement/SKILL.md#33-구현) 반영). 스크립트는 목록 순서대로 그리므로 배치는 목록에서 한다.

## 완료 시점 표기

완료로 렌더되는 라인 — `[✓]` action item, 완료된 작업 노드, 접힌 완료 서브트리 롤업 — 은 우측 끝에 완료 시점(`YYYY-MM-DD HH:MM`)을 표기한다.

- 값은 항목 목록의 완료 필드([wf-doc plan 템플릿](../../wf-doc/references/templates.md#구현-계획-plan)의 `완료:` 필드)에서 파생한다. 포트폴리오는 완료 작업을 싣지 않으므로 작업 노드의 완료 시점은 없다. 트리에만 존재하는 시점을 만들지 않는다(단일 소스 원칙). 완료 판정과 필드 기입은 내용 소유자가 한다.
- 기존 우측 주석(작업 노드의 `completed (n/m)` 롤업, `depends:`)이 있으면 완료 시점을 그 뒤 라인의 마지막 요소로 둔다. 좌측 내용과는 점선 리더 또는 공백으로 구분하고 같은 형제 블록에서 열을 맞춘다.
- 접힌 완료 서브트리와 완료 작업 노드의 롤업 시점은 자식 완료 시점의 최댓값을 쓰는 표시 전용 파생값이다. 항목 자체에 완료 필드가 있으면(축약된 작업 등) 그 값을 우선한다.
- 완료 필드가 없는 완료 항목(규칙 신설 전 항목 등)은 시점 표기만 생략하고 렌더링을 계속한다. 자식 중 완료 필드가 없는 항목이 있으면 롤업 시점도 생략한다.

## 접기와 뷰

깊이 상한 안에서도 "전부 보여주되 전부 펼치지 않는다"를 적용한다.

1. **완료 서브트리 자동 접기** — 완료된 가지는 `[✓] 설계 단계 (4/4)` 한 줄로 요약한다. 펼침은 `all` 뷰를 요청할 때.
2. **활성 경로 중심 뷰(기본값)** — 루트→진행 중 노드 경로만 전체 깊이로 펼치고 나머지 가지는 깊이 1 요약.
3. **ASCII 필터** — 전체 / 진행 중 경로만 / 남은 항목만 / 특정 가지만.
4. **롤업 배지** — 접힌 가지에도 `(완료/전체)`와 `⚠ blocked N`을 병기해 상태 손실을 막는다.

| 뷰 | `--view` | 용도 |
|---|---|---|
| 활성 경로(기본) | `active` | 세션 재개 — "지금 어디"를 한눈에. 진행 중 노드의 조상·자손만 펼치고 완료 가지는 접는다 |
| 전체 | `all` | 계획 전체 조망·검토. 접지 않고 전부 펼친다 |
| 남은 항목 | `remaining` | 남은 일 목록. 완료 항목과 완료 서브트리를 제외한다 |
| 특정 가지 | `branch=TASK-NN` | 한 TASK의 하위 항목만. 루트와 그 가지만 전부 펼친다 |

## render.py 실행

- `python skills/wf-tree/scripts/render.py <plan.md|status.md> [--view V] [--depth N] [--write]`. 설치 위치가 다르면 그 경로(예: `~/.claude/skills/wf-tree/scripts/render.py`)로 실행한다.
- 입력은 `plan.md`(`## 작업 목록`의 `### TASK-NN: 제목` 블록과 `상태`·`완료`·`상위`·`의존성` 필드) 또는 `status.md`(`## 작업 목록` 표의 작업 ID·제목·상태·의존 열)다. 루트의 상태는 문서 머리말 `상태`에서 읽는다.
- `--depth N`(기본 2)은 작업 내부 트리의 분해 상한이다. 초과 항목은 경고하고 그대로 그린다 — 상한의 의미는 [본문 §2](../SKILL.md#2-트리-모델).
- `--write`는 `## 계획 트리` 절의 첫 코드 펜스와 `<!-- generated: … -->` 주석을 교체한다. 절이 없으면 `## 작업 목록` 앞에 삽입한다. 절 안의 다른 문장은 보존한다.
- 경고(exit 0): `상위` 대상 없음(루트 아래로 붙임), `상위` 순환(끊고 루트 아래로), 깊이 상한 초과, 상태 어휘 오류(`[ ]`로 그림). 오류(exit 1): 파일 없음, `## 작업 목록` 없음.

## 손 렌더 시 준수 표기

Python을 쓸 수 없을 때만 손으로 그린다. 위 표기 어휘·완료 시점·우측 주석 순서를 그대로 따르고, `상위:` 필드가 있는 목록 항목만 그리며 목록에 없는 노드를 만들지 않는다. generated 주석을 `<!-- generated: YYYY-MM-DD HH:MM — 손 렌더(Python 없음) -->`로 적어 손 렌더 사실을 남긴다.
